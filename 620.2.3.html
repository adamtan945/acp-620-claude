3 分鐘速覽

Column 是 status 的容器，位置決定意義

  1. 一欄可以放多個 status一個 status 在同一個 board 只能對到一欄。
  2. 沒對到欄的 status＝隱形官方：Unmapped statuses will hide work items both in your board view and backlog view；只有搜尋找得到。
  3. Scrum 以最右欄判定完成Done、Cancelled、Won't Do 都要放最右欄，否則完成 sprint 時會被帶到下一個 sprint。
  4. Kanban 的 Hide completed 看 status category進到 Done 類別就算完成，跟放在哪一欄無關；任何編輯都會重設計時。
  5. WIP limit（column constraint）只提醒不阻擋超過上限欄頭變紅、低於下限變黃；卡片照樣拖得進去；算整欄總數，不管 quick filter。
  6. CMP 可設上下限，TMP 只能設上限你常錯CMP 的 Scrum、Kanban 都能設；題目問「最適合設 WIP limit 的 project」選 CMP Kanban。

WIP limit

Column constraint：CMP vs TMP

Company-managed

Scrum 與 Kanban 都能設
  • 可設 最小值與最大值
  • 可選 Issue count 或排除 sub-task
  • 超過上限紅、低於下限黃
  • 不會阻止拖曳（只提醒）

Team-managed

board 欄頭 ••• → Set column limit
  • 只能設 最大值
  • 超過時欄位變色
  • 沒有最小值
  • 沒有「排除 sub-task」選項
你練習時錯過

題目：「要在 In Progress 欄設 WIP limit，該選哪種 project？」單選時選 Company-managed Kanban（功能最完整、WIP 是 Kanban 核心）。但別記成「TMP 不能設」或「Scrum 不能設」，兩句都是錯的。

Simplified workflow

什麼時候能在 board 上直接加 status

條件（全部要成立）
Board 的 filter 只含一個 project
該 project 所有 issue type 共用同一個 workflow
Workflow 只用 Atlassian 內建的 post function、validator、condition
每個 status 至少一條出去的 transition

符合時，project admin 在 Columns 頁看得到 Add status；不符合時只有 Jira admin 在 workflow editor 能加。

易錯觀念

考題愛用的錯誤說法

Workflow 拿掉 Resolved status 後，要更新 Resolution 欄位的值和 Created vs Resolved 報表。
要檢查的是用到這個 status 名稱的地方：board 的 column mapping（那欄少了 status），以及寫了 status = Resolved 的 saved filter。Resolution 是另一個欄位（全站共用的值），不會因為拿掉 status 而要改；Created vs Resolved 看的是 resolution date，不是 status 名稱。（有題庫的答案給 Created vs Resolved＋column mapping，saved filter 反而不算，這點依官方定義存疑。）
Status 被拿掉 → 找「寫著這個 status 名字」的地方：board 欄位、JQL filter。Status ≠ Resolution。

動手做

實作 Lab：拆掉 status 對應、設 WIP limit

約 20 分鐘WEB 的 board admin 或 project admin

第一次做 Lab？先看 Lab 環境準備：用測試站台、準備測試帳號。畫面名稱可能隨 Atlassian 更新而不同，以下以現行畫面為準。

目標：在 WEB 的 Columns 頁把一個 status 拿出欄位，看 issue 怎麼「隱形」；再設 column constraint，看它只變色、不阻擋。

這個 Lab 對應的考點

沒對到欄的 status，issue 在 board 與 backlog 都看不到；Scrum 以最右欄判定完成；WIP limit 只提醒不阻擋，CMP 有上下限、TMP 只有上限。

準備

  • WEB 有一個 active sprint，To Do、In Progress、Done 各有幾張卡。
  • 只含單一 project 的 board 正逐步換成新版 board view：若 Board settings 找不到 Columns，改用 board 右上 ••• → Configure columns。

步驟

  1. 你應該看到：看到每欄可以放多個 status；畫面會寫 You’re using the simplified workflow 或 You’re using the Jira workflow。
  2. 你應該看到：In Progress 的卡在 board 和 backlog 都不見了；用 JQL status = "In Progress" 搜尋還找得到。
  3. 你應該看到：卡片回到 board。Issue 一直都在，只是沒有欄可以放。
  4. 你應該看到：每欄欄頭顯示 work item 數量與上限。
  5. 你應該看到：欄頭變紅，但卡片照樣拖得進去：constraint 只提醒、不阻擋。
  6. 你應該看到：To Do 欄頭變黃：低於下限。
  7. 你應該看到：卡片變少了，但欄頭仍是紅的：constraint 算的是整欄總數，不管 quick filter。

試試看：改一個設定，觀察差異

T1在 Columns 頁把 Done 欄拖到 In Progress 左邊，看每欄頂端的顏色條。看結果
最右邊那欄變成綠色條：Jira 永遠把最右欄當「完成」。Scrum 完成 sprint 時，Done 欄的卡會被當成未完成。看完立刻拖回。
T2打開 TEAM 的 board，在某一欄的 ••• 選 Set column limit。看結果
只能設一個最大值，沒有最小值，也沒有「排除 subtask」選項。
T3在 WEB 的 Columns 加一欄 Review，再把它刪掉。看結果
若是 simplified workflow，加欄時會同時建一個同名 status；刪欄後裡面的 status 回到 Unmapped，issue 不會被刪。
心像錨點：閉上眼睛想一次這個畫面

Columns 設定頁右邊的 Unmapped statuses 面板：In Progress 被拖進去的那一刻，board 上整欄的卡一起消失。口訣：沒對欄，就隱形。

收尾

  • Column constraints 改回 None。
  • 確認所有 status 都對到原本的欄、Done 在最右邊；刪除 Review 欄（與它建出的 status，若沒有 issue 在用）。
  • 取消勾選 quick filter。
