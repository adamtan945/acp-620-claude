題目問的是哪一種問題？

問「多久」：cycle time、lead time、在某狀態待多久
Control chart
問「各狀態幾張」、瓶頸、flow、WIP
Cumulative flow diagram
問「這個 sprint 還剩多少、做得完嗎」
Burndown chart
問「sprint 中途被加了多少工作」（scope creep）
Burnup chart
問「做完、沒做完、被移除了哪些」、retro
Sprint report
問「每個 sprint 做多少、下次承諾多少」
Velocity chart
問「epic 還剩多少、哪些沒估點」
Epic report
問「epic 還要幾個 sprint」
Epic burndown
問「版本還要幾個 sprint」
Release burndown
問「版本預計哪天 release」、樂觀悲觀
Version report
問「未來 N 天有哪些版本要 release」（dashboard）
Road Map gadget
問「每個人各狀態幾張」（兩個欄位交叉）
Two Dimensional Filter Statistics

最常搞混的是「幾張」和「多久」：問數量變化用 CFD，問時間長短用 Control chart。

Burndown Chart

ScrumTMP 也有吃 working days
回答
這個 sprint 還剩多少？做得完嗎？
X 軸
sprint 的日子（跳過非工作日）
Y 軸
剩餘估算（board 的 estimation statistic）
  • 灰色虛線 guideline：從 sprint 開始的總量，依工作天直線降到 0。
  • 紅線＝實際剩餘；往上跳＝中途加工作或估點調高。
  • 非工作日是灰底，guideline 在那幾天是平的。
  • Sprint 開始時沒有估點的 issue，就畫不出 guideline。
考點　只算 parent 的估點；sub-task 估點不計。吃 working days。
題目關鍵字：remaining work、likelihood of achieving the sprint goal
官方說明

Burnup Chart

ScrumTMP 也有
回答
Sprint 中途有沒有被追加工作（scope creep）？
X 軸
sprint 的日子
Y 軸
故事點
  • 紅線＝work scope（總共要做多少）。
  • 綠線＝completed（已經做完多少）。
  • 灰線＝guideline（照這個進度走才能準時做完）。
  • 紅線往上跳＝scope creep；綠線追上紅線＝完成。
考點　紅線不是完成量。不吃 working days。
題目關鍵字：scope creep、work added during the sprint、completed vs total scope
官方說明

Sprint Report

Scrum吃 working days
回答
這個 sprint 完成了哪些、沒完成哪些、被移除哪些？
形式
上方附一張 burndown；下方是清單
  • 四個清單：Completed、Not completed、Removed、Completed outside of this sprint。
  • 星號 *＝sprint 開始後才加入。
  • 3 → 5＝sprint 中估點被改過。
考點　Retro 會議用。CMP 專屬（TMP 的清單在 Sprint burndown 下方）。吃 working days。
題目關鍵字：completed or pushed back to the backlog、retrospective、overcommitting
官方說明

Velocity Chart

ScrumTMP 也有
回答
團隊每個 sprint 能做多少？下個 sprint 該承諾多少？
X 軸
最近幾個 sprint
Y 軸
故事點（或 board 的 estimation statistic）
  • 每個 sprint 兩根柱：Commitment（開始時的量）vs Completed。
  • 中途加入又完成的會讓 Completed 大於 Commitment。
  • 用最近幾個 sprint 的 Completed 平均當產能。
考點　Commitment 不含開始後加入的工作。不吃 working days（以 sprint 為單位）。
題目關鍵字：how much work per sprint、forecast、capacity、plan future sprints
官方說明

Epic Report

Scrum吃 working days
回答
這個 epic 還剩多少？有哪些還沒估點？
X 軸
時間
Y 軸
故事點或 issue 數
  • 進度線＋三個清單：完成、未完成、未估點。
  • 可以切換 story points 或 issue count 視角。
考點　CMP Scrum 專屬。吃 working days。
題目關鍵字：progress of an epic、incomplete and unestimated work
官方說明

Epic Burndown

Scrum
回答
這個 epic 還要幾個 sprint 才做得完？
X 軸
sprint
Y 軸
剩餘故事點
  • 淺綠＝該 sprint 完成、淺藍＝原估剩餘、深藍＝中途加的 scope、灰＝預測的未來 sprint。
  • 有 scope change 的 bar 會往 0 線下方凸出：官方定義「淺綠＋淺藍＝sprint 開始時的原估」「淺藍＋深藍＝sprint 結束時的剩餘」，所以深藍畫在 0 線下，bar 看起來不是從 0 開始是正常的。
  • 預測＝剩餘 ÷ 最近三個 sprint 的平均完成量。
  • 未估點超過 30% 會警告，預測不可信。
考點　用最近 3 個 sprint；status 沒對應 column 的 issue 完全不計。不吃 working days。
題目關鍵字：how many sprints to complete an epic
官方說明

Release Burndown

Scrum
回答
這個版本還要幾個 sprint？
X 軸
sprint
Y 軸
剩餘故事點
  • 跟 Epic burndown 同一種圖，範圍換成一個 version。
  • 預測用最近三個 sprint；未估點超過 30% 標紅。
  • Status 沒對應 column 的工作完全不列入。
考點　「報表少了一批卡」先查 unmapped status。不吃 working days。
題目關鍵字：how many sprints to release a version
官方說明

Version Report

Scrum吃 working days
回答
這個版本預計哪一天可以 release？
X 軸
日期（從版本 Start Date 開始）
Y 軸
故事點
  • 藍色直線＝預測 release 日。
  • 左灰帶＝樂觀（平均日速度 +10%）、右灰帶＝悲觀（−10%）。
  • 估算工作要先完成 10% 才算得出預測。
考點　排除 sub-task、只顯示 Released 不顯示 Archived 版本。吃 working days。
題目關鍵字：predicted／projected release date、optimistic、pessimistic
官方說明

Control Chart

ScrumKanban吃 working days
回答
一張卡從開始到完成要多久？穩不穩定？
X 軸
issue 完成的日期
Y 軸
經過時間（cycle time 或 lead time）
  • 每個點＝一張 issue。
  • 藍線＝rolling average（依 issue 數算，不是依天數）。
  • 藍帶＝標準差；帶子變寬＝越來越難預測。
  • Columns 只勾一個狀態＝看在那個狀態待多久。
考點　Scrum 與 Kanban 都有；TMP 沒有。吃 working days。
題目關鍵字：cycle time、lead time、variance、predictability、how long in a status
官方說明

Cumulative Flow Diagram

ScrumKanbanTMP 也有
回答
各狀態的數量怎麼變？瓶頸在哪一欄？
X 軸
日期
Y 軸
issue 數（累積堆疊）
  • 每一色帶＝一個狀態（對應 board column）；由下往上是 workflow 倒過來，Done 在最底、To Do 在最上。
  • 哪條帶一直變厚，哪裡就是瓶頸。
  • 色帶厚度＝該狀態的件數；線的高度是累積上界。
  • 每條線＝該欄＋右邊所有欄的累積數，所以卡片往回拖時，它經過的線會各扣 1。
考點　按日曆日，不吃 working days。看不到單張卡待多久（那是 Control chart）。
題目關鍵字：bottleneck、work in progress、flow、statuses over time
官方說明

Average Age Report

不綁 board
回答
還沒解決的 issue 平均放了幾天？
X 軸
時間（每一期）
Y 軸
未解決 issue 的平均年齡（天）
  • 長條圖＋資料表；只算未解決的。
  • 一期比一期高＝舊案子堆著沒人處理。
考點　跟 Resolution Time 相反：這張看「還沒解決」。
題目關鍵字：average age of unresolved、backlog kept up to date
官方說明

Resolution Time Report

不綁 board
回答
解決一張 issue 平均花多久？
X 軸
時間（每一期）
Y 軸
那期解決的 issue 平均花幾天
  • 長條圖，只算已解決的。
  • 一期比一期低＝解得越來越快。
考點　看「已經解決」的速度。
題目關鍵字：time taken to resolve
官方說明

Created vs Resolved

不綁 board
回答
Backlog 在變多還是變少？
X 軸
時間
Y 軸
issue 數（可選累積）
  • 紅線＝建立、綠線＝解決；開 Cumulative totals 時兩條線是累計數，會一路往上。
  • 紅區＝建立多於解決（backlog 在累積）；綠區＝解決多於建立。累計模式下，紅區＝累計建立 > 累計解決。
  • 可以用虛線標出版本 release 日。
考點　兩條線比較同一段時間。
題目關鍵字：backlog growing or shrinking、created versus resolved
官方說明

Recently Created Issues

不綁 board
回答
團隊跟得上新進來的量嗎？
X 軸
時間（每一期）
Y 軸
那期新建立的張數
  • 一期一根長條。
  • 綠段＝其中已解決、紅段＝還沒解決。
  • 紅段越來越長＝跟不上。
考點　追蹤「那期建立的卡後來解決了幾張」。
題目關鍵字：keeping up with incoming work、rate of creation
官方說明

Time Since Issues

不綁 board
回答
某個日期欄位在哪幾天被設定？
X 軸
時間（每一期）
Y 軸
所選日期欄位落在那期的張數
  • 先選一個日期欄位：Created、Updated、Due、Resolved 或自訂。
  • 可選累積。
考點　任何日期欄位都能選。
題目關鍵字：a date field (created／updated／due) was set
官方說明

Pie Chart Report

不綁 board
回答
依某個欄位分，各佔多少？
形式
沒有座標軸；扇形大小＝張數佔比
  • 選一個欄位（Statistic Type），例如 status、priority、assignee。
  • 一次只能一個欄位。
考點　算張數；要兩個欄位交叉用 Two Dimensional。
題目關鍵字：grouped by a field、breakdown at a glance
官方說明

Single Level Group By

不綁 board
回答
Filter 的結果按一個欄位分組，每組進度如何？
形式
表格；每組一個進度條
  • 只能用 filter。
  • 每組標題旁有進度條（該組 issue 的整體狀態）、底下列出 issue；最多 1,000 筆。
考點　是表格不是圖，只吃 filter。
題目關鍵字：search results grouped by a field、status of each group
官方說明

Workload Pie Chart

不綁 board
回答
每個人手上的剩餘工時佔多少？
形式
沒有座標軸；扇形大小＝剩餘工時佔比
  • 長得像 Pie Chart，但算的是剩餘工時，不是張數。
考點　要開 time tracking；不看 story points。
題目關鍵字：relative workload for assignees
官方說明

User Workload

不綁 board
回答
某一個人手上還有多少工作？
形式
表格；列＝project；欄＝未解決張數、剩餘工時
  • 先選一個人，跨 project 列出。
  • 最後一列是合計。
考點　以「人」為主角；要開 time tracking。
題目關鍵字：work allocated to a user
官方說明

Version Workload

不綁 board
回答
版本完成前，每個人還剩多少？
形式
表格；列＝assignee；欄＝各 issue type 的剩餘工時
  • 先選一個版本（看 Fix Version）。
  • 最後列出未指派的。
考點　以「版本」為主角、依人拆開；要開 time tracking。
題目關鍵字：outstanding work per user before a version is complete
官方說明

Time Tracking Report

不綁 board
回答
這個版本的估時準不準？超前還是落後？
形式
上方兩條橫條；下方表格：Original、Remaining、Spent、Accuracy
  • Progress：綠＝已花、橙＝剩餘。Accuracy：藍＝原估。
  • 一樣長＝照原估；Progress 比 Accuracy 的藍段長＝落後（Accuracy 尾端淺灰＝落後的時數）；Accuracy 較長＝超前（原估高估了）。
  • 必須有 Fix Version；Σ 欄含 sub-task。
考點　看估得準不準；要開 time tracking。
題目關鍵字：original estimate vs actual、ahead of or behind schedule
官方說明

Filter Results

來源：saved filter

把 filter 的結果列成清單，可自選欄位與筆數。

考點　不分組；內容由 filter 決定，不會自動換成「我的」issue，但仍受權限限制：filter 要分享給對方、對方也要有 Browse 權限才看得到。

Pie Chart

來源：filter 或 project

依一個欄位畫佔比圓餅。

考點　一次只能一個欄位，算張數。

Issue Statistics

來源：filter 或 project

一個欄位分組，列出數量與百分比。

考點　跟 Pie Chart 一樣是一維，只是用表格。

Two Dimensional Filter Statistics

來源：saved filter

兩個欄位交叉成表，例如 Assignee × Status。

考點　唯一能回答「每個人各狀態幾張」。

Created vs Resolved

來源：filter 或 project

新建與解決兩條線，夾出紅／綠區；開 Cumulative totals 時兩條線是累計數。

考點　紅區＝backlog 在累積。

Recently Created Issues

來源：filter 或 project

每期新建幾張，綠＝已解決、紅＝未解決。

考點　看團隊跟不跟得上。

Average Age

來源：filter 或 project

未解決 issue 平均放了幾天。

考點　往上＝舊案堆積。

Resolution Time

來源：filter 或 project

已解決 issue 平均花幾天。

考點　Average Age 的反面。

Time Since Issues

來源：filter 或 project

依一個日期欄位畫每期張數。

考點　任何日期欄位都能選。

Average Time in Status

來源：filter 或 project

各狀態平均停留多久。

考點　找卡最久的狀態。

Average Number of Times in Status

來源：filter 或 project

平均進入每個狀態幾次。

考點　明顯大於 1＝反覆被退回。

Assigned to Me

來源：不需設定

指派給觀看者、未完成的 issue。

考點　跨所有 project，內容跟著觀看者變。

Issues in Progress

來源：不需設定

指派給觀看者、狀態進行中的 issue。

考點　只列 In Progress，不含 To Do。

Watched／Voted Issues

來源：不需設定

觀看者關注或投過票的 issue。

考點　兩個 gadget，都跟著觀看者變。

Sprint Health

來源：board＋sprint吃 working days

依欄位上色的進度條，加 Time elapsed、Work complete、Scope change、Blockers、Flagged。

考點　看 scope change；吃 working days。

Sprint Burndown

來源：board＋sprint吃 working days

目前 sprint 的燃盡曲線。

考點　資料同 Burndown chart；吃 working days。

Days Remaining in Sprint

來源：board＋sprint

只顯示 sprint 還剩幾天。

考點　一個數字，適合掛牆上。

Road Map

來源：project（可多選）

未來 N 天要 release 的版本與各版本的完成進度。

考點　多個版本的概覽；單一版本的預測日用 Version report。

Projects

來源：project

Project 資訊與常用 filter 捷徑。

考點　只是捷徑，不做統計。

Bubble Chart

來源：saved filter

四個維度：X＝開了幾天、Y＝留言數、泡泡大小＝參與人數或票數、顏色＝綠低紅高。

考點　撈出「又熱門又拖很久」的 issue。

Labels

來源：project

列出 project 用過的 label 與次數。

考點　檢查拼字變體。

Activity Stream

來源：project 或 user

最近的活動紀錄。

考點　純紀錄，不做統計。
