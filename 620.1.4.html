3 分鐘速覽

Project details、category、trash

  1. CMP 的 project admin 改得動你常錯Name、Avatar、URL、Description、Project lead、Default assignee。
  2. CMP 的 project admin 改不動你常錯Key（org、site、Jira admin）、Category（Jira admin 指派）。
  3. TMP 的 Details 只有 5 個欄位你常錯Name、Avatar、Key、Category、Access；TMP 沒有 URL、Description、Default assignee。Name、Avatar、Category、Access 由 project admin 自己改。Key 的權限官方兩頁說法不同：Edit a space's details 寫只有 org、site、Jira admin 能改（沒有區分 CMP／TMP），TMP 專頁則寫「有 space 權限」就能改；作答以前者為準。
  4. 改 key 不會壞，刪 previous key 才會舊 key 變成 alias，舊連結照樣導向。
  5. Default assignee 只有兩種Unassigned 或 Project lead。
  6. Trash 60 天Move to trash：Jira／site admin 兩種 project 都能移；project admin 能移哪些，官方兩頁說法不同（Move 頁寫有 Administer Projects 即可，Trash 總覽頁寫只能移 TMP）。Restore、永久刪除：只有 Jira admin。

Details 頁

CMP 與 TMP 的 Details 頁

你練習時錯過

CMP 的 Details 頁，project admin 不能改 Project category。題目說 team-managed 時，Category 反而是正確選項（TMP 的 project admin 可以自己指派）；TMP 題目出現 Description、URL 就是陷阱。

官方兩說：TMP 的 key 誰能改

Edit a space's details（考綱連結的那一頁）寫：只有 organization、site、Jira admin 能改 space key，全文沒有區分 CMP 與 TMP。Create and edit team-managed spaces（TMP 專頁）則寫：有 space 權限的人就能在 Details 頁改 key。

兩頁互相矛盾，教材早先依實測寫「TMP 的 project admin 能改」，但那不是官方明文。作答時以考綱那一頁為準：改 key 找 org、site 或 Jira admin；實際站台若讓 TMP 的 project admin 改得動，以站台為準。題庫已避開這個有爭議的點。

改 key

改 key 與刪 previous key

  • 改 key：舊 key 自動存成 previous key（alias），舊連結、filter、JQL 繼續運作。
  • 刪 previous key：引用舊 key 的連結才會失效（為了把舊 key 給別的 project 用）。
  • Key 規則：至少 2 個字元、大寫字母開頭、只有大寫字母與數字。
本段必考
  • 改 key 安全；刪 previous key 才會壞。

Category

Project category

  • Category 由 Jira admin 建立（⚙ → Projects → Project categories）。
  • 一個 category 可以給多個 project；一個 project 只能一個 category。
  • 不能做階層；JQL 可用 category = "X"。

Name 是必填，不能空白（Key、Project lead、Default assignee 也都一定有值）。可以留空的是 URL、Project category（可選 None）、Description。Component 不在 Details 頁；Project type 也不是 Details 的欄位。

動手做

實作 Lab：Details、改 key 與 trash 走一圈

約 30 分鐘Jira admin；另用 Leo（project admin）

第一次做 Lab？先看 Lab 環境準備：用測試站台、準備測試帳號。畫面名稱可能隨 Atlassian 更新而不同，以下以現行畫面為準。

目標：用一個可丟棄的 project 看 Details 每個欄位誰能改，改一次 key 看舊連結，再移到 trash 與還原。

這個 Lab 對應的考點

CMP 的 project admin 改不了 key 與 category；default assignee 只有 Unassigned 或 project lead；改 key 舊連結照樣能用，刪 previous key 才會壞；trash 60 天，restore 要 Jira admin。

準備

  • 建一個可丟棄的 company-managed Kanban project：名稱 Lab Trash、key LAB，建 2 張 work item。只在測試站台做。
  • 把 Leo 加進 LAB 的 Administrators role。

步驟

  1. 你應該看到：這就是 CMP 的 Details 欄位；TMP 只有 Name、Avatar、Key、Category、Access。
  2. 你應該看到：只有 Unassigned 與 Space owner（project lead）兩個選項；要指定別人，得先把那個人設成 space owner。
  3. 你應該看到：通常兩個都改不了（欄位灰掉或沒有選項）：改 key 要 org、site 或 Jira admin；CMP 的 category 要 Jira admin 指派。
  4. 你應該看到：兩個 project 都在 Lab 底下：一個 category 可以給多個 project；但一個 project 只能選一個 category。
  5. 你應該看到：仍會導到 LABX-1：舊 key 自動存成 previous key，舊連結、filter 繼續運作。Details 頁多了 Previous space keys。
  6. 你應該看到：搜尋找不到；直接開網址看得到內容，但不能編輯。
  7. 你應該看到：LABX 回到 space 目錄，work item 又搜得到。

試試看：改一個設定，觀察差異

T1在 LABX 的 Details 的 Previous space keys 刪掉 LAB，再開一次 LAB-1 的網址。看結果
舊連結失效：刪 previous key 才會壞。只在 LABX 這種可丟棄的 project 做。
T2打開 TEAM 的 Details。看結果
只有 Name、Avatar、Key、Category、Access；沒有 URL 與 Description。TEAM 的 admin 可以自己選 category（category 仍要 Jira admin 先建好）。
T3用 Leo（LABX 的 project admin）試著把 LABX 移到 trash，或到 Trash 頁 Restore。看結果
Move to trash 的結果以你的站台為準（官方兩頁寫法不完全一致）；Restore 與永久刪除只有 Jira admin 做得到。
心像錨點：閉上眼睛想一次這個畫面

Details 表單裡的 Space key 欄，下方多出一行 Previous space keys。改 key 安全，刪舊 key 危險；trash 60 天，Jira admin 救。

收尾

  • LABX 移到 trash（60 天後自動永久刪除；要立刻清就在 Trash 選 Delete permanently）。
  • 把 WEB 的 category 改回 None，刪除 Lab category。
