Board filter、sub-filter、quick filter

三層過濾是 board 設定最常考的地方：每一層只能縮小範圍；報表只看最外層的 board filter。

3 分鐘速覽

三層過濾：board filter → sub-filter → quick filter

  1. 每一層只能縮小quick filter 不能讓 board filter 排除的 issue 出現。
  2. Sub-filter 只有 CMP Kanban 有你常錯預設 fixVersion in unreleasedVersions() OR fixVersion is EMPTY；它只改 board 顯示，報表不會跟著縮小。
  3. 報表只看 board filter你常錯sub-filter、Hide completed、quick filter 都只改 board 顯示；要改報表範圍就改 board filter。
  4. Quick filter 多選＝AND勾越多越少；要 OR 就寫在同一個 quick filter。
  5. 改 board filter 立即生效board、backlog、報表全部用新範圍；同一份 filter 的所有 board 一起變。
  6. Sub-filter 還是 Hide completed？看條件你常錯自訂條件（48 小時、只藏 Won't Fix）→ sub-filter；完成超過 1／2／4 週 → Hide completed。
  7. 沒有 ORDER BY Rank 就拖不動Board settings → General → Add Rank。
  8. 只看自己團隊的 issue你常錯改 board filter（一勞永逸）或建 quick filter；不是 issue security。

設定畫面

Board settings → General

需求用什麼報表受影響嗎
多個 project＋依自訂條件自動藏卡（例：Won't Fix 超過 48 小時）CMP Kanban＋sub-filter不會
完成超過 1、2、4 週的卡自動藏起來Hide completed不會
每個人自己臨時篩選Quick filter不會（除非在報表裡 Refine）
整個 board 只看某團隊改 board filter會
更正（9/26）：sub-filter 不會影響報表

之前教材和我在對話裡都說「sub-filter 會讓報表跟著變」，這是錯的，你原本題庫的說法才對。官方 Data Center 版原句：預設 sub-filter 讓已 release 的 issue 從 board 消失，although the reports in Reports will continue to show them；Cloud 的 CFD 頁也寫 CFD 只包含符合 board saved filter 的 issue。

所以 sub-filter、Hide completed、quick filter 都只改 board 顯示。題目要你在兩者之間選，看的是條件：自訂條件選 sub-filter，1／2／4 週選 Hide completed。

你練習時錯過

「要看 3 個 project，並自動藏掉 Won't Fix 超過 48 小時的卡」→ company-managed Kanban board＋sub-filter（例如 AND NOT (resolution = "Won't Fix" AND resolved <= -48h)）。TMP board 不能撈別的 project、也沒有 sub-filter；Hide completed 沒有 48 小時選項。

Q1要讓 Kanban board 自動藏掉「resolved 超過 4 週」的卡，而且報表維持不變，用什麼最有效率？看答案
Hide completed issues older than：4 weeks。現成選項、不用寫 JQL；它只影響 board，不影響報表。
Q2改了 sub-filter 之後，CFD 和 Control Chart 的資料會少掉嗎？看答案
不會。報表依 board 的 saved filter；sub-filter 只改 board 顯示。
Q3Scrum board 的設定頁有 sub-filter 欄位嗎？看答案
沒有。Sub-filter 只有 CMP 的 Kanban board 有。
本段必考

  • Hide completed：1／2／4 週、報表不變。你常錯
  • 兩者之間怎麼選：看條件，不是看報表。你常錯
Quick filters

每個人自己的即時篩選

  • 誰能管：board admin 或 project admin。
  • 勾選狀態只存在自己的瀏覽器，不影響別人。
  • Quick filter 的 ORDER BY 沒有作用。
  • 同時勾 type = Bug 與 type = Task → 空的（AND）。
你練習時錯過

Scrum board 只想看自己團隊的 issue → board filter（改 JQL）＋ quick filter。Issue security level 不是 board 功能，它讓無權限的人完全看不到 issue。

本段必考
  • 預設兩個：Only My Issues、Recently Updated。
  • 多選 AND；OR 寫在同一條。
  • 只顯示自己團隊：board filter＋quick filter。你常錯
Rank 與改 filter

改 board filter 的後果

  • Board、backlog、報表立刻用新範圍（報表只看 board filter，不看 sub-filter）。
  • 同一份 filter 的所有 board 一起變。
  • Backlog 的 Epics／Versions 面板數字只算 board filter 撈到的 issue。
  • Board admin 不等於 filter editor；改不動就 Save as 自己的 filter 再指過去。
  • 沒有 ORDER BY Rank：卡片拖不動、Scrum 建不了 sprint → 按 Add Rank。
你練習時錯過

「Epics 在 backlog 的計數不受 board filter 影響」是錯的。官方 KB：“The issue counts in a board will only include issues that appear on that board.”

自我檢查：先在心裡回答，再點開對答案
Q1Backlog 的 epic 顯示 5 張 child，但 epic 實際有 8 張，為什麼？看答案
有 3 張 child 沒被 board filter 撈到；board 上的計數只算 board 上的 issue。
本段必考
  • 改 filter 立即影響所有用它的 board 與報表。
  • Epic／Version 面板數字只算 board filter 內的 issue。你常錯
  • 沒有 Rank 拖不動 → Add Rank。
