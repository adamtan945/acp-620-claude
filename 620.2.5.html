620.2.5・Board configuration 29%

Estimation 與 time tracking

Board 有兩個估算旋鈕：估什麼（estimation statistic）與追蹤什麼（time tracking）。它們決定報表的單位與 sub-task 的算法。

3 分鐘速覽

兩個旋鈕：估什麼、追蹤什麼

  1. Estimation statisticStory points、Original time estimate、Issue count 或自訂數字欄位；決定 velocity 與 burndown 的單位。
  2. Time trackingNone，或 Remaining estimate and time spent；開了之後 burndown 改用剩餘工時。
  3. 只有 CMP Scrum board 有這一頁Board settings → Estimation；TMP 在 Features 開 Estimation（story points 或 time）。
  4. Sub-task 的估點永遠不算Burndown、velocity 只加總 parent。
  5. Sprint 中途加 sub-task 一律算 scope change你常錯只有開了 Remaining estimate and time spent 時 burndown 才畫得出來。
  6. Time tracking 三個欄位你常錯Original estimate、Remaining estimate、Time spent（log work 累加）。

Time tracking 欄位

三個專門追蹤時間的欄位

欄位意思
Original estimate開始前估要花多少時間
Remaining estimate還剩多少；log work 後自動扣，可手動改
Time spent已經花了多少；由 Log work 累加
  • Story points、Due date、Sprint 都不是 time tracking 欄位。
  • CMP 在 screen 上加一個「Time tracking」欄位，就同時帶出 Original 與 Remaining。
  • 要記工時：Jira admin 開 time tracking＋使用者有 Work On Issues 權限。
自我檢查：先在心裡回答，再點開對答案
Q1哪三個欄位專門用來追蹤時間？看答案
Original estimate、Remaining estimate、Time spent。
本段必考
  • Original／Remaining／Time spent。你常錯
  • 記工時需要 Work On Issues。

原因修法

Sprint 開始日期在過去、時區不一致Edit sprint 修日期、確認時區
完成的 status 沒對到最右欄Columns 把 Done、Cancelled 拖到最右欄

本段必考
  • Guideline 要有「開始時的總量」；先放 issue 再 Start sprint。
Team-managed

TMP 的估算

  • Project settings → Features → 打開 Estimation（預設關）→ 選 Story points 或 Time。
  • TMP 的欄位叫 Story point estimate，CMP 叫 Story Points，不是同一個欄位。
  • 沒開 Estimation 時報表用 issue 張數。
本段必考
  • TMP：Features 開 Estimation。
  • TMP 的 Story point estimate ≠ CMP 的 Story Points。
易錯觀念

考題愛用的錯誤說法

勾了「Include child issues」，velocity 就會把 sub-task 算進去。
Sub-task 估算無條件不進 velocity。Include child issues 在 parent issue 的 time tracking 區塊，只讓 parent 顯示的工時加上 sub-task 的工時；報表層級沒有這個選項。

兩個名稱都不存在。正解：Estimation statistic＝Story Points＋Time tracking＝None；None＝完成才整包扣，Remaining Estimate and Time Spent＝記工時就逐步降。
