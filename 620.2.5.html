620.2.5・Board configuration 29%

Estimation 與 time tracking

Board 有兩個估算旋鈕：估什麼（estimation statistic）與追蹤什麼（time tracking）。它們決定報表的單位與 sub-task 的算法。

3 分鐘速覽

兩個旋鈕：估什麼、追蹤什麼

  1. Estimation statisticStory points、Original time estimate、Issue count 或自訂數字欄位；決定 velocity 與 burndown 的單位。
  2. Time trackingNone，或 Remaining estimate and time spent；開了之後 burndown 改用剩餘工時。
  3. 只有 CMP Scrum board 有這一頁Board settings → Estimation；TMP 在 Features 開 Estimation（story points 或 time）。
  4. Sub-task 的估點永遠不算Burndown、velocity 只加總 parent。
  5. Sprint 中途加 sub-task 一律算 scope change你常錯只有開了 Remaining estimate and time spent 時 burndown 才畫得出來。
  6. Time tracking 三個欄位你常錯Original estimate、Remaining estimate、Time spent（log work 累加）。

Time tracking 欄位

三個專門追蹤時間的欄位

欄位意思
Original estimate開始前估要花多少時間
Remaining estimate還剩多少；log work 後自動扣，可手動改
Time spent已經花了多少；由 Log work 累加
  • Story points、Due date、Sprint 都不是 time tracking 欄位。
  • CMP 在 screen 上加一個「Time tracking」欄位，就同時帶出 Original 與 Remaining。
  • 要記工時：time tracking 功能要開著＋使用者有 Work On Issues 權限。考試版：time tracking 是全站功能，由 Jira admin 在全站設定啟用或停用。現行版：官方寫 Jira Cloud 預設啟用、而且一律啟用，不能整個關掉；要不要用改由欄位控制：CMP 在 field configuration 顯示或隱藏 Time tracking 欄位，TMP 在 work type 加入或移除這個欄位。作答時，題目若要求「開啟 time tracking」，現行版不必找 Jira admin 開全站開關。

易錯觀念

考題愛用的錯誤說法

關掉 Remaining Estimate and Time Spent 時，加進 active sprint 的哪種 issue「不算 scope change」？→ All answers（Epic、Story、Bug、Sub-task 都不算）。
題庫這種題目要選 Sub-task。官方現行寫法：sub-task 加進 active sprint 仍算 scope change，只是關掉時間追蹤時 burndown 上看不出來；Story、Bug 加進來一律算、也畫得出來。舊題用「do not consider as a scope change」描述的就是「看不出來」這件事，選項裡只有 sub-task 有這個例外。
加子必記，有時才畫：題目說「不算」，其實在考「畫不出來」的那個子。
你練習時錯過官方來源
勾了「Include child issues」，velocity 就會把 sub-task 算進去。
Sub-task 估算無條件不進 velocity。Include child issues 在 parent issue 的 time tracking 區塊，只讓 parent 顯示的工時加上 sub-task 的工時；報表層級沒有這個選項。
你練習時錯過官方來源
要讓 issue 完成時整包燒掉 story points，Estimation statistic 選「Burn story points upon issue completion」、Time tracking 選「Disabled」。
兩個名稱都不存在。正解：Estimation statistic＝Story Points＋Time tracking＝None；None＝完成才整包扣，Remaining Estimate and Time Spent＝記工時就逐步降。
你練習時錯過官方來源
Estimation statistic 設定後，所有人所有報表都必須用同一個單位；只有 board admin 能在報表切換。
Board 定預設，報表自己選：board admin 在 Board settings 設預設值；部分報表有估算選單，任何使用者都能切換，只影響自己看的畫面。
你練習時錯過官方來源
Sub-task 不能有 story points，也不會出現在 active sprint board。
能填不能算：CMP、TMP 的 sub-task 都能填 story points，只是報表不算；sub-task 會出現在 active sprint board（可用 Stories swimlane 排在 parent 底下）。
你練習時錯過官方來源
在 active sprint 的 story 加 sub-task 不算 scope change。
一律算；只是沒開時間追蹤時 burndown 看不到。
你練習時錯過官方來源
Sub-task 的 story points 會算進 velocity。
不算；只加總 parent。
官方來源
Story points 是 time tracking 欄位。
Time tracking 欄位是 Original、Remaining、Time spent。
你練習時錯過官方來源
沒估點就不能開始 sprint。
Jira 只提醒，不會擋。
官方來源
Kanban board 也能設 Estimation statistic。
Board settings 的 Estimation 頁只有 CMP Scrum。

動手做

實作 Lab：切換估算方式，看 burndown 怎麼變

約 25 分鐘WEB 的 board admin；TEAM 的 space admin；Leo 的瀏覽器

第一次做 Lab？先看 Lab 環境準備：用測試站台、準備測試帳號。畫面名稱可能隨 Atlassian 更新而不同，以下以現行畫面為準。

目標：在 WEB 的 Estimation 頁切換 Time tracking，親眼看 sub-task 何時會出現在 burndown 上，以及 TMP 的估算開在哪裡。

這個 Lab 對應的考點

Estimation 頁只有 CMP Scrum board 有；sub-task 的估點不進 burndown、velocity；sprint 中途加 sub-task 一律算 scope change，只有開了 Remaining estimate and time spent 時 burndown 才畫得出來。

準備

  • WEB 有 active sprint，裡面有幾張已估 story points 的 Story。

步驟

  1. 你應該看到：預設通常是 Story Points、Time tracking 是 None。
  2. 你應該看到：縱軸單位跟著換；這個下拉只改你自己看的畫面，board 設定不變。
  3. 你應該看到：通常看不出變化：sub-task 的點數不計，Time tracking 是 None 時 sub-task 的 scope change 也不畫在圖上。
  4. 你應該看到：設定存好；burndown 改用剩餘工時。
  5. 你應該看到：Story 的時間追蹤顯示已花 1h、剩 3h；burndown 往下掉。
  6. 你應該看到：Burndown 出現 scope change、線往上跳：sub-task 的剩餘工時捲到 parent。
  7. 你應該看到：找不到：官方寫這個設定只給 company-managed scrum board。
  8. 你應該看到：開啟後可以選 Story points 或 Time；欄位名稱是 Story point estimate。

試試看：改一個設定，觀察差異

T1在 ⚙ Settings›Work items›Permission schemes›WEB Permission Scheme 把 Work On Work Items 從 Developers 移除，請 Leo 在 WEB 的 Story 上 Log work。看結果
Leo 找不到或無法使用 Log work：記工時要有 Work On Work Items 權限。
T2WEB 的 Reports → Velocity Chart，看上一個 sprint 的 Commitment 與 Completed。看結果
數字只算 parent 的估點；sub-task 的估點不會加進去。
T3Estimation 頁把 statistic 改成 Work item count，再看 burndown 縱軸。看結果
縱軸改成張數；改回 Story Points 後恢復。
心像錨點：閉上眼睛想一次這個畫面

Burndown 的線在你加了一張 2h 的 sub-task 那一刻往上跳了一格；Time tracking 是 None 時同一個動作卻毫無痕跡。口訣：加子必記，有時才畫。

收尾

  • Time tracking 改回 None，statistic 改回 Story Points。
  • ⚙ Settings›Work items›Permission schemes›WEB Permission Scheme：把 Work On Work Items 加回 Developers。
  • TEAM 的 Estimation 改回原本的開關狀態（官方寫停用不會刪掉既有估算資料）；刪除測試用的 sub-task。
