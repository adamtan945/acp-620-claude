3 分鐘速覽

三層 issue type，什麼時候該建新的

  1. Epic → Standard → Sub-taskEpic 的 child 是 standard；sub-task 跟 parent 同進同出 sprint。
  2. 估點估在 standard 層Sub-task 的 story points 不計入 burndown 與 velocity。
  3. 流程或欄位不同才建新 type只是分類 → component、label、custom field。
  4. CMP 的 issue type 要 Jira admin 建再加進 issue type scheme；TMP 的 admin 自己建（最多 30 個）。
  5. Sub-task 繼承 parent 的 project、security level、sprint不繼承 fix version、component、assignee、估點。
  6. Subtask Blocking Condition vs automation事前擋住 parent → condition；事後自動完成 parent → automation。

Sub-task 規則

繼承與限制

  • 全站開關：⚙ → Issues → Sub-tasks；停用前要先把既有 sub-task 轉成 standard。
  • 繼承：project、issue security level、sprint。
  • 不繼承：fix version、components、assignee、priority、估點。
  • Parent 被清出 board 時，sub-task 不管狀態一起被清（TMP）。
  • Subtask Blocking Condition：sub-task 沒到指定狀態前，parent 的 transition 按鈕直接不出現。

動手做

實作 Lab：Sub-task 跟著 parent 走，再擋住 parent

約 25 分鐘Jira admin（改 workflow 與 sub-task 設定）

第一次做 Lab？先看 Lab 環境準備：用測試站台、準備測試帳號。畫面名稱可能隨 Atlassian 更新而不同，以下以現行畫面為準。

目標：在 WEB 建 sub-task，看它從 parent 繼承了什麼；再加一個 Subtask Blocking Condition，讓 parent 在 sub-task 沒完成前轉不到 Done。

這個 Lab 對應的考點

Sub-task 繼承 parent 的 space、security level、sprint；sub-task 的估點不計入 velocity 與 burndown；Subtask Blocking Condition 是事前把 transition 藏起來。

準備

  • WEB 有一個進行中的 sprint，裡面有一張 Story（有 story points、有 fix version）。

步驟

  1. 你應該看到：Sub-task 預設是啟用的；清單裡至少有 Subtask。
  2. 你應該看到：兩個 sub-task 自動在同一個 sprint，board 上掛在 Story 底下。
  3. 你應該看到：Sprint 跟 parent 一樣，無法單獨移出；Fix versions 通常是空的（教材：fix version 不繼承）。
  4. 你應該看到：點數只算 Story 本身的；sub-task 上的 story points 不計入。
  5. 你應該看到：那個 transition 底下多了一條 condition。
  6. 你應該看到：Done 選項不見了：condition 不符時，按鈕直接不出現，不是按了才報錯。
  7. 你應該看到：Done 出現了，Story 可以完成。

試試看：改一個設定，觀察差異

T1（想像，不實際做）在 Subtasks 頁按 Disable。看結果
要先把既有的 sub-task 都轉成 standard work type，才能停用。
T2把 Subtask Blocking Condition 換成一條 automation（Work item transitioned：sub-task 全部 Done → 把 parent 轉 Done）的想法比一比。看結果
Condition 是事前擋住，automation 是事後自動做。題目問「沒完成就不能結案」選 condition；「全部完成就自動結案」選 automation。
T3（想像，不實際做）把 WEB 的 Epic 改名成 Initiative。看結果
不會多出一層；要在 epic 上面再加層級，得用 Plans（Premium）並由 Jira admin 設定階層。
心像錨點：閉上眼睛想一次這個畫面

Story 的狀態下拉裡，Done 那一行不見了；sub-task 全部完成後才又出現。條件藏按鈕，事前就擋。

收尾

  • 從 workflow 移除 Subtask Blocking Condition 並發布。
  • 刪除或保留兩個 sub-task 都可以（保留不影響其他 Lab）。
