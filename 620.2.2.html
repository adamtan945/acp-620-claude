620.2.2 · Configure boards across multiple teams and projects

跨團隊、跨 project 的 board

一個 board 可以顯示好幾個 project 的 issue，也可以一個 project 有好幾個 board。做得到的原因只有一個：board 的內容由 saved filter 決定，不是由 project 決定。看懂這件事，「誰看得到」「掛在哪裡」「改了 filter 會怎樣」全部推得出來。

術語：考試用 project／issue；現行產品為 space／work item。本教材沿用考試用語。
這一節考什麼

三條 bullet，翻成考題語言

官方 bullet考題會怎麼問
Know how to create cross-project boards「要一個 board 同時看 A、B 兩個 project，怎麼建？」「TMP 想要第二個 board？」
Understand the implications of cross-project boards「同事看得到 project 卻看不到 board，為什麼？」「兩個 project 的 workflow 不同，columns 怎麼辦？」「sprint 會跨 project 嗎？」
Understand which board configurations support cross-project boards「哪些設定是 board 層、哪些是 project 層？」「swimlane by project 在哪？」
核心模型

Board 跟著 filter 走，不跟著 project 走

圖 1　兩道門：filter 分享（進得了 board）＋ project 權限（看得到哪些卡）。
從模型推出的三條規則
  • 想讓一個 board 看到多個 project，前提是先有一份 JQL 涵蓋這些 project 的 saved filter；沒有 filter 就沒有跨 project 的 board。
  • Board 對所有能存取該 filter 的人可見（官方原句：This new board will be available to all users who have access to your chosen filter）。
  • 一旦改動 filter 的 JQL，所有使用這份 filter 的 board 會同時改變，因為 board 本身並不保存「自己的 issue 清單」，它每次都是即時去問 filter 要資料。
怎麼建

兩條路，都需要 Browse Projects

方式步驟適用
多選既有 project搜尋列 / → Go to all: Boards → Create board → Scrum／Kanban → 選一或多個既有 project → 照提示完成。Jira 自動產生 filter project in (…) ORDER BY Rank ASCCMP；你對每個 project 都有 Browse Projects
既有 saved filterCreate board → Scrum／Kanban → Board from an existing Saved Filter → 命名、選 filter → Create board。或 project 側欄 hover + → 選類型 → Advanced → 選 filter任何 JQL 條件（跨 project、只看某 component、某 label…）；TMP 要第二個 board 的唯一方法；別人分享給你的 filter 也可用
考題長相
「Project 沒出現在建 board 的下拉清單」→ 你沒有它的 Browse Projects，或它是 TMP → 改用 saved filter。「一個 board 看三個團隊的 bug」→ filter project in (A,B,C) AND issuetype = Bug ORDER BY Rank 再建 board。

最常見的求助
最常聽到的求助是「他明明有 Project A 的權限，為什麼看不到我的 board？」——問題出在第一道門：底層的 saved filter 沒有分享給他。要記得這是兩道獨立的門，filter 決定「看不看得到這個 board」，各 project 的 Browse Projects 才決定「board 上看得到哪些卡片」。分享 filter 的路徑是 Filters → 該 filter → Edit → Viewers，這件事不需要 Jira admin，但操作的人要有 Share dashboards and filters 這個全域權限。
Board location

Board 掛在 project 或個人 profile，可隨時搬

項目內容
兩種位置某個 project（在該 project 側欄顯示）或你的 profile（個人 board）。建 board 時就會問
怎麼改Board ••• → Board settings → General → Location 欄位 → 輸入 project 名稱或你的名字 → 立即生效
位置失效時掛在停用的 project 或被停用／刪除的 user 上，board 會找不到；project admin 或 board admin 要重新指定 location 才能再存取
Location 影響什麼只影響兩件事：這個 board 會出現在哪裡（哪個 project 的側欄，或誰的個人 profile），以及哪個 project 的 admin 有權管理它。它完全不影響 board 上顯示哪些 issue——那是 filter 決定的
找 board/ 快速搜尋（最近的 board 先出現）；加星後在 For you 依 starred 排序；project 側欄的 board 清單
Copy board

複製 board：副本沿用同一份 filter

路徑：/ 快速搜尋 → Go to all: Boards → 找到來源 board → 右側 More actions ••• → Copy。

圖 3　Copy board 複製的是視圖設定，不是 filter。要讓副本有獨立資料範圍，得另存新 filter 再指定給它。
項目官方明說的官方沒有說的
資料範圍your new board will be based on the same work item filter as the original board——副本用同一份 filter官方沒有提到任何「自動複製出一份新 filter」的行為，所以不能假設副本會有自己獨立的 filter
管理權you'll be the administrator of your new board——執行複製的人是副本的 administrator沒有列出完整 Administrators 名單：不能推論「只有複製者」，也不能斷言「原管理員全部保留」
Filter 編輯權you may not be able to edit the filter if it wasn't created by you——filter 不是你建的就可能改不動官方沒有說複製 board 會連帶把 filter 的編輯權給你；board 的管理權與 filter 的編輯權是兩回事
複製後的檢查清單
比對三件事：① 新舊 board 的 Saved Filter 是否同一個；② 誰能編輯該 filter；③ Board settings → Administrators 的使用者與群組（複製前後各看一次）。沿用同一 filter 表示日後改查詢會同時波及兩個 board——Copy board 不等於 Copy filter。
考題長相
「複製 board 後想讓副本只看 API 的工作」→ 另存新 filter 再指定給副本，不能直接改共用 filter（會動到原 board）。選項若寫「複製一定會產生新 filter」或「複製一律需要 Create Shared Objects 權限」，都超出官方原文。
跨 project 的代價

哪些設定支援跨 project、哪些會打架

Board 設定跨 project要注意的事
Filter✓用 project in (…) 把多個 project 一次撈進來。JQL 結尾一定要加 ORDER BY Rank，否則 board 上的卡片拖不動，因為 Jira 是靠 Rank 這個欄位記住手動排序的
Columns ↔ statuses✓Unmapped statuses 面板會列出所有 project 的 workflow status；兩邊 workflow 不同時，要把每個 project 的「完成」status 都對到最右欄，否則那個 project 的 issue 永遠算未完成
Swimlanes✓Swimlanes 的分組方式裡有一個 Projects 選項，就是專為跨 project board 設計的，可以讓每個 project 各佔一條泳道；想要更彈性的分組也可以改用 Queries 自己寫 JQL
Quick filters✓常見做法是替每個來源 project 各建一個 quick filter（例如 project = A），讓成員一鍵就能把畫面收斂到自己團隊的工作
Sprints（Scrum）✓ 但有代價Sprint 會跨 project；官方（Manage Sprints 權限說明）：sprint 含多個 board／project 的工作時，要更新 sprint 需要所有相關 project 的 Manage Sprints 權限；同一張 issue 只能在一個 active sprint。
權限名稱核對：官方 CMP 權限清單只有 Manage sprints（涵蓋建立、開始、完成、調整）；本次查閱未找到名為 Create and Reorder Sprints 的獨立權限，別把操作描述當成權限名
Versions／Releases✗Version 屬於各自的 project：不能把 A 的 issue 指到 B 的版本；兩個 project 各有一個「秋季版」也是兩個不同的 version，要協調發版就各自管理
Rank（重排）✓官方：只有在 ranking 已啟用、且你對該 issue 具備 Schedule work item 與 Edit work item 兩個權限時才能排序。看得到 board、甚至是 board admin，都不等於能重排所有來源 project 的工作
Estimation✓估算方式是整個 board 一種，不能一個 project 用 story points、另一個用小時。所以跨 project board 上的兩個團隊必須先講好同一套估點尺度，否則加總出來的 velocity 沒有任何意義
Kanban sub-filter／Release✓Release 動到的是 project 層的 version，而 version 不能跨 project 共用；所以在跨 project board 上清 Done，得由各個 project 各自發佈自己的版本
Card colors／layout、working days、detail view✓這幾項都是純粹的 board 層設定，跟 issue 屬於哪個 project 無關，跨 project 使用不會有任何問題
Simplified workflow✗官方條件：board 的 filter 只含一個 project、該 project 所有 issue type 共用同一個 workflow、workflow 只用 Atlassian 內建的 post function／validator／condition、每個 status 至少一條出去的 transition；跨 project board 不能在 board 上加 status
Board admin✓Board settings 的 Administrators；project admin 只對 board location 所在的 project 有管理權，對另一個 project 的 admin 而言這個 board 不是他管的
考題長相
「跨 project board 完成 sprint 時，B project 的 Cancelled issue 被帶到下一個 sprint」→ B 的 Cancelled 沒對到最右欄。「PM 只有 A 的 Manage Sprints，開始 sprint 失敗」→ 跨 project sprint 要兩邊都有。「想在跨 project board 直接加 status」→ simplified workflow 只支援單 project。
情境練習

先自己判斷，再點開解答

三個開發團隊各有 project，主管想在一個 board 看全部的 Bug。
解答
先建一份 saved filter：project in (A,B,C) AND issuetype = Bug ORDER BY Rank ASC（結尾的 ORDER BY Rank 不能省，否則卡片拖不動），再用 Board from an existing Saved Filter 建一個 Kanban board。最後別忘了把 filter 分享給主管與團隊——board 的可見性是跟著 filter 走的，沒分享出去，別人連 board 都打不開。
同事對 A、B 兩個 project 都有 Browse，但打開你給的 board 連結是空白或無權限。
解答
因為底層的 saved filter 沒有分享給他。這是「第一道門」——能不能打開這個 board，取決於他有沒有存取該 filter 的權限，跟他對 project 有什麼權限無關。解法是到 Filters 找到那份 filter，編輯它的分享對象（Viewers）把他加進去；執行這個動作的人需要 Share dashboards and filters 全域權限，但不需要是 Jira admin。
Filter 分享給整個公司，但同事在 board 上只看得到 A 的卡片。
解答
因為他沒有 B project 的 Browse Projects 權限。這題考的是兩道門的分工：filter 分享只打開第一道門（能不能看到這個 board），至於 board 上哪些卡片顯示得出來，是由他對每一個來源 project 各自的權限決定的。所以會出現「board 打得開、卡片只有一半」這種看似奇怪、其實完全合理的現象。
TMP 團隊想要第二個 board 專看 component = API 的 issue。
解答
這題有兩個關卡。第一，TMP 根本沒有 component 這個功能，所以 component = API 這個條件寫不出來，要先改用 label 或自訂欄位來標記這批 issue。第二，TMP 不能直接在 project 裡再加一個 board，唯一的路是把條件存成 saved filter，再用「Board from an existing Saved Filter」建出第二個 board。
跨 project Scrum board，PM 按 Start sprint 被拒。
解答
因為這個 sprint 裡含有多個 project 的 issue，而官方規定：要更新一個橫跨多個 board／project 的 sprint，操作者必須對所有相關 project 都具備 Manage Sprints 權限，缺一個就會被擋。解法是請 Jira admin 在缺的那個 project 的 permission scheme 裡，把 Manage Sprints 補給 PM 所屬的 role。
跨 project board 上，B project 的 issue 進了 Cancelled 卻一直算未完成。
解答
因為 B project 的 Cancelled 這個 status 沒有被對應到 board 的最右欄（也可能根本躺在 Unmapped statuses 面板裡）。board 判定「完成」的依據是 issue 落在最右邊那一欄，而不是 status 的名字看起來像不像結束。跨 project board 特別容易踩到這個坑，因為兩個 project 的 workflow 往往不同。到 Board settings → Columns，把 B 的 Cancelled 拖進 Done 欄就解決了。
Board 掛在已離職同事的 profile 上，現在沒人打得開。
解答
這是 location 失效：board 掛在一個已被停用或刪除的使用者 profile 上，等於它的家沒了，一般人再也找不到入口。解法是由 project admin 或 board admin 到 Board settings → General → Location，把位置改成某個現存的 project（或自己的 profile），board 就會重新出現在該 project 的側欄。同樣的狀況也會發生在 board 掛在已停用的 project 上。
想在跨 project 的 board 上直接按 + 加一個 column 兼 status。
解答
做不到。board 上那個「按 + 直接新增 column 並同時建立 status」的便利功能叫 simplified workflow，它有嚴格的啟用條件，其中一條就是 board 的 filter 只能包含一個 project。跨 project board 不符合條件，所以沒有這個按鈕。正確做法是請 Jira admin 到每一個來源 project 的 workflow 各自加上這個 status，再回到 Board settings → Columns 把它們對應到同一欄。
A project 的 admin 想改一個 location 在 B project 的跨 project board 的 columns。
解答
改不了。能管一個 board 的只有兩種人：該 board location 所在 project 的 project admin，以及被列在 Board settings → Administrators 裡的 board admin。這位 A 的 admin 兩者都不是——他對 A 的管理權不會延伸到掛在 B 底下的 board。解法有兩個：請 B 的 project admin 幫忙改，或是請對方把他加進這個 board 的 administrators 名單。
改了共用 filter 的 JQL，另一個團隊的 board 突然少了一半卡片。
解答
這是正常且必然的結果，不是 bug。board 並不保存自己的 issue 清單，它每次都是去問 filter；同一份 filter 同時餵養好幾個 board 時，改動 JQL 就會一次影響全部。想讓兩個團隊互不干擾，做法是各自存一份 filter（用 Save as 複製一份再修改），再把新的 filter 指給自己的 board。
複製了一個 board 給新團隊，改了副本的 filter 查詢後，原團隊說他們的 board 也變了。
解答
因為 Copy board 並不會複製 filter——官方原文寫得很清楚，副本是基於同一份 work item filter 建立的。所以你改的其實是兩個 board 共用的那份查詢，原團隊當然跟著遭殃。正確順序是：先把 filter 用 Save as 另存成一份新的，再到副本的 Board settings 把它指過去，兩個 board 才算真正脫鉤。記住這句話：Copy board ≠ Copy filter。
題目選項寫「複製 board 後，原 board 的所有管理員都會保留在副本」。
解答
這個敘述超出了官方講過的範圍。官方只寫了一句「執行複製的人會成為新 board 的 administrator」，並沒有交代原本那份管理員名單會不會一起帶過去。所以「只有複製者」和「原管理員全部保留」兩種說法都不能當成定論——這是教材刻意保留的證據界線。實務上要確認，唯一可靠的方法是複製前後各看一次 Board settings → Administrators 做比對。
成員在跨 project board 的 backlog 拖不動 API 團隊的卡片，但看得到、也是 board admin。
解答
因為拖曳排序（rank）需要對那張 issue 本身具備權限，官方列的條件是：ranking 功能已啟用，而且操作者同時擁有該 issue 的 Schedule work item 與 Edit work item 兩個權限。這位成員缺的是 API team 那個 project 的 issue 權限。要特別注意：board admin 管的是 board 的設定，不會給你任何來源 project 的 issue 權限，兩者是不同層級的東西。
常見陷阱

考題喜歡設的誤解

誤解事實
「Board 分享 = 分享 board 連結」把 board 的網址貼給別人沒有用。真正要分享的是底層那份 saved filter，對方拿到 filter 的存取權，才打得開這個 board
「Filter 分享了，大家就看得到所有卡片」不會。filter 只打開第一道門，每張卡片還要看他對該 issue 所屬 project 有沒有 Browse Projects 權限，所以常出現「board 開得起來、卡片只看得到一半」
「Board location 決定 board 內容」不。location 只決定 board 放在哪裡找得到、哪個 project 的 admin 能管它；board 上顯示什麼，完全由 filter 決定
「Sprint 是 project 的東西」sprint 其實屬於 board，因此可以橫跨多個 project；代價是要更新這種 sprint 時，必須對每一個相關 project 都有 Manage Sprints 權限
「跨 project board 也能用 simplified workflow」不行。simplified workflow 的啟用條件之一就是 board 的 filter 只包含一個 project，跨 project board 不符合，所以沒有在 board 上直接加 status 的功能
「TMP 可以在 project 裡再加 board」不行。一個 TMP 只有一個內建 board，想要第二個只能先存一份 saved filter，再用它建立
「Copy board 會複製出一份新 filter」不會。副本沿用的是同一份 filter，改了副本的查詢等於改了原 board；想要獨立範圍，得自己 Save as 另存一份新 filter 再指給副本
「權限清單裡有 Create and Reorder Sprints」官方清單是 Manage sprints；查閱未見該獨立權限名稱
「兩個 project 的同名版本是同一個 version」不是。version 是屬於各自 project 的物件，兩個 project 各有一個「秋季版」也是兩個毫不相干的 version，發版要各自管理
實作（30 分鐘）

用兩個 project 做一次

  1. 建 filter project in (LAB, OPS) ORDER BY Rank ASC，先不分享；用它建 Scrum board。
  2. 用第二個帳號（有 LAB 的 Browse、沒有 OPS 的）開 board 連結 → 無權限；分享 filter 給他 → 看得到 board 但只有 LAB 的卡片；給他 OPS 的 Browse → 兩邊都看得到。
  3. Board settings → Columns：把 OPS 的 Done 從 unmapped 拖到最右欄；建 sprint 把兩個 project 的 issue 都拉進去，Complete sprint 觀察。
  4. Swimlanes 改成 Projects；建兩個 quick filter project = LAB、project = OPS。
  5. Board settings → General → Location 改到你的 profile 再改回 project，觀察側欄變化。
  6. 把 filter 改成 project = LAB，回 board 看 OPS 的卡片消失，體會「board 跟著 filter 走」。
  7. Copy board：/ → Go to all: Boards → 對這個 board 用 ••• → Copy。比對三件事：新舊 board 的 Saved Filter 是否同一個、Board settings → Administrators 的名單、你能否編輯該 filter。接著改副本的 filter 查詢，回原 board 確認兩邊同時改變；再 Save as 一份新 filter 指給副本，確認兩者脫鉤。
