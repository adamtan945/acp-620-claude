620.2.6 · Configure board swimlanes, card colors, card layout, working days, and issue detail view

Swimlanes、card colors、card layout、working days、issue detail view

這五個設定都不改變「哪些 issue 在 board 上」（那是 620.2.4 的事），它們改變的是怎麼分組、怎麼上色、卡片顯示什麼、報表怎麼算天數、點開卡片看到什麼。考題喜歡問每個設定的使用情境與規則細節（第一個符合的 query、最多三個欄位、哪些報表吃 working days）。

術語：考試用 project／issue；現行產品為 space／work item。本教材沿用考試用語。
這一節考什麼

三條 bullet，翻成考題語言

官方 bullet考題會怎麼問
Know how to apply each board configuration — card colors, card layout, working days, and issue detail view各在 Board settings 的哪一頁、選項有哪些、誰能改
Understand the use cases for each board configuration item「想一眼看出誰的工作」→ swimlane by assignee 或 card color by assignee？「想在卡片上看 due date」→ card layout。要分得清「分組」「上色」「顯示欄位」三種手段
Understand the relationship between working days settings and board reports哪些報表會跳過週末與假日（burndown、sprint／epic／version report、control chart、兩個 gadget）；哪些不會（CFD）
全景

五個設定在 Board settings 的位置與分工

圖 1　同一個需求常有三種手段：分組（swimlane）、上色（card color）、顯示欄位（card layout）。考題會給情境要你選最合適的一種。
需求最合適為什麼不是其他
一眼看出每個人手上有幾張Swimlanes by Assigneescard color by assignee 也行，但人多顏色就分不清；分組能直接數

Swimlanes

Queries 模式：由上到下、第一個符合的 lane 贏

Base swimlanes on行為
Queries每條 lane 一段 JQL；issue 進由上而下第一條符合的 lane；都不符合進 Everything Else（刪不掉、永遠在最下）。預設有一條 Expedite：priority = Blocker。lane 內的 ORDER BY 被忽略，一律照 rank
Stories每個 parent 一條 lane，其 sub-task 在底下；沒有 sub-task 的 issue 集中在所有 lane 下方
Assignees每人一條；Unassigned 可設在最上或最下
Epics依 parent epic 分；沒 epic 的在下方；epic 不在 board filter 內時它的 lane 不會出現（KB 常見問題）
Projects跨 project board 用
No swimlanes取消橫向分組

自己試：三條 query 用 ▲▼ 換順序，看同一張 issue 跑到哪條 lane。

Queries（由上到下）
∞Everything Else刪不掉

考題長相
「一張 Blocker 等級的 Bug，Expedite lane 和 Bugs lane 都符合，它會在哪？」→ 排在上面的那條。「怎麼讓它進 Bugs lane？」→ 把 Bugs 拖到 Expedite 上面，或把 Expedite 的 JQL 改成排除 Bug。
Card colors

四種上色依據，Queries 一樣是「第一個符合」

Colors based on規則
Issue types每種 type 一色；預設 Bug 紅、Task 藍…可自訂
Priorities用全站 priority 設定的顏色（Jira admin 在 ⚙ → Issues → Priorities 定義）
AssigneesJira 自動分配顏色給被指派的人
Queries每條 JQL 一色；依第一個符合的 query 上色；都不符合＝灰色。官方例：due <= "24h"、reporter = "Jane"、duedate > endOfMonth()
None不上色
和 swimlane 的差別
兩者都可用 JQL、都是「第一個符合」，但 swimlane 改變位置（分組），card color 只改外觀（左緣色條）。一張 board 可以同時用：swimlane by Assignee ＋ card color by Issue type。
沒有「依 Status 上色」的選單，就不能依狀態上色嗎？
可以——用 Queries 寫 status = "In Review" 就好。直接提供的依據只有 issue type、priority、assignee、Queries 四種；「某欄位沒有專屬選單」不等於「做不到」，只要 JQL 表達得出來就行。同理，saved filter 不是第五種依據，但可以在 Queries 裡用 filter = 12345 引用你有權存取的篩選器。
Card layout

最多再加三個欄位，backlog 與 board 可以不同

Card layout
  • Board settings → Layout → Card layout
  • 每張卡片最多再加 3 個欄位（Summary、key、type、priority、assignee 頭像本來就有）
  • Scrum board 可分別設定 Backlog 與 Active sprints 的欄位；Kanban 只有一組
  • 常見：Story points、Due date、Fix versions、Labels
Days in column
  • 同頁的開關，卡片右下顯示小圓點表示「在這一欄待了幾天」
  • 官方例：1 天 一個灰點；5 天 三灰一紅；20 天以上四個紅點
  • 預設：Kanban 開、Scrum 關
  • issue 搬回原欄會累計之前待過的天數

另有 card covers（卡片封面圖：顏色、漸層、Unsplash、附件）：在卡片 ••• → Select cover 設定；View settings → Card cover 可整張 board 關掉。它不在 Board settings 裡，屬於檢視偏好。

TMP 不是「完全不能調卡片」——但要分清楚是哪一種調
官方 Customize your view of the board and backlog：「Unless otherwise noted, view settings in software spaces are the same for both company-managed and team-managed spaces」，而且 「View settings are applied per user」。TMP 在 board 可切換 Work type、key、Epic、Linked work items、Priority、Assignee、Card cover，以及 Due date、Labels（team-managed 專屬）；backlog 可切換 Work type、key、Version、Epic、Status、Priority、Assignee、Due date。
但同一頁把 Card layout（company-managed spaces） 標成 CMP 專屬。所以：顯示／隱藏「既有的」欄位＝兩種 project 都行、每人各自設定；「再加三個自選欄位」＝只有 CMP、board 共用設定。看題目問的是哪一種。
Working days

哪些報表會跳過週末與假日

圖 2　官方列出的受影響清單就是右上框那七項；不在清單裡的報表用日曆日。
  • 路徑：••• → Configure board → Working days；board admin 或 project admin。
  • 設定是每張 board 各自的，不是全站；跨時區團隊要各自設。
  • Burndown 的 guideline 會在非工作日「走平」，所以週末沒進度不會被畫成落後。
  • 時區設錯會讓 sprint 起訖日看起來差一天，是「guideline 怪怪的」的常見原因（見 620.2.5）。
Issue detail view

點開卡片右側面板看到什麼

類別欄位
永遠顯示、不可移除Summary、Description
永遠顯示、可調Status、Priority、Reporter、Assignee、Date created、Date updated、Comments、Attachments
條件顯示Estimate（依 board estimation 設定）、Component（project 有 components 才可編）、Labels、Affected versions、Fix versions、Parent、Issue links（有連結才顯示）、Subtasks
現行文件的變化
考綱的「Issue detail view」原本是 Board settings 的一個分頁；現行官方頁面把設定路徑指到 Project settings → Screens →（該 issue type 的 scheme）→ View issue screen（需要 Administer Projects），並說明欄位要先在 issue type 的 screen 上且未被 field configuration 隱藏。考試若問「board 設定裡的 issue detail view 由誰管」，答 board admin／project admin 即可；實務上現在是改 screen。
需求配對：別讓一條 JQL 承擔所有介面設定
「想在卡片上看到到期日」→ Card layout；「想一眼分辨緊急工作」→ Card colors（Queries）或 Queries swimlane；「報表不要把假日算成落後」→ Working days；「開會時只看某一組工作」→ quick filter（620.2.4）。四個需求四個設定，考題常把它們混在同一個選項裡。
情境練習

先自己判斷，再點開解答

Scrum master 想讓 Blocker 永遠在 board 最上面，其他不變。
解答
Swimlanes by Queries，保留預設 Expedite（priority = Blocker）在最上；其餘落到 Everything Else。
Query swimlane 有「Bugs」（type = Bug）在第一條、「Expedite」在第二條，一張 Blocker 的 Bug 會在哪？
解答
Bugs lane——由上到下第一個符合的 query 贏。
Swimlane query 裡寫了 ORDER BY duedate，lane 內卻沒照 due date 排。
解答
正常，swimlane 的 ORDER BY 被忽略，lane 內一律照 rank。
Card colors by Queries 設了兩條，一張 issue 兩條都符合，會是什麼顏色？都不符合呢？
解答
第一條 query 的顏色；都不符合是灰色。
PM 想在卡片上看到 Story points、Due date、Fix version、Labels 四個欄位。
解答
Card layout 最多加 3 個，得取捨；Scrum 可讓 backlog 與 active sprint 各放不同的 3 個。
團隊週末不上班，burndown 每到週一都顯示「落後」。
解答
Working days 沒把週六日拿掉；設好後 guideline 會在週末走平。
設了 working days 之後，Cumulative flow diagram 還是算週末。
解答
正常，CFD 不在受影響清單（burndown、sprint／epic／version report、control chart、Sprint Health／Burndown gadget）。
兩個時區的團隊共用一張 board，sprint 起訖看起來差一天。
解答
Working days 的 timezone 是每張 board 一組；分兩張 board 各自設，或統一用一個時區並告知。
卡片右下出現四個紅點是什麼意思？
解答
Days in column：issue 在同一欄超過 20 天（含搬回來累計）。
Swimlanes by Epics 時，某個 epic 的 child 都在 board 上但 lane 沒出現。
解答
該 epic 本身不在 board filter 內（例如屬於另一個 project）。把 epic 的 project 加進 filter，或改用其他 swimlane 依據。
常見陷阱

考題喜歡設的誤解

誤解事實
「swimlane 會過濾 issue」只分組，不過濾；不符合任何 query 的進 Everything Else
「Everything Else 可以刪」刪不掉，永遠在最下
「card layout 想加幾個欄位都行」最多 3 個
「working days 是全站設定」每張 board 各自設
「working days 影響所有報表」CFD、velocity 等照日曆日
「card color 的 query 都符合會混色」第一個符合的顏色
「card cover 在 Board settings 裡」在卡片 ••• 與 View settings，屬檢視偏好
實作（30 分鐘）

五個設定各動一次

  1. Swimlanes → Queries：加一條「Bugs」type = Bug 放在 Expedite 上面，建一張 Blocker 的 Bug，看它進 Bugs；把 Bugs 拖到下面，看它跳到 Expedite。
  2. Card colors → Queries：第一條 due <= "24h" 紅、第二條 type = Bug 橙；建一張明天到期的 Bug，確認是紅。
  3. Card layout：加 Story points、Due date、Labels；試加第四個看被擋。Scrum 的 backlog 與 active sprint 各設不同欄位。
  4. Working days：拿掉週六日、加一個假日；看 burndown guideline 走平；打開 CFD 確認不受影響。
  5. Days in column：把一張 issue 留在 In Progress，隔天看灰點；用 Move 搬到別欄再搬回，觀察累計。
  6. 空泳道的判讀：把 Bugs 泳道的條件改成一個目前沒有工作符合的值（例如 labels = nonexistent），確認畫面沒有那條橫列。看不到泳道不代表設定被刪掉——回 Board settings 確認規則還在，再把條件改回來。Epic 泳道另外要查 parent 有沒有落在 board filter 範圍內。
  7. 全部還原：swimlanes、card colors、card layout、working days 都設回原值，並移除測試用的 label 與假日。
