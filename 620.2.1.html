620.2.1 · Recommend an appropriate board type (Scrum, Kanban, Kanban with backlog)

選擇 board 類型：Scrum、Kanban、Kanban with backlog

620.2 是最大的 domain（29%），而這一節是它的入口：先搞懂 board 到底是什麼（一個 saved filter ＋ 一組 column 對應 ＋ 一種工作節奏），三種類型的差別就只剩「有沒有 sprint」「backlog 放哪裡」。

術語：考試用 project／issue；現行產品為 space／work item。本教材沿用考試用語。
這一節考什麼

一條 bullet，三種 board

官方 bullet考題會怎麼問
Understand board types and features for each – scrum, Kanban and Kanban with backlog「團隊 X 的工作方式是…，該建哪種 board？」（情境選型）、「Kanban board 的 Done 怎麼清掉？」「Kanban backlog 誰能開、開了會怎樣？」（功能差異）
核心模型

Board ＝ filter ＋ columns ＋ 工作節奏

官方定義：board 把團隊的工作顯示成可在 columns 間移動的卡片；columns 代表 issue 的 status。它是「戰術」工具（未來一兩週），長期規劃是 Timeline 的事。一個 board 最多顯示 5,000 個 issue。

圖 1　三種類型共用前兩層（filter、columns），差別在第三層「工作節奏」。

選型流程

兩個問題就能決定

圖 2　關鍵字：「sprint／承諾／velocity」→ Scrum；「持續交付／維運／支援」→ Kanban；「backlog 太長把 board 塞爆」→ Kanban with backlog。
選 Scrum 的訊號
  • 兩週一次 sprint planning、review
  • 要估點、看 velocity 預測產能
  • 「這個 sprint 承諾什麼」是團隊的語言
選 Kanban 的訊號
  • 工作隨時進來（維運、支援、內容）
  • 關心 cycle time、瓶頸、WIP
  • backlog 小，第一欄放得下
選 Kanban with backlog 的訊號
  • Kanban，但 backlog 上百張
  • PM 要在獨立畫面排 rank、用 Epic panel 規劃
  • 團隊只想在 board 上看 WIP
Kanban backlog 細節

怎麼開、誰能開、開了哪些 issue 會出現

項目內容
誰能開該 board location 的 project admin，或該 board 的 board admin（Jira admin 亦可）；開了之後 board 使用者才看得到 Backlog
怎麼開Board ••• → Board settings → Layout → Columns → 把一個既有 status 拖進 Kanban backlog 面板（或 Add status 建一個再拖）
Backlog 畫面顯示什麼Backlog 段（對到 kanban backlog 欄的 status）＋ 下一段（通常叫 Selected for Development，對到 board 第一欄）；可在兩段之間拖曳
可見規則issue 要符合 board filter，且 status 對到 backlog 欄或下一欄。如果所有 status 都塞在第一欄，Backlog 段會是空的
在 Backlog 能做建 issue、拖曳排 rank、直接編 Summary／Assignee／Story point／Parent／Priority、多選 bulk edit、建 sub-task、拖到下一段＝轉換狀態
Epic 的顯示開了 kanban backlog 後可選 epic 顯示成卡片或放在 backlog 的 Epic panel
完成工作怎麼離開 board

清 Done 的三條路：Complete sprint、Release、14 天自動清

「Done 欄太長」是視圖問題，不是節奏問題。先辨認管理方式，再選清理手段；不要因為想保留幾週的 Done 就去改 board 類型。

情境怎麼清誰能做
CMP ScrumComplete sprint：最右欄的 issue 視為完成，清出 board 且不回 backlogManage Sprints
CMP KanbanRelease 版本（sub-filter 排除已 release 的 fixVersion）；或調 Hide completed work（1／2／4 週或不隱藏，詳見 620.2.3）Manage Versions／board admin
TMP（未啟用 Sprints）Done 欄 ••• → Clear Done work items 手動清；另有移入 Done 後 14 天自動清官方原文：Only space admins and Jira admins can clear Done work items
TMP（已啟用 Sprints）不能手動清；完成 sprint 時一併清出，且不回 backlog—
清 parent 會連 sub-task 一起清（TMP）
官方原文：When a parent work item is cleared, its subtasks are also cleared, regardless of each subtask’s status.——即使 sub-task 還沒完成也會從 board 消失。這是「從 board 移除」不是刪除：用 Done 欄的 See all Done work items，或開 work item navigator 選 Done 篩選，仍找得到。
考題長相
「維運團隊只嫌 Done 欄太長，需要改成 Scrum 嗎？」→ 不必。TMP Kanban 手動 Clear Done 或等 14 天；CMP Kanban 用 Release／Hide completed work。把視圖整潔需求誤當成 sprint 節奏需求是典型陷阱。
Parallel sprints

同一個 backlog，多個 active sprint

同一份 backlog 可以同時跑多個 sprint，各自獨立開始與完成——例如開發一個、設計一個。company-managed 與 team-managed 都支援，不要當成 CMP 專屬功能（team-managed 的支援見 JSWCLOUD-17195，狀態 Closed／Fixed）。

項目內容
CMP 啟用路徑⚙ Settings → Jira apps → Jira configuration → 切換 Parallel sprints for company-managed spaces；需 Administer Jira 權限。這條路徑不適用 TMP
資料關係多個 sprint 共用同一個 backlog；每個 sprint 各自 start／complete；同一張 issue 仍只能在一個 active sprint
報表不會讓同一張 Velocity chart 自動按團隊拆開；官方也提醒此用法假設各團隊估算方式一致，兩組不同尺度的點數不該相加比較
把未完成工作換到另一個 active sprint先退回 backlog，再加入該 active sprint；不能直接在兩個 active sprint 之間拖
重開已關閉的 sprint官方：若要把誤移到未來 sprint 的工作移回已關閉的原 sprint，必須先啟用 parallel sprints 才能重開
怎麼建、誰能建

三種來源、一個前提

來源路徑結果
新 projectBoards → Create board → Scrum／Kanban → 新 software projectproject 與 board 一起建
既有 project（可多選）同上 → 選一或多個既有 project；或 project 側欄 hover → + → Scrum／Kanban → 選要納入的內容 → Create自動產生 filter project = "X" ORDER BY Rank ASC
Saved filterCreate board → Board from an existing Saved Filter；或側欄 + → Advanced → 選 filter跨 project、或 TMP 要第二個 board 的唯一方法；board 對所有能存取該 filter 的人可見
前提
從既有或新 project 建 board 都需要 Browse Projects 權限；project 沒出現在下拉時，通常是沒權限或它是 TMP → 改用 saved filter。board 建好後可自由改設定，但 Scrum ↔ Kanban 不能互轉，要換就用同一份 filter 再建一個（產品行為；官方 Create board 頁未明寫，Board settings 沒有切換類型的選項）。
情境練習

先自己判斷，再點開解答

行銷團隊每天有新需求進來，沒有固定發布週期，主管想知道一張需求平均多久做完。
解答
Kanban：連續流、看 control chart 的 cycle time。
開發團隊兩週一次 planning，PM 要用歷史數據預測下個 release 能做多少。
解答
Scrum：sprint ＋ 估點 ＋ velocity。
維運團隊用 Kanban，但 backlog 累積 300 多張，第一欄捲不完，PM 想用 Epic panel 分組排序。
解答
Kanban with backlog：把 Backlog status 拖進 Kanban backlog 面板。
Scrum board 建好了，成員說 board 上一張卡都沒有。
解答
Sprint 還沒開始；Scrum 的 board 只顯示 active sprint 的 issue，先到 Backlog 建 sprint 並 Start。
CMP 的 Kanban board，Done 欄已經堆了兩個月的卡片。
解答
Kanban 靠 Release 清 Done（sub-filter 預設排除已 release 的 fixVersion）；把完成的 issue 指到版本並 Release。
TMP 的 Kanban，成員問為什麼上週 Done 的卡片自己不見了。
解答
TMP 沒 sprint 時 Done 的 issue 14 天自動清掉；用 See all Done issues 找回。
開了 Kanban backlog，但 Backlog 畫面的 Backlog 段永遠是空的。
解答
可見規則：issue 的 status 要對到 backlog 欄或下一欄；檢查 columns 對應，至少要有一個 status 對到 board 的第一欄（Selected for Development）之外的欄位。
Project admin 想把現有的 Kanban board 改成 Scrum。
解答
做不到，類型不能互轉；用同一份 filter 再建一個 Scrum board。
TMP 團隊想要第二個 board 看不同切面。
解答
TMP 不能直接加 board；建 saved filter，再用「Board from an existing Saved Filter」建。
誰能把 Kanban backlog 開起來？
解答
Jira admin 或該 board 的 board admin（在 Board settings → Columns 拖 status 進 Kanban backlog 面板）。
常見陷阱

考題喜歡設的誤解

誤解事實
「Board 屬於某個 project」Board 屬於一份 filter；location 只是它掛在哪裡
「Scrum board 隨時看得到所有 issue」只看 active sprint；sprint 開始前是空的
「Kanban 的 Done 會自動消失」CMP 要 Release；只有 TMP（無 sprint）才 14 天自動清
「Kanban with backlog 是另一種 board 類型」就是 Kanban board 開了 Kanban backlog；仍是 Kanban
「Kanban board 不能估點」可以設 estimation，只是通常不用；報表以 control chart／CFD 為主
「一個 board 可以顯示無限多 issue」上限 5,000
「Board 可以從 Kanban 切成 Scrum」不能互轉，用同一份 filter 重建（產品行為，官方頁未明寫）
「Parallel sprints 是 CMP 專屬」CMP、TMP 都支援；只有啟用路徑不同（CMP 走 Jira configuration，需 Administer Jira）
「TMP 隨時都能手動 Clear Done」啟用 Sprints 後不能手動清；且只有 space admin 與 Jira admin 能清
「清 Done 只清完成的卡」清 parent 時連未完成的 sub-task 一起從 board 清掉
實作（30 分鐘）

三種 board 各建一個，用同一份 filter

  1. 存一個 filter project = LAB ORDER BY Rank ASC。
  2. 用它建 Scrum board：確認 board 空的 → 到 Backlog 建 sprint、拉 3 張 issue、Start sprint → board 出現卡片 → Complete sprint 看 Done 消失且不回 backlog。
  3. 用同一份 filter 建 Kanban board：看預設四欄；把 3 張 issue 拉到 Done → 指 fixVersion 並 Release → Done 清空。
  4. 在 Kanban board 的 Columns 設定把 Backlog status 拖進 Kanban backlog 面板 → 出現 Backlog 畫面；把所有 status 都拖到第一欄，觀察 Backlog 段變空，再改回來。
  5. 試著在 Board settings 找「改成 Scrum」——確認沒有這個選項。
  6. TMP 清 Done：另建一個 TMP Kanban（未開 Sprints），把一張含 sub-task 的 parent 拖到 Done → Done 欄 ••• → Clear Done work items → 確認 parent 與未完成的 sub-task 一起從 board 消失，再用 See all Done work items 找回；接著開啟 Sprints feature，確認手動清的選項不見了。
  7. Parallel sprints：在 CMP 走 ⚙ Settings → Jira apps → Jira configuration 開啟，建兩個 sprint 同時 Start；把一張未完成 issue 從 sprint A 換到 sprint B——先退回 backlog 再加入，體會不能直接互拖。
