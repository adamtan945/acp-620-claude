3 分鐘速覽

三種 board，差在工作節奏

  1. Scrum＝sprint 節奏固定週期承諾一批工作；sprint 還沒開始時 board 是空的。
  2. Kanban＝連續流隨時拉新工作，靠 WIP limit 控制；只有 Control chart 與 CFD 兩張報表。
  3. Kanban with backlog 不是第三種類型是在 Kanban board 開 Kanban backlog：把一個 status 拖進 Kanban backlog 面板。
  4. Board 不能 Scrum ↔ Kanban 互轉要換就用同一份 filter 再建一個。
  5. Done 怎麼清Scrum＝Complete sprint；CMP Kanban＝Release 或 Hide completed；TMP Kanban＝14 天自動清或手動 Clear Done。
  6. Parallel sprints你常錯Jira admin 在 Jira configuration 開；一次只能完成一個 sprint；Velocity 不分團隊。
  7. 一個 board 最多 5,000 張（考試版）超過的不會顯示，要縮小 filter。現行新版 board view 已移除一般 board 的上限，只剩從多個 project 拉 issue 的 company-managed software board 仍受 5,000 張限制。

Parallel sprints

同一個 backlog、多個 active sprint

項目重點
誰開、在哪開Jira admin（Administer Jira）：⚙ Settings → Jira apps → Jira configuration → Parallel sprints
完成 sprint一次只能完成一個：先在 Active sprints 選一個 sprint，Complete 按鈕才會出現
Velocity照樣每個 sprint 一組長條，但不分團隊；官方假設各團隊估算方式相同

你練習時錯過

「Velocity 不能分開顯示每個 sprint」是錯的；它本來就一個 sprint 一組長條。真正的限制是不分團隊。「可以一次完成所有 active sprint」也是錯的。

開了 Kanban backlog 看得到 Versions 面板卻沒有 Epics 面板 → Epics 面板無法顯示（或缺權限、或要移除 TMP 的 issue）。

先問 backlog 開了沒：沒開 → 不能顯示；開了 → 要自己開。

不行。Estimation 是 board 的設定，parallel sprints 是同一個 board 跑多個 sprint，只有一種估算方式；velocity 也合在一起不分團隊。要各用各的估算，就每隊一個 board。另外 active sprint 要一個一個完成，parallel sprints 是 Jira admin 在全站開關。

動手做

實作 Lab：開 Kanban backlog、跑兩個平行 sprint

約 25 分鐘Jira admin（parallel sprints 要 Administer Jira）；OPS、WEB 的 board admin

第一次做 Lab？先看 Lab 環境準備：用測試站台、準備測試帳號。畫面名稱可能隨 Atlassian 更新而不同，以下以現行畫面為準。

目標：在 OPS 親手打開 Kanban backlog，看 board 與 backlog 怎麼分工；再在 WEB 開 parallel sprints，體會「一次只能完成一個」。

這個 Lab 對應的考點

Kanban with backlog＝Kanban board 開了 Kanban backlog，不是第三種類型；parallel sprints 由 Jira admin 全站開，active sprint 要一個一個完成。

準備

  • OPS 有幾張 issue 在 Backlog 與 Selected for Development 狀態。
  • WEB 目前沒有 active sprint（若有，先完成它），Backlog 裡至少有 4 張 issue。

步驟

  1. 你應該看到：畫面左邊有 Kanban backlog 面板。如果它已經有 status、側欄也已有 Backlog，表示這張 board 已開過 backlog，先記下是哪個 status。
  2. 你應該看到：Backlog 欄從 board 上消失；側欄出現 Backlog 頁。
  3. 你應該看到：Backlog 頁分成 Backlog 與 Selected for Development 兩段；拖過去的那張卡出現在 board 的第一欄。
  4. 你應該看到：Versions 面板用切換開關就能打開；Epics 面板要先在這張 board 的設定啟用（epic 要選顯示成卡片或放進 epic panel）才會出現。
  5. 你應該看到：開關變成開啟；這是全站設定，不是某個 project 或 board 的設定。
  6. 你應該看到：兩個 sprint 都能開始；Active sprints 上方出現 sprint 下拉選單。
  7. 你應該看到：沒選 sprint 時 Complete sprint 按鈕不出現；選了 Sprint A 才出現，而且只完成 Sprint A。

心像錨點：閉上眼睛想一次這個畫面

讀完了？用這張收攏整節

Scrum 看 sprint、Kanban 看 flow沒 sprint 就沒 sprint 類報表。
類型不能換，要換就另建同一份 filter 建第二個 board。
平行 sprint：admin 開、一次完成一個Velocity 不分團隊。
功能對照
  • Scrum 看 sprint；Kanban 看 flow。
  • Kanban with backlog＝Kanban＋開 backlog，不是新類型。
  • Board 類型不能互轉。
怎麼開、誰能開
  • 開法：Board settings → Columns，把 status 拖進 Kanban backlog 面板。
  • 誰能開：官方寫 Jira administrator 或 board administrator。
Done 欄太長怎麼辦
  • Scrum：Complete sprint。
  • CMP Kanban：Release 或 Hide completed（1／2／4 週）。
  • TMP：14 天自動清；開了 Sprints 就不能手動清。
同一個 backlog、多個 active sprint
  • 開關：Jira admin，Jira configuration。
  • 一次完成一個 sprint。你常錯
  • Velocity 每個 sprint 一組長條，但不分團隊。你常錯
三種來源，一個前提
  • TMP 要第二個 board → 用 saved filter 建。
  • 建 board 需要 Browse Projects。
