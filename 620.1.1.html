620.1.1・Project creation 13%

選擇 CMP 還是 TMP

兩種 project 都能建 issue、跑 board、做報表；真正的差別是設定放在哪、誰能改。

3 分鐘速覽

差別不在功能，在「設定屬於誰」

  1. CMP＝scheme 掛在 project 上設定可跨 project 共用、標準化；改設定要 Jira admin。
  2. TMP＝設定長在 project 裡Project admin 自己改、只影響自己；適合自主、快速開始的團隊。
  3. TMP 沒有的東西你常錯Components、issue security、Affects versions、transition screen（考試版）、匿名公開存取、多個 board（要靠 saved filter）。
  4. TMP 有、別誤會的自訂 issue type、Fix versions（開 Releases）、自訂通知寄件 email、parallel sprints。
  5. 建立 CMP 要 Jira adminTMP 任何人都能建，除非收回 Create team-managed projects 全域權限。
  6. Template 決定工作方式，不決定管理方式選 Scrum 或 Kanban 之後，還要選 CMP 或 TMP。

易錯觀念

考題愛用的錯誤說法

CMP 的 project admin 也能自己改 workflow 的 status 名稱。
考試版不行：CMP 的 workflow 放在 scheme 裡、status 是全站共用物件，要 Jira admin 改。只有 TMP 的 project admin 能自己改 workflow 與 status。
題目要「project admin 自己改 workflow／status」＋「每週 iteration」＋「建好就能用」→ Team-managed Scrum。
你練習時錯過官方來源
TMP 可以在 project 層級設定預設的 issue security level。
不行。Default security level 是 issue security scheme 的功能（只有 CMP）。TMP 沒有 security level，它用的是另一套機制：可以在 issue 上逐張限定 role；現行版也能在 Work types 設定頁按鎖頭，把某個 work type 鎖給指定 role，但只影響之後新建的 issue，已經存在的不受影響（Free 方案不能用）。
TMP 的特性：清 parent 時 sub-task 不管狀態一起清（不是刪除）。
你練習時錯過官方來源
TMP 不能讓 issue 只給某些 role 看、也不能把通知寄給指定 role（因為沒有 scheme）。
TMP 都做得到：Access 設定可限制 issue 只給指定 role 看、Notifications 可選 role。CMP 獨有的是 board 上寫 JQL 的進階設定：sub-filter、JQL swimlane（Queries）、跨 project board。
你練習時錯過官方來源
TMP 不能建自訂 issue type。
可以，project admin 在 Project settings 直接建。
官方來源
TMP 可以加 Affects versions 欄位。
不行（JRACLOUD-85690 未解決）。
你練習時錯過官方來源
選了 Scrum template 就決定了管理方式。
Template 決定工作方式；管理方式另外選。
官方來源
TMP 的 Open access＝公開給網際網路。
Open 只對站台使用者；TMP 不支援匿名。

動手做

實作 Lab：CMP 與 TMP 的設定頁對照

約 20 分鐘Jira admin（可以看全站設定）；另用 Kim 的帳號

第一次做 Lab？先看 Lab 環境準備：用測試站台、準備測試帳號。畫面名稱可能隨 Atlassian 更新而不同，以下以現行畫面為準。

目標：打開 WEB（CMP）與 TEAM（TMP）的 Space settings 並排比較，親眼看「設定掛在 scheme 上」和「設定長在 project 裡」的差別。

這個 Lab 對應的考點

CMP 的設定來自 Jira admin 管的 scheme；TMP 由 project admin 自己改。TMP 沒有 components、issue security、Affects versions；有自訂 issue type、Fix versions（開 Releases）、通知寄件 email。TMP 任何人都能建，CMP 要 Jira admin。

準備

  • WEB、TEAM 照 Lab 環境準備建好。

步驟

  1. 你應該看到：WEB 顯示 Company-managed，TEAM 顯示 Team-managed。題目沒寫類型時，現場就是這樣分辨。
  2. 你應該看到：WEB 有 Permissions、Components 等項目，權限頁顯示的是 WEB Permission Scheme 這份 scheme；TEAM 是 Access、Features、Work types、Notifications，沒有 Components，也沒有 permission scheme。
  3. 你應該看到：TEAM 出現 Releases，work item 可以填 Fix versions；找不到 Affects versions 欄位。
  4. 你應該看到：可以設定通知的寄件 email，收件對象可以選 role。TMP 的 project admin 自己就能改，不用 Jira admin。
  5. 你應該看到：Spike 出現在 Work types 側欄，TEAM 可以直接建這種 work item。CMP 要建新 work type，得由 Jira admin 到 ⚙ Settings 建，再加進 work type scheme。
  6. 你應該看到：Kim 建得出 TMP（預設所有人都有 Create team-managed spaces）；通常選不到或無法建立 Company-managed（那要 Administer Jira）。

試試看：改一個設定，觀察差異

T1⚙ Settings›System›Global permissions：把 Create team-managed spaces 從一般使用者的 group 移除，用 Kim 再按一次 Create space。看結果
Kim 不能再建 TMP。這就是「TMP 任何人都能建，除非 Jira admin 收回這個 global permission」。做完記得加回。
T2用無痕視窗（未登入）打開 TEAM 一張 work item 的網址。看結果
要求登入。TMP 不支援匿名存取；要公開只能用 CMP，把 Browse Projects 給 Public。
T3（想像，不實際做）在 WEB Permission Scheme 改一格權限。看結果
所有使用 WEB Permission Scheme 的 CMP 會一起改變；TEAM 改 Access 只影響 TEAM 自己。這就是「標準化選 CMP、自主選 TMP」。
心像錨點：閉上眼睛想一次這個畫面

Space settings 側欄並排：左邊 WEB 有 Permissions、Components，右邊 TEAM 有 Access、Features。C 掛 scheme、T 長在裡面。

收尾

  • 刪除 TEAM 的 Spike work type（還沒有 work item 時可以直接刪）。
  • Kim 的 KIMT 移到 trash（KIMT 的 admin 是 Kim，可以自己移）。
  • 確認 Create team-managed spaces 已加回原本的 group；TEAM 的 Releases 可以保持開啟。
