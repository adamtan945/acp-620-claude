Version、release page、timeline、Plans

  1. Version 三個狀態Unreleased、Released、Archived；Release、Archive 可逆，Merge、Delete 不可逆。
  2. Archived versionissue 還在 board、JQL 查得到，但不能再指派新 issue 給它。
  3. Fix vs AffectsFix version＝在哪版出貨（進報表）；Affects version＝影響哪些版（只供搜尋）。TMP 沒有 Affects versions。
  4. Timeline 只看一個 project你常錯Board filter 撈多個 project 時 timeline 用不了；跨 project 要 Plans（Premium／Enterprise）。
  5. Timeline 的 view settings 是個人的你常錯改了只影響自己；已完成的 epic 用 Show completed 決定顯示多久，不會被全部自動移除。
  6. Plans（舊名 Advanced Roadmaps）你常錯Premium 內建；跨 project 與團隊、epic 之上加層級（Jira admin 設）、容量規劃、改了要 Review changes 才寫回。

Fix vs Affects

兩個版本欄位

Fix versions

在哪版出貨
  • 填了＝加進該 version
  • Release page、Version report、Release burndown 都看它
  • Kanban sub-filter 看它
  • TMP 開 Releases 後可用

Affects versions

影響哪些版
  • 可以填好幾個舊版
  • 不會把 issue 加進 version
  • 不影響報表
  • TMP 沒有（JRACLOUD-85690 未解決）
本段必考
  • Fix＝出貨版（進報表）；Affects＝受影響版（只搜尋）。
  • TMP 沒有 Affects versions。你常錯
資料來源（5）有疑慮時點開看官方原文
  • Manage versionsFix versions shows the version that the work on the work item is released in.
  • Manage versionsEntering a version in the Fix versions field adds the work item to the release version.
  • Manage versionsEntering a version in the Affects versions field on a work item does not add the work item to the version
  • Enable releases and versionsA new Fix versions field will be added to your work types.
  • JRACLOUD-85690On team-managed (formerly next-gen) projects, the Release option was released recently which shows "Fix versions" in tickets, but we are unable to add "Affects versions".

Timeline

單一 project 的時程圖

規則內容
範圍只能一個 project；board filter 撈多個 project 時用不了
Scrum 的 child用所屬 sprint 的日期畫長條（Scrum、Kanban 都有 child 排程）
Kanban 的 child用 Start date 與 Due date
Inline hierarchy開啟時只顯示 epic 層（level 1）與 story 層（level 0）
View settings每個人各自的，不會改到別人的畫面
已完成的 epic考試版：View settings → Show completed 決定顯示多久，不會全部自動移除。現行版改成 Hide done items 開關（只作用在 parent 層）
自動排除進入 Done 超過一年的項目會自動排除；timeline 一次最多 5,000 項、parent 層最多 500 項

看不到 timeline 的可能原因

  • Board filter 撈了多個 project（官方：All work items need to come from one space）。
  • 功能沒開：CMP 在 board settings 啟用；TMP 在 Features 打開。
  • 方案：要跨 project 就是 Plans，Standard 沒有。
你練習時錯過

錯誤敘述：「View settings 是全域的，改了大家都變」「所有完成的 epic 都會自動從 timeline 移除」。正解：View settings 每人各自；完成的 epic 由 Show completed 決定顯示期間。

動手做

實作 Lab：Release、archive 一個版本，再看 timeline

約 30 分鐘WEB 的 space admin（或有 Manage versions）；Leo 的瀏覽器

第一次做 Lab？先看 Lab 環境準備：用測試站台、準備測試帳號。畫面名稱可能隨 Atlassian 更新而不同，以下以現行畫面為準。

目標：在 WEB 建兩個 version，走一次 release（處理未完成 issue）與 archive；再打開 timeline，確認 view settings 只改自己的畫面。

這個 Lab 對應的考點

Release 時要決定未完成 issue 的去向；archive 從報表與下拉隱藏；Fix version 才算加入 version，Affects version 只供搜尋；timeline 只看一個 project、view settings 是個人的。

準備

  • WEB 有一個 epic、底下有幾張 story；至少一張 issue 已 Done、一張未完成。

步驟

  1. 你應該看到：列表出現兩個 Unreleased 的 version。
  2. 你應該看到：Fix versions 欄位顯示 Lab-1.0。
  3. 你應該看到：Progress 區有進度條；Work items 清單只有那 3 張 Fix versions 的 issue，Affects versions 那張 Bug 不在裡面。
  4. 你應該看到：對話框要你決定未解決的 issue 怎麼處理（忽略或移到其他 version）並填 release date。選移到 Lab-1.1，按 Release。Lab-1.0 變 Released，那兩張的 Fix versions 變成 Lab-1.1。
  5. 你應該看到：Lab-1.0 不在可選清單裡（archive 會從報表與下拉隱藏）。
  6. 你應該看到：通常仍查得到 Lab-1.0 的那張 Done issue：archive 只是隱藏 version，issue 沒有被刪。
  7. 你應該看到：刻度改變；Hide done items 打開時，已完成的 epic 從畫面上收起來。
  8. 你應該看到：Leo 的畫面沒有被你的 view settings 影響：view settings 是每個人各自的。

試試看：改一個設定，觀察差異

T2再建一個 Lab-0.9，放一張 issue，然後 Lab-0.9 的 ••• → Merge 進 Lab-1.1。看結果
Lab-0.9 消失，它的 issue 改掛 Lab-1.1。Merge 沒有反向按鈕，所以只對 Lab 用的 version 做。
T3（想像，不實際做）把 WEB board 的 filter 改成 project in (WEB, OPS) 再開 Timeline。看結果

心像錨點：閉上眼睛想一次這個畫面

Lab-1.0 的 release 對話框：上面一行問「未解決的 issue 怎麼辦」，下面是 release date。Release 之後 archive，它就從 Fix versions 下拉消失，但 JQL 還找得到。口訣：Fix 出貨、Affects 受害。

收尾

  • 刪除 Lab-1.0、Lab-1.1（Delete 時選 remove references，issue 不會被刪）。
  • 把 Timeline 的 Hide done items 改回原本的設定。
