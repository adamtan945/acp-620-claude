Versions、release 與 timeline

Version 的狀態與動作、release page、單一 project 的 timeline，以及跨 project 的 Plans。你練習時在 timeline 與 archived version 錯過。

3 分鐘速覽

Version、release page、timeline、Plans

  1. Version 三個狀態Unreleased、Released、Archived；Release、Archive 可逆，Merge、Delete 不可逆。
  2. Archived versionissue 還在 board、JQL 查得到，但不能再指派新 issue 給它。
  3. Fix vs AffectsFix version＝在哪版出貨（進報表）；Affects version＝影響哪些版（只供搜尋）。TMP 沒有 Affects versions。
  4. Timeline 只看一個 project你常錯Board filter 撈多個 project 時 timeline 用不了；跨 project 要 Plans（Premium／Enterprise）。
  5. Timeline 的 view settings 是個人的你常錯改了只影響自己；已完成的 epic 用 Show completed 決定顯示多久，不會被全部自動移除。
  6. Plans（舊名 Advanced Roadmaps）你常錯Premium 內建；跨 project 與團隊、epic 之上加層級（Jira admin 設）、容量規劃、改了要 Review changes 才寫回。
Versions

三個狀態、六個動作

動作後果
Release問未解決的 issue 要忽略還是移到下一版；填 release date
Unrelease退回 Unreleased；被 Kanban sub-filter 藏起來的會重新出現
Archive從報表與下拉隱藏、不能再指派新 issue；issue 仍在、JQL 查得到；可 Unarchive
Merge來源版本的 issue 全部改掛目標版本；不可逆
Delete問 issue 要移到哪一版或解除關聯；issue 不會被刪
自我檢查：先在心裡回答，再點開對答案
Q1Archive 一個 version 後，它的 issue 還在 board 上嗎？還能把新 issue 指派給它嗎？看答案
Issue 還在、JQL 查得到；不能再指派新 issue 給它（實測）。
Q2Release 時還有一張未完成的 issue，最佳做法？看答案
移到下一個 version，讓 release 內容與實際交付一致。
本段必考
  • Release／Archive 可逆；Merge／Delete 不可逆。
  • Archived：不能再指派，但 issue 還在。
Fix vs Affects

兩個版本欄位

Fix versions

在哪版出貨
  • 填了＝加進該 version
  • Release page、Version report、Release burndown 都看它
  • Kanban sub-filter 看它
  • TMP 開 Releases 後可用

Affects versions

影響哪些版
  • 可以填好幾個舊版
  • 不會把 issue 加進 version
  • 不影響報表
  • TMP 沒有（JRACLOUD-85690 未解決）
本段必考
  • Fix＝出貨版（進報表）；Affects＝受影響版（只搜尋）。
  • TMP 沒有 Affects versions。你常錯
Release page

Release hub 看得到什麼

區塊重點
Progressissue 的完成、warnings
Warningsissue Done 但有 open PR、未 review commit、build 失敗；要：已連 dev tool＋View Development Tools＋warnings 已開
Development infocommit、branch、PR、build、deployment；issue key 要出現在 branch 名、commit 訊息或 PR 標題
Approvals勾 Require approvals 才會擋 release
本段必考
  • 看不到 warnings → 先查 View Development Tools。
Timeline

單一 project 的時程圖

規則內容
範圍只能一個 project；board filter 撈多個 project 時用不了
Scrum 的 child用所屬 sprint 的日期畫長條（Scrum、Kanban 都有 child 排程）
Kanban 的 child用 Start date 與 Due date
Inline hierarchy開啟時只顯示 epic 層（level 1）與 story 層（level 0）
View settings每個人各自的，不會改到別人的畫面
已完成的 epic考試版：View settings → Show completed 決定顯示多久，不會全部自動移除。現行版改成 Hide done items 開關（只作用在 parent 層）
自動排除進入 Done 超過一年的項目會自動排除；timeline 一次最多 5,000 項、parent 層最多 500 項

看不到 timeline 的可能原因

  • Board filter 撈了多個 project（官方：All work items need to come from one space）。
  • 功能沒開：CMP 在 board settings 啟用；TMP 在 Features 打開。
  • 方案：要跨 project 就是 Plans，Standard 沒有。
你練習時錯過

錯誤敘述：「View settings 是全域的，改了大家都變」「所有完成的 epic 都會自動從 timeline 移除」。正解：View settings 每人各自；完成的 epic 由 Show completed 決定顯示期間。

自我檢查：先在心裡回答，再點開對答案
Q1跨三個 project 的 board，為什麼沒有 timeline？看答案
Timeline 只吃一個 project；跨 project 要用 Plans（Premium／Enterprise）。
Q2你改了 timeline 的 view settings，同事看到的也會變嗎？看答案
不會，view settings 是每個人各自的。
本段必考
  • Timeline 只一個 project；跨 project→Plans。你常錯
  • View settings 個人；Show completed 決定完成 epic 顯示多久。你常錯
  • 週、月、季三種刻度。
Plans

Plans（舊名 Advanced Roadmaps）的特色

特色說明
方案Jira Premium／Enterprise 內建，不是 Marketplace app
範圍一個 plan 可拉多個 board、project、filter
階層Epic 之上加 Initiative 等層級，要 Jira admin 設定 issue type hierarchy
容量規劃設定團隊與 sprint 容量
情境與寫回在 plan 裡改的東西要 Review changes 並儲存，才會寫回 Jira issue
Saved views同一份 plan 存多種檢視

更大規模：企業級 portfolio、多個 Jira 站台 → Jira Align（另一個產品）。

自我檢查：先在心裡回答，再點開對答案
Q1在 Plans 裡把某個 epic 的日期往後拉，其他人馬上看得到嗎？看答案
不會。要先 Review changes 並儲存，才會寫回 Jira issue。
本段必考
  • Plans＝Premium 內建、跨 project、容量規劃、Jira admin 加層級、改了要 review 才寫回。你常錯
範圍變動

Scope 變了，報表怎麼顯示

報表範圍變動的樣子
Sprint report中途加入的標 *；改估點顯示 3 → 5
Burnup紅線往上跳
Burndown剩餘線往上跳；guideline 不變
Epic／Release burndown深藍段＝加入的 scope
Version report預測日往後移
本段必考
  • Scope 增加：* 、紅線上跳、深藍段、預測日延後。
