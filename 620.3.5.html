3 分鐘速覽

自動指派的三種手段

  1. Project default assignee 只有兩種Unassigned 或 Project lead；要指定別人得先換 project lead，或用 automation。
  2. Component default assignee 四種Component lead、Project lead、Unassigned、Project default；覆蓋 project default。
  3. 多個 component 時（官方兩說）你常錯KB：先比 default assignee 的類型，Component lead ＞ Project lead ＞ Unassigned ＞ Project default，同級再依 component 名稱字母序。現行 Configure Jira components 頁：default assignee 不同人時，直接取字母序第一個 component 的 default assignee，沒提類型。兩說都同意：比的是 component 名稱，不是 lead 名字。
  4. 被指派者要有 Assignable User沒有就跳過，往下一個候選。
  5. 輪流、平均、依欄位分流 → AutomationAssign issue action：round robin、balanced workload、random、copy from field。
  6. 想選 Unassigned 選不到全站 Allow unassigned issues 是關的。

  • How to Manage Components and Default Assignees in Jira Software ProjectsComponents are assigned in the order: Component Lead >> Project Lead >> Unassigned >> Project default.
  • Configure Jira componentsIf someone creates a work item with more than one component, and the default assignees for those components are different people, then Jira assigns the work item to the default assignee of the component that is first alphabetically.

決策鏈

選了 Automatic 之後，Jira 怎麼決定

issue 掛的 components結果
Alpha（Component lead 小傑）＋ Backend（Component lead 阿宏）同級 → 字母序 Alpha 先 → 小傑
Docs（Unassigned）＋ Zeta（Project default）Unassigned 優先於 Project default → 未指派
Alpha，但小傑沒有 Assignable User跳過 → 下一個候選（KB）
官方兩說：類型優先，還是只看字母序？

上面的決策鏈依官方 KB（How to Manage Components and Default Assignees）：先比類型，同級才比 component 名稱。現行的 Configure Jira components 頁只寫一句：多個 component 的 default assignee 不同人時，指派給字母序第一個 component 的 default assignee，沒有提類型優先序，也沒提 Assignable User 被跳過。

兩說在多數情境結果相同：上表前兩列兩種算法都一樣（Alpha、Docs 本來就排在前面）。會分歧的是「字母序在前的 component，類型反而比較低」的情境，例如 Alpha（Project default）＋ Beta（Project lead）：KB 選 Beta，現行頁選 Alpha。考試時代的題目多依 KB 出題；實際站台的結果以畫面為準。

易錯觀念

考題愛用的錯誤說法

不用手動指派的方法只有 project default、component 和 automation 三種。
還有 workflow：CMP 的 transition 可以加 post function（Assign to current user、Assign to reporter、Assign to lead developer，或 Update issue field 設 Assignee）。Bulk operations 還是要人去做；permissions 只決定誰能被指派，不會自動指派。
自動指派四招：專案預設、元件、流程、自動化。
官方來源
多個 component 的預設指派「衝突」時，Jira 為了避免歧義一律 Unassigned。
錯（有題庫的解析這樣寫，是錯的）。官方 KB 原句：If multiple components were added and one of those components has a default assignee set to Component lead, then Jira assigns the issue to that person。KB 範例：Project lead＋Component lead＋Unassigned 三個 component → 指派給那位 Component lead。所以 Hardware（Component lead）＋Software（Project default）＋Infrastructure（Unassigned）→ Hardware 的 lead。
有 Component lead 就是他（要有 Assignable User）；「衝突就 Unassigned」沒有官方依據。

動手做

實作 Lab：四個 component 排出自動指派的順序

約 30 分鐘WEB 的 space admin；Jira admin（改 Assignable User 與 automation）

第一次做 Lab？先看 Lab 環境準備：用測試站台、準備測試帳號。畫面名稱可能隨 Atlassian 更新而不同，以下以現行畫面為準。

目標：在 WEB 建四個 default assignee 類型不同的 component，建幾張掛多個 component 的 issue，對照官方 KB（先比類型、再比字母序）與現行 Configure Jira components 頁（直接取字母序第一個 component）的說法，看你的站台實際怎麼指派。

這個 Lab 對應的考點

Project default 只能 Unassigned 或 Project lead；多個 component 依 KB 先比類型（Component lead＞Project lead＞Unassigned＞Project default），同類型再比 component 名稱字母序（現行頁只寫取字母序第一個 component，兩說並存）；沒有 Assignable User 會被跳過（KB）；輪流、平均分配要用 automation。

準備

  • 全站的 Allow unassigned work items 是開著的（⚙ Settings → System → General configuration，只看）。
  • WEB 的 project lead（space owner）是你。

步驟

  1. 你應該看到：只有 Unassigned 與 Space owner（project lead）兩個選項；要指定別人得換 owner 或用 automation。
  2. 你應該看到：列表上四個 component 的 default assignee 各不相同。
  3. 你應該看到：依 KB 預期指派給 Leo：兩個都是 Component lead，同類型再比 component 名稱，Alpha 在 Beta 前面（現行頁取字母序第一個，也是 Alpha）。實際結果以畫面為準。
  4. 你應該看到：依 KB 預期保持未指派：Unassigned 的優先序高於 Project default，Project default 是四級裡最低的（現行頁取字母序第一的 Gamma，結果相同）。實際結果以畫面為準。
  5. 你應該看到：依 KB 預期指派給你：Component lead 的優先序最高，不看字母序（現行頁取字母序第一的 Beta，結果相同）。實際結果以畫面為準。
  6. 你應該看到：依 KB 預期指派給 Beta 的 lead（你）：Leo 沒有 Assignable User，被跳過，換下一順位。現行 Configure Jira components 頁沒有寫這種情形，實際結果以畫面為準。
  7. 你應該看到：3 張 issue 依清單順序輪流指派給 Leo 與你：輪流、平均分配是 automation 的事，component 與 project default 做不到。

試試看：改一個設定，觀察差異

T1把 Zeta 的 default assignee 改成 Space owner（Project lead），再建一張 Gamma＋Zeta 的 issue。看結果
這是兩份官方文件會分歧的情境。依 KB 預期指派給你：Project lead 高於 Unassigned，不看字母序。依現行 Configure Jira components 頁則取字母序第一的 Gamma，保持未指派。實際結果以畫面為準，記下你的站台是哪一種。
T2（想像，不實際做）把 Allow unassigned work items 關掉，再看 WEB 的 Default assignee 與 Gamma 的選項。看結果
選不到 Unassigned；沒有指定 assignee 的 issue 會指派給 space owner。這是全站設定，所以只想像。
T3打開 WEB 用的 workflow（只看），點某個 transition 的 post functions，找 Assign to Lead Developer。看結果
官方說明：指派給 component lead，沒有就給 space lead。Workflow 是第四種自動指派手段。
T4把 automation rule 的 Round-robin 改成 Balanced workload，再建 3 張。看結果
改成依各人手上 issue 數平均分配（範圍由 JQL 決定），不再單純輪流。
