620.5.2 · Determine an appropriate gadget and dashboard configuration

Dashboard 與 gadget 的設計

Dashboard 是 Jira 登入後的首頁，也是把 filter（620.5.1）變成「別人看得懂的畫面」的地方。考題兩種：操作面（誰能建、怎麼分享、丟掉後怎麼救）與選型面（主管要看 X，該放哪個 gadget、它要吃什麼資料來源）。

術語：考試用 project／issue；官方 gadget 名稱現已改為 work item（例如「Work item Statistics」），本頁以考試常見的舊名為主、括號附新名。

核心模型

Gadget 不會自己有資料：每個都要接一個來源

幾乎所有 gadget 的設定第一格都是「Filter or project」。所以 dashboard 的設計順序是：先把需求寫成 saved filter → 再挑 gadget 呈現 → 最後決定分享給誰。看的人要同時看得到 dashboard 與底層 filter，畫面才會有內容。

圖 1　挑 gadget 前先問「它吃 filter、project 還是 board」；再問「看的人有沒有那個來源的權限」。
考題長相
「同事打開我分享的 dashboard 全是空的」→ dashboard 分享了，但底層 saved filter 沒分享給他。分享 dashboard 與分享 filter 是兩件事。
操作面

建立、分享、管理（官方三頁整理）

動作路徑／規則
建立側欄 Dashboards → Create dashboard，填名稱與描述。任何 Jira 使用者都能建。
版面Edit → Change layout：單欄、兩欄（等寬或左右不等）、三欄。
加 gadgetEdit → Add gadget（要看全部先按 Load all gadgets）→ 設定來源 → 拖曳排列。
分享••• → Rename or share：分別指定 Viewers 與 Editors；對象可以是 user、group、project（現行文件稱 space）、project role，或開放給任何登入者／public。分享需要全域權限 Share dashboards and filters（見 620.3.1）。
加星Star 後出現在側欄「Starred and recent」；只有加星的會顯示在側欄。
複製••• → Copy dashboard：以既有 dashboard 為底建新的。
自動刷新••• → Configure automatic refresh，以分鐘為單位；任何使用者都能對自己的 dashboard 設定（官方 Configure custom dashboards）。
Wallboard單一 dashboard 全螢幕，或 wallboard slideshow 多個輪播、可設秒數。
刪除••• → Move to trash。只有 Jira admin 能從 trash 還原；60 天後永久刪除。
System dashboard登入預設看到的那一個，由 Jira admin 設定；改了會影響所有用它的人（gadget 仍受權限影響，例如 Administration gadget 只有 admin 看得到）。
找別人的Dashboards → View all dashboards，可搜尋分享給你的 dashboard。

情境練習

先自己判斷，再點開解答

主管要一張「每個工程師手上各狀態有幾張」的表。
解答
Two Dimensional Filter Statistics：X＝Status、Y＝Assignee，來源是團隊 filter。一維的 Issue Statistics 只能看一個欄位。
想知道 backlog 這三個月是越積越多還是在消化。
解答
Created vs Resolved，期間設 90 天。
Project admin 建好 dashboard，分享時找不到 project role 選項或分享失敗。
解答
缺全域權限 Share dashboards and filters，找 Jira admin。
同事看得到 dashboard，但 Pie Chart 一片空白。
解答
底層 saved filter 沒分享給他，或他沒有該 project 的 Browse 權限。gadget 依看的人的權限顯示。
不小心把 dashboard 丟進 trash，自己救得回來嗎？
解答
不行，只有 Jira admin 能還原；60 天後永久刪除。
想在牆上電視輪播三個團隊的 dashboard。
解答
Wallboard slideshow，設定輪播秒數；每張 wallboard 少放 gadget。
Scrum master 要在 dashboard 上看目前 sprint 還剩幾天和燃盡狀況。
解答
Days Remaining in Sprint ＋ Sprint Burndown（或 Sprint Health），來源是 board 不是 filter。
誰能改 System dashboard？改了會影響誰？
解答
Jira admin；影響所有沒有自訂首頁的使用者，但 gadget 仍依各人權限顯示。
想找出「票數多且放很久」的需求。
解答
Bubble Chart：可用四個維度（例如 votes、age、priority、watchers）一次看。
老闆只想看「指派給我的」，不想設 filter。
解答
Assigned to Me 不需要來源，跨所有 project 列出未完成的指派。
常見陷阱

考題喜歡設的誤解

誤解事實
「只有 admin 能建 dashboard」任何 Jira 使用者都能建；分享才需要 Share dashboards and filters。
「分享 dashboard 就等於分享資料」gadget 的來源 filter 要另外分享，且看的人要有 project 的 Browse 權限。
「Pie Chart 可以交叉兩個欄位」一維；交叉用 Two Dimensional Filter Statistics。
「Sprint gadget 用 filter 當來源」用 board。
「刪掉的 dashboard 自己可以還原」只有 Jira admin，60 天內。
「Wallboard 就是普通 dashboard 放大」是全螢幕模式，另有 slideshow 輪播；設計上要少而大。
實作（30 分鐘）

建一個團隊 dashboard

  1. 用 620.5.1 存的 filter 建 dashboard，layout 選兩欄（左寬）。
  2. 左欄放 Two Dimensional（Assignee × Status）與 Created vs Resolved；右欄放 Assigned to Me、Days Remaining in Sprint、Filter Results（前 10 筆）。
  3. 分享給 project role Developers；用第二帳號開——先不分享 filter，看 gadget 空白；再分享 filter，看資料出現。
  4. 設 automatic refresh 15 分鐘；開 wallboard 看版面。
  5. 丟進 trash，用非 admin 帳號確認救不回；請 Jira admin 還原。
  6. 用同一份資料比對兩個 gadget：沿用 620.5.1 那三張 acp620-jql-lab 卡，filter 寫 project = KEY AND labels = acp620-jql-lab（不要加 currentUser()）。加入 Filter Results（看到三張）與 Two Dimensional Filter Statistics（Assignee × Status，未指派自成一類）。只把其中一張改成 In Progress 再重新整理 → 交叉表格數移動、總數仍是 3。
  7. 另存一份含 assignee = currentUser() 的 filter 換掉其中一個 gadget → 該 gadget 只剩自己的工作，另一個仍是完整集合。這就是「主管只看到自己切片」的成因。
  8. 用一般測試帳號分別測 dashboard 分享與 filter 分享，體會容器分享 ≠ 資料來源分享；不要用「分享給 Anyone」當測試捷徑。
