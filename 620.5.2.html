620.5.2 · Determine an appropriate gadget and dashboard configuration

Dashboard 與 gadget 的設計

Dashboard 是 Jira 登入後的首頁，也是把 filter（620.5.1）變成「別人看得懂的畫面」的地方。考題兩種：操作面（誰能建、怎麼分享、丟掉後怎麼救）與選型面（主管要看 X，該放哪個 gadget、它要吃什麼資料來源）。

術語：考試用 project／issue；官方 gadget 名稱現已改為 work item（例如「Work item Statistics」），本頁以考試常見的舊名為主、括號附新名。

核心模型

Gadget 不會自己有資料：每個都要接一個來源

幾乎所有 gadget 的設定第一格都是「Filter or project」。所以 dashboard 的設計順序是：先把需求寫成 saved filter → 再挑 gadget 呈現 → 最後決定分享給誰。看的人要同時看得到 dashboard 與底層 filter，畫面才會有內容。

圖 1　挑 gadget 前先問「它吃 filter、project 還是 board」；再問「看的人有沒有那個來源的權限」。
考題長相
「同事打開我分享的 dashboard 全是空的」→ dashboard 分享了，但底層 saved filter 沒分享給他。分享 dashboard 與分享 filter 是兩件事。

情境練習

先自己判斷，再點開解答

主管要一張「每個工程師手上各狀態有幾張」的表。
解答
用 Two Dimensional Filter Statistics，X 軸設 Status、Y 軸設 Assignee，來源接團隊的 saved filter。判斷關鍵在需求裡的「每個工程師」加上「各狀態」——兩個維度交叉，就必須用二維的 gadget。一維的 Issue Statistics 或 Pie Chart 一次只能依一個欄位分組，做不出這張表。
想知道 backlog 這三個月是越積越多還是在消化。
解答
用 Created vs Resolved，期間設成 90 天。它會同時畫出「這段期間新建了多少」與「解決了多少」兩條線，兩者的落差就直接回答了「backlog 在漲還是在消」——建立線持續高於解決線就是越積越多。這是回答「趨勢」類問題的標準 gadget，而 Pie Chart 那種只能呈現「此刻的分佈」，看不出時間變化。
Project admin 建好 dashboard，分享時找不到 project role 選項或分享失敗。
解答
因為缺少全域權限 Share dashboards and filters。建立 dashboard 本身任何 Jira 使用者都可以，不需要特別權限；但要把它分享出去就必須有這一項。它是全域權限，只有 Jira admin 能授予，而且只能授予群組。順帶一提，同一個權限也管 filter 的分享——所以缺了它，dashboard 與底層 filter 兩邊都分享不出去。
同事看得到 dashboard，但 Pie Chart 一片空白。
解答
因為底層的 saved filter 沒有分享給他，或是他沒有該 project 的 Browse Projects 權限。這題要建立的核心觀念是：分享 dashboard 只是分享了「容器」，資料來源要另外分享。而且 gadget 的內容永遠是依照觀看者自己的權限即時查詢出來的——這其實是好事，代表不會因為分享 dashboard 而洩漏他無權查看的 issue，但也意味著同一張 dashboard 每個人看到的數字可能不同。
不小心把 dashboard 丟進 trash，自己救得回來嗎？
解答
自己救不回來。dashboard 被 Move to trash 之後，只有 Jira admin 能執行還原，一般使用者（包含原本的擁有者）都不行，而且60 天後就會永久刪除。所以誤刪時要立刻找 Jira admin，不要拖。這個規則跟 project 的 trash 很像，可以一起記：丟進去比較容易，救出來一律要站台管理員。
想在牆上電視輪播三個團隊的 dashboard。
解答
用 wallboard slideshow：它可以把多個 dashboard 排成輪播，並設定每一張停留幾秒。一般的 wallboard 只是把單一 dashboard 全螢幕顯示，要輪播就得用 slideshow 模式。設計上有一個實務建議：牆上的螢幕是給人幾公尺外掃一眼的，每張 wallboard 放的 gadget 要少而大（建議不超過 6 個），密密麻麻的表格在遠處完全讀不到。
Scrum master 要在 dashboard 上看目前 sprint 還剩幾天和燃盡狀況。
解答
放 Days Remaining in Sprint 加上 Sprint Burndown（想一次看進度、工作分配與 scope 變動的話，改用 Sprint Health）。這題最重要的考點是資料來源：這三個 sprint 相關的 gadget 都是接 board，不是接 filter——因為 sprint 這個概念本身就屬於 board。大部分其他 gadget 接的是 filter 或 project，這一組是例外，很值得記起來。
誰能改 System dashboard？改了會影響誰？
解答
只有 Jira admin 能修改 System dashboard。它是使用者登入後預設看到的那一張，所以改動會影響站台上所有沒有自訂首頁的人，要相當謹慎。不過有一點可以放心：gadget 的內容仍然依照每個人自己的權限顯示，不會因為放在公用首頁就洩漏資料（例如 Administration gadget 只有管理員看得到內容）。
想找出「票數多且放很久」的需求。
解答
用 Bubble Chart。它的特色是一次可以呈現四個維度——X 軸、Y 軸、泡泡大小與顏色，例如把票數放 X、停留天數放 Y、優先度當顏色、關注人數當大小。這樣「票多又放很久」的需求就會浮現在圖的右上角，一眼認得出來。這是其他 gadget 做不到的：Pie Chart 只有一維，Two Dimensional 也只有兩維而且是表格形式。
老闆只想看「指派給我的」，不想設 filter。
解答
用 Assigned to Me。它是少數不需要設定任何來源的 gadget，直接列出「目前指派給觀看者本人、且尚未完成」的 issue，而且跨所有 project。同一類的還有 Issues in Progress、Watched Issues、Voted Issues。這類個人型 gadget 的另一個好處是：同一張 dashboard 分享給十個人，每個人看到的都是自己的工作，不必為每個人各做一份 filter。
常見陷阱

考題喜歡設的誤解

誤解事實
「只有 admin 能建 dashboard」不是。任何 Jira 使用者都能建立 dashboard，不需要任何特殊權限；只有要把它分享出去時，才需要全域權限 Share dashboards and filters。
「分享 dashboard 就等於分享資料」不等於。分享 dashboard 只是分享了「容器」，gadget 接的那份 saved filter 必須另外分享，而且觀看者還要有該 project 的 Browse Projects 權限，畫面才會有資料。
「Pie Chart 可以交叉兩個欄位」不行。Pie Chart 與 Issue Statistics 都是一維的，一次只能依一個欄位分組；要兩個欄位交叉請用 Two Dimensional Filter Statistics。
「Sprint gadget 用 filter 當來源」不是。Sprint Health、Sprint Burndown、Days Remaining in Sprint 這一組接的來源是 board，不是 filter，因為 sprint 本身就屬於 board。
「刪掉的 dashboard 自己可以還原」不行。只有 Jira admin 能從 trash 還原 dashboard，而且要在 60 天內，逾期就永久刪除。
「Wallboard 就是普通 dashboard 放大」不只如此。wallboard 是專門的全螢幕模式，還可以用 slideshow 輪播多張 dashboard 並設定秒數；因為是給人遠距離掃視的，設計上要少而大。
實作（30 分鐘）

建一個團隊 dashboard

  1. 用 620.5.1 存的 filter 建 dashboard，layout 選兩欄（左寬）。
  2. 左欄放 Two Dimensional（Assignee × Status）與 Created vs Resolved；右欄放 Assigned to Me、Days Remaining in Sprint、Filter Results（前 10 筆）。
  3. 分享給 project role Developers；用第二帳號開——先不分享 filter，看 gadget 空白；再分享 filter，看資料出現。
  4. 設 automatic refresh 15 分鐘；開 wallboard 看版面。
  5. 丟進 trash，用非 admin 帳號確認救不回；請 Jira admin 還原。
  6. 用同一份資料比對兩個 gadget：沿用 620.5.1 那三張 acp620-jql-lab 卡，filter 寫 project = KEY AND labels = acp620-jql-lab（不要加 currentUser()）。加入 Filter Results（看到三張）與 Two Dimensional Filter Statistics（Assignee × Status，未指派自成一類）。只把其中一張改成 In Progress 再重新整理 → 交叉表格數移動、總數仍是 3。
  7. 另存一份含 assignee = currentUser() 的 filter 換掉其中一個 gadget → 該 gadget 只剩自己的工作，另一個仍是完整集合。這就是「主管只看到自己切片」的成因。
  8. 用一般測試帳號分別測 dashboard 分享與 filter 分享，體會容器分享 ≠ 資料來源分享；不要用「分享給 Anyone」當測試捷徑。
