3 分鐘速覽

要負責人用 component、要自由用 label、要管控用 custom field

  1. Components 獨有的兩件事你常錯決定 assignee（component lead／default assignee）、現成的 Components 頁列出各 component 的 issue。
  2. Components 只有 CMP 有Project admin 自己建；刪除時要把 issue 改連或解除。
  3. Labels 全站共用、沒有管控任何有 Edit Issues 的人都能新增；拼字差一個字就是另一個 label。
  4. Custom field 由 Jira admin 建，型別不能改要兩層選單用 cascading select；要算數字用 formula。
  5. 多選與預設值不是 Components 的專利Custom field 也能多選（multi-select）、也能設預設值（context）。
  6. Category：一個 category 可給很多 project你常錯一個 project 只能有一個 category；category 不能做階層。

易錯觀念

考題愛用的錯誤說法

「單選＋可設預設值＋不同 project 顯示不同值」選 Version picker、Project picker（值本來就跟 project 走）。
選 Radio button 和 User picker (single user)。三個需求都是 field context 的功能：context 可以設預設值、給不同 project 另一套選項（radio）、限制 user picker 能選哪些人。Version／Project picker 的值不是 context 設定出來的，也不能設預設值；Components、Labels 可多選；Text field 沒有「選值」。
看到「不同 project 不同值＋預設值」→ 想 context：有選項清單的（radio／select）或 user picker。

動手做

實作 Lab：Component、label、custom field 各做一次

約 30 分鐘Jira admin（custom field、category）；WEB 的 space admin（component）

第一次做 Lab？先看 Lab 環境準備：用測試站台、準備測試帳號。畫面名稱可能隨 Atlassian 更新而不同，以下以現行畫面為準。

目標：在 WEB 建一個有 lead 的 component、打兩個拼法不同的 label、建一個 cascading custom field，再建一個 category 套到兩個 project，親手比較三種分類工具。

這個 Lab 對應的考點

Components 獨有的是決定 assignee 與 Components 頁；labels 沒有管控；custom field 由 Jira admin 建、型別不能改；一個 category 可給多個 project，一個 project 只有一個 category。

步驟

  1. 你應該看到：Components 列表出現 Payments，lead 是 Leo。
  2. 你應該看到：建好後 Assignee 是 Leo：component 的 default assignee 覆蓋了 project 的 default assignee。
  3. 你應該看到：直接列出所有掛 Payments 的 issue：這是 components 獨有的清單頁。
  4. 你應該看到：只找到第一張：label 沒有選項管控，拼錯一個字就是另一個 label。
  5. 你應該看到：建立面板提醒型別建立後不能改；欄位清單出現 Lab Product。
  6. 你應該看到：Context 頁列出適用的 work type 與 space、預設值：預設值與選項清單都是 context 的功能，不是 Components 的專利。
  7. 你應該看到：兩個 project 都屬於 Lab Category；Details 的 Category 是單選，一個 project 只能有一個 category。
  8. 你應該看到：WEB 與 OPS 的 issue 都出現：category 可以拿來搜尋與篩選，但不能做成 project 階層。

試試看：改一個設定，觀察差異

T1打開 TEAM（TMP）的 Space settings，找 Components。看結果
找不到：Jira components 只有 company-managed space 有。
T2刪除 Payments component（••• → Delete）。看結果
對話框問掛著 Payments 的 issue 要改連到別的 component 還是直接解除；issue 本身不會被刪。
T3（想像，不實際做）想把 Lab Product 從 cascading 改成 multi-select。看結果
做不到：欄位型別建立後就不能改，只能建新欄位再搬資料。
心像錨點：閉上眼睛想一次這個畫面

Create component 對話框最下面的 Default assignee 下拉，選了 Component lead；建單時 Assignee 留 Automatic，自動變成 Leo。口訣：要負責人用 C、要自由用 L、要管控用 CF。

收尾

  • 刪除 Payments component（若 T2 沒刪）；移除 lab-login、lab-logn 兩個 label。
  • WEB、OPS 的 Category 改回原本的值（或清空），再刪除 Lab Category。
  • Lab Product 欄位可以留著不用；要刪也只在可丟棄的站台刪（刪除的欄位會先進 60 天待刪區）。
