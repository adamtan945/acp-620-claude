620.3.4 · Recommend a method to sub-categorize issues (components, labels, custom fields)

Components、labels、custom fields：
怎麼幫 issue 分類

三種工具都能「把 issue 分群」，差別在誰能建、範圍多大、能不能管控、能不能自動指派。這是推薦題：題目給需求，你要選對工具，並知道哪些需要 Jira admin。

術語：考試用 project／issue；現行官方文件為 space／work item。本教材沿用考試用語。

Components

Jira components：project 內的模組與負責人

Jira components are only available in company-managed spaces, and are scoped to the space they're created in.— Atlassian, What are Jira components?

建立與欄位
  • Project settings → Components → Create component（或側欄 Components）
  • 名稱、描述（hover 時顯示）、Component lead、Default assignee
  • 建了第一個 component 後，issue 上才出現 Components 欄位
  • 刪除時：把已連結的 issue 改連到別的 component，或解除連結
  • Compass components 是另一套（跨系統的軟體架構目錄），project 可切換使用哪一套；它不是考綱裡 project-scoped 的 Jira components。做自動指派 lab 前先確認自己在用哪一套
Default assignee 的四個選項
  • Project default：跟 project 的預設一樣
  • Project lead
  • Component lead：官方建議用 role 型的選項，人員異動不用改
  • Unassigned：站台允許未指派時才有效

Component 的 default assignee 覆蓋 project 的 default assignee；多個 component 時先比 default assignee 的類型優先序（Component lead ＞ Project lead ＞ Unassigned ＞ Project default），同一級再依 component 名稱字母序取第一個；候選人要有 Assignable User，沒有就往下一個（官方 KB，2026-09-08）。細節與互動在 620.3.5。

Labels

Labels：最自由，也最難管

特性內容
誰能加任何有 Edit Issues 的人，打字就新增；官方 Label 型別欄位描述：「select from an existing label or create new ones」
範圍全站；同名 label 在所有 project 是同一個，適合跨 project 主題（例如 tech-debt）
格式不能有空白；大小寫與拼字不同就是不同 label（UX、ux、u-x）
報表Labels gadget；JQL labels = tech-debt；Pie chart by Labels
Jira admin 也可以建 Label 型別的 custom field與內建 Labels 欄位分開，用來做第二套標籤
清理 labels 之前

先查每個值的實際使用量，以及有沒有 board filter／automation 正在用它。若要批次把 payments 統一成 payment，務必保留每張 issue 其他既有的 labels——用「整欄覆寫」會意外刪掉無關的標記。分類一改，JQL 結果與報表分組都會跟著變。

考題長相
「產品線 → 子產品 兩層選單」→ cascading select。「Approver 欄位只能選 QA role 的人」→ user picker ＋ context 限制。「顯示預算差額」→ formula。「欄位建成 text 後想改成 select」→ 不能改型別，得建新欄位搬資料。

四個容易答錯的現行差異

Priority schemes：現行 Cloud 已經有

別把「Jira Cloud 沒有 Priority scheme」當成現行規則。官方已提供 priority schemes：為 project 指定一組可用的 priority 與預設值，多個 project 也能共用；沒有指定 scheme 的 project 使用預設 scheme（含站台全部 priorities）。

它處理的是 Priority 系統欄位的選項，不等於新增一個 custom field。入口：⚙ → Work items → Priorities／Priority schemes（需 Jira app admin）。
Manage priorities（2026-09-08 查核）

Disable 選項 ≠ 刪除選項

Disable 只是讓這個選項不再供新的選取；Delete 才是移除定義。兩者不是同一個清理操作。

退役舊代碼時，先查既有 issue 的引用與報表，再決定停用或遷移——停用不代表已經批次清掉歷史值，舊 issue 上那個值還在，JQL 也還找得到。

Context 的 default value ≠ Component 的 default assignee

兩個都叫「預設」，但：context 的 default value 是預填欄位的值；component 的 default assignee 決定 Automatic 指派給誰。custom field 沒有 component lead 那套內建規則，但仍可當 automation 的指派條件。

另外別因為 Components 可多選，就以為所有 custom field 都是多選：Multi-select／Checkboxes 才能保留多值，單選欄位不行。

User picker 的 Edit User Filtering

「單選一人＋各 project 不同名單」不必用四個欄位：User picker（single user）在各 context 設 default，再用 Edit User Filtering 限定 group／project role——採購 project 只列採購審核群組，工程 project 只列工程審核群組。

這是候選名單，不是授權；被選的人沒有因此取得任何 project 權限。若預設人員停用或離開了允許的群組，原本的 default 可能導致建立 issue 失敗。

Team-managed 欄位的版本界線
  • Dependent dropdown（第二層選項隨第一層而變，例如先選產品類別再選型號；和兩個互不相關的 dropdown 不同）：舊版 TMP 介面有這個型別，但 2026-09-08 核對現行欄位清單未列出。不能只憑舊截圖保證所有站台現在都能新增，也不能因文件沒列就斷言完全不支援——請在目標 project 的 Create a field 實際檢查。
  • Time stamp 含日期與時間，別和登錄工時的 Time tracking 混淆。舊畫面的「Set to current time by default」是預填值選項，不是每次讀取都會更新的即時時鐘。
情境練習

先自己判斷，再點開解答

CMP 團隊想把 issue 分成前端、後端、資料庫，各模組有負責人自動接單。
解答
Components，各設 lead 並把 default assignee 設為 Component lead。
四個 project 都想標記「technical debt」，方便一個跨 project filter 找出來。
解答
Label（全站共用）；或請 Jira admin 建一個全站的 select 欄位如果要管控。
PM 發現 label 有 ux、UX、u-x 三種，報表分散。
解答
label 無法管控；改成 Jira admin 建的 select list 欄位，選項固定。
TMP 團隊想用 component 分模組。
解答
TMP 沒有 component；用 label 或自建欄位（TMP 的欄位只在該 project）。
要一個「產品線 → 子產品」的兩層選單。
解答
Cascading select list（Jira admin 建）。
「Approver」欄位只能選 QA role 的人。
解答
User picker ＋ context 限制為 project role QA。
Jira admin 把「Severity」建成 short text，現在想改成下拉選單。
解答
型別不能改；建新的 select 欄位，bulk edit 搬資料，再隱藏舊欄位。
issue 同時掛 component「Backend」（lead 阿宏）與「Alpha」（lead 小傑），Assignee 留 Automatic，誰被指派？
解答
字母順序第一個「Alpha」的 default assignee → 小傑（若他有 Assignable User）。
Project admin 想在 issue 上顯示「預算 − 實際支出」。
解答
請 Jira admin 建 Formula 欄位；project admin 建不了 custom field。
刪掉 component「Legacy」時 Jira 問了什麼？
解答
已連結的 issue 要改連到別的 component，還是解除連結。
常見陷阱

考題喜歡設的誤解

誤解事實
「TMP 也有 components」只有 CMP 有
「Component 可以跨 project 共用」只在建它的 project
「Project admin 可以建 custom field」Jira admin 才能（TMP 的 project admin 可建僅限該 project 的欄位）
「Custom field 建錯型別可以改」不能改
「Label 可以設負責人」label 沒有任何屬性
「多個 component 時用 project default assignee」或「只看字母序」先看 default assignee 類型優先序（Component lead ＞ Project lead ＞ Unassigned ＞ Project default），同級才依 component 名稱字母序
「Jira Cloud 沒有 Priority scheme」現行已提供；可為 project 指定可用 priority 與預設值，多 project 可共用
「Disable 選項＝把歷史值清掉」只是不再供新選取；舊 issue 的值還在、JQL 仍找得到
「User picker 選到的人就有權限」那只是候選名單；Edit User Filtering 限的是「能選誰」，不授權
「TMP 一定（或一定不）有 Dependent dropdown」舊介面有、現行清單未列；兩種絕對斷言都不安全，實機檢查 Create a field
實作（25 分鐘）

三種分類各做一次

  1. CMP：建 components Backend（lead A，default assignee = Component lead）與 Alpha（lead B）；建 issue 同時掛兩個、Assignee 留 Automatic → 觀察 B 被指派。
  2. 刪除 Alpha，看 Jira 要求你處理已連結的 issue。
  3. 在兩個 project 各加 label tech-debt，用 JQL labels = tech-debt 跨 project 找到；再故意加 Tech-Debt 觀察變成另一個 label。
  4. Jira admin：建 cascading select「產品線」、user picker「Approver」（context 限 QA role）、formula「預算差額」；把它們加到 screen；試著改型別 → 不行。
  5. 到 TMP 找 Components → 沒有；在 TMP 建一個 select 欄位，到別的 project 找它 → 找不到。
  6. 拼字防護對照（A 版 lab）：在單選欄位試著輸入拼錯的 Priorty → 單選不應把任意拼字變成正式選項；同一張 issue 的 Labels 卻能直接新增這個新值。這就是「受控 vs 自由」的差別。
  7. 做一份欄位決策表：需求／型別／是否多值／誰維護／哪些 project 使用。用它解釋為什麼某個需求不該用 Components。
  8. 清理測試欄位前先確認 context 與 usage，只移除測試用的 labels、component 與關聯，不要動到共用的正式欄位。
