3 分鐘速覽

權限分四層，每層主人不同

  1. 全域權限給 group（或個別使用者），不能給 project roleJira admin 設定；8 個，最常考：Make bulk changes、Share dashboards and filters、Browse users and groups。
  2. 幾乎所有 issue 權限都要 Browse Projects你常錯例外：Create Issues 不需要 Browse——建得出來，但打不開剛建的那張。
  3. 排序要 Schedule Issues＋Edit Issues你常錯Manage Sprints 管 sprint 本身；拖 backlog 排序不靠它。
  4. Bulk change＝全域 Make bulk changes＋動作對應的 project 權限你常錯批次改欄位配 Edit Issues、搬移配 Move Issues、轉狀態配 Transition Issues。
  5. 具體的權限優先Scheme 另外設了 Assign Issues，改 Assignee 就只看 Assign Issues，不看 Edit Issues。
  6. Project admin 的邊界能填 role 成員、管 versions、components、details；不能改 permission scheme、建 role、建 custom field。

要不要 Browse Projects？一句話判斷

動作的對象是「已經存在的 issue」→ 要 Browse；只有「生出一張新的」不用。

  • 不用 Browse：Create Issues（官方明寫：沒有 Browse 也建得出來，只是建完看不到）
  • 要 Browse：Edit、Transition、Assign、Schedule（排序）、Comment、Create／Delete Attachments、Link、Work On（記工時）、Delete…所有對既有 issue 動手的權限
  • 題目問「最少幾個 role」：先列出題目要的動作，只要有任何一個動作碰到既有 issue，就得多算一個有 Browse 的 role

例：只要建立 issue → 只給有 Create 的 role；要加、刪附件 → Browse＋Create Attachments＋Delete Own Attachments。

你問過的：Schedule Issues 能做哪些事？

Schedule Issues 管「時間與順序」：改 Due date、在 board 和 backlog 排序（rank）。官方：change a work item's Due date and change work item ranking on a board and backlog。

  • 排序還要同時有 Edit Issues，而且 board filter 要有 ORDER BY Rank。
  • 開始、完成 sprint 是 Manage Sprints，跟排序是兩回事。
  • Due date 看得到但灰色 → 缺 Schedule Issues。
你練習時錯過

Selma 看得到 issue 卻不能排序 backlog → Schedule Issues＋Edit Issues，不是 Manage Sprints。TMP 的 Member 能做所有事、只有不能 rank → 缺的是 Jira Software 產品授權（舊的授權分工）。

Administer Projects

Project admin 能做、不能做

Project admin 能做

Administer Projects
  • 把人或 group 放進任何 role
  • Versions（另需 Manage Versions）
  • Components、lead、default assignee
  • Details：名稱、avatar、URL、description、lead
  • Issue layout（screen 沒被共用時）

要 Jira admin

Administer Jira
  • 改 permission scheme、換 scheme
  • 建新的 project role
  • 建 custom field、issue type、screen
  • 改 CMP 的 Key、指派 category
  • 全域權限、issue linking 開關

考題愛用的錯誤說法

建立與重新排列 sprint 需要「Sprint admin」或 board admin 權限。
沒有 Sprint admin 這種權限。要 Manage Sprints（project 權限）＋產品存取；board admin 管的是 board 設定。
排 sprint 找 Manage，排 issue 找 Schedule。

把 issue 從 backlog 移進 active sprint 要 Manage Sprints。
移 issue 是改 issue 的 Sprint 欄位與 rank：Browse＋Edit Issues＋Schedule Issues。Manage Sprints 只管 sprint 本身（建、開始、完成、改日期），官方：does not allow users to update the work contained in a sprint。
你練習時錯過官方來源
排序 backlog 需要 Manage Sprints。
需要 Schedule Issues＋Edit Issues。
你練習時錯過官方來源
權限表寫「Browse Projects：Global Team、Application access (Jira Software)」，就得加進 Global Team 才能 Browse。
Application access＝有該產品存取的人全部都有這個權限；產品存取本來就是用 Jira 的前提，一次解決「能登入」與「能 Browse」。
Kimberly 題：Proxy Product Owners（Modify Reporter＋Assignable User）＋Jira Software product access。
你練習時錯過官方來源
加 board admin、指派時叫不出建議的使用者名單，是缺「Browse users」project 權限。
挑人名單要 Browse users and groups（global）；「Browse users」project 權限、board 權限都不存在。
挑人、分享、bulk、站台管理 → global；動 issue、sprint、version → project。
你練習時錯過官方來源
Make bulk changes 是 project 權限。
它是 global 權限，還要搭配 Edit Issues 等 project 權限。
你練習時錯過官方來源
Project admin 可以改自己 project 的 permission scheme（例：把 Delete issues 給 project lead）。
Permission scheme 是站台層共用物件，要 Jira admin。Project admin 只能管 role 的成員。
判斷法：只屬於這個 project 的（components、versions、issue layout、role 成員）→ project admin；會被多個 project 共用的（screens、各種 scheme、custom fields）→ Jira admin。

能編輯、轉換、指派 issue 卻不能設 Fix version，是缺 Schedule Issues。
Fix version 要 Resolve Issues（和 Resolution 同一把）。Schedule Issues 管的是 Due date 與排序。
例外欄位：指派 Assign、報告 Modify、到期 Schedule、版本 Resolve。

改 Due date 只要 Edit Issues。
Due date 要 Schedule Issues；Schedule Issues 也管 board／backlog 的排序。

Create Issues 是例外，不需要 Browse。

Jira admin 完成 sprint 也要 Manage Sprints。
Jira admin 不需要 Manage Sprints 也能完成 sprint。

加、刪附件要有 Edit Issues。
