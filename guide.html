620.1 專案建立

620.1.1 選擇實作方式

C 掛 scheme、T 長在裡面CMP 共用、TMP 自己改。
TMP 四沒有Components、security、Affects、transition screen。
  1. CMP＝scheme 掛在 project 上設定可跨 project 共用、標準化；改設定要 Jira admin。
  2. TMP＝設定長在 project 裡Project admin 自己改、只影響自己；適合自主、快速開始的團隊。
  3. TMP 沒有的東西你常錯Components、issue security、Affects versions、transition screen（考試版）、匿名公開存取、多個 board（要靠 saved filter）。
  4. TMP 有、別誤會的自訂 issue type、Fix versions（開 Releases）、自訂通知寄件 email、parallel sprints。
  5. 建立 CMP 要 Jira adminTMP 任何人都能建，除非收回 Create team-managed projects 全域權限。
  6. Template 決定工作方式，不決定管理方式選 Scrum 或 Kanban 之後，還要選 CMP 或 TMP。
本節所有「本段必考」（3 條）
  • 自主快速→TMP；標準化、複雜權限→CMP。
  • TMP 沒有：components、issue security、Affects versions、transition screen。你常錯
  • TMP 有：自訂 issue type、Fix versions、通知 email。

620.1.2 建立與設定 TMP

地板加天花板Access level 是地板，role 往上疊。
Viewer 能說話可以留言、加附件。
  1. 三個 access levelOpen：全站使用者自動是 Member；Limited：自動是 Viewer；Private：只有被加入的人（和 Jira admin）。
  2. Role 是疊加Open 下指派 Viewer 仍然能編輯；要唯讀先改成 Limited。
  3. Viewer 不是純唯讀能留言、加附件。
  4. 三個內建 roleViewer、Member、Administrator；project admin 可以自建 role（勾權限包）。
  5. 加了 Member 卻不能編輯他沒有 Jira 產品存取（授權席次），找 site admin。
  6. Board column＝status建一欄就建一個 status；最右欄＝完成；Done 14 天自動清。
本節所有「本段必考」（5 條）
  • Role 疊加，不覆蓋。
  • Viewer 能留言、加附件。
  • Private：沒被加入的人完全看不到。
  • TMP admin 能自建 role；CMP 要 Jira admin。
  • TMP：column 就是 status。

620.1.3 Issue type 設計

流程、欄位不同才建只是分類不要建。
Sub-task 跟著 parent 走sprint、security 繼承；fix version 不繼承。
  1. Epic → Standard → Sub-taskEpic 的 child 是 standard；sub-task 跟 parent 同進同出 sprint。
  2. 估點估在 standard 層Sub-task 的 story points 不計入 burndown 與 velocity。
  3. 流程或欄位不同才建新 type只是分類 → component、label、custom field。
  4. CMP 的 issue type 要 Jira admin 建再加進 issue type scheme；TMP 的 admin 自己建（最多 30 個）。
  5. Sub-task 繼承 parent 的 project、security level、sprint不繼承 fix version、component、assignee、估點。
  6. Subtask Blocking Condition vs automation事前擋住 parent → condition；事後自動完成 parent → automation。
本節所有「本段必考」（4 條）
  • 估點估在 standard。
  • Sub-task 跟 parent 同進同出。
  • 流程不同、欄位不同 → 新 type；只是分類 → 不要。
  • Condition 事前藏按鈕；automation 事後自動做。

620.1.4 專案設定與 trash

C 管外觀與人、T 全權CMP 改不了 key、category。
改 key 安全、刪舊 key 危險alias 保住舊連結。
Trash 60、Jira admin 救
  1. CMP 的 project admin 改得動你常錯Name、Avatar、URL、Description、Project lead、Default assignee。
  2. CMP 的 project admin 改不動你常錯Key（org、site、Jira admin）、Category（Jira admin 指派）。
  3. TMP 的 Details 只有 5 個欄位你常錯Name、Avatar、Key、Category、Access；project admin 全部都能改。TMP 沒有 URL、Description、Default assignee。
  4. 改 key 不會壞，刪 previous key 才會舊 key 變成 alias，舊連結照樣導向。
  5. Default assignee 只有兩種Unassigned 或 Project lead。
  6. Trash 60 天Move to trash：Administer Jira 或 Administer Projects；Restore、永久刪除：只有 Jira admin。
本節所有「本段必考」（5 條）
  • CMP：外觀和人可以；Key、Category 不行。你常錯
  • TMP：Name、Avatar、Key、Category、Access 全都可以。你常錯
  • 改 key 安全；刪 previous key 才會壞。
  • 一對多；不能階層；Jira admin 建。你常錯
  • Trash 60 天；只有 Jira admin 能救。

620.2 Board 設定

620.2.1 選 board 類型

Scrum 看 sprint、Kanban 看 flow沒 sprint 就沒 sprint 類報表。
類型不能換，要換就另建同一份 filter 建第二個 board。
平行 sprint：admin 開、一次完成一個Velocity 不分團隊。
  1. Scrum＝sprint 節奏固定週期承諾一批工作；sprint 還沒開始時 board 是空的。
  2. Kanban＝連續流隨時拉新工作，靠 WIP limit 控制；只有 Control chart 與 CFD 兩張報表。
  3. Kanban with backlog 不是第三種類型是在 Kanban board 開 Kanban backlog：把一個 status 拖進 Kanban backlog 面板。
  4. Board 不能 Scrum ↔ Kanban 互轉要換就用同一份 filter 再建一個。
  5. Done 怎麼清Scrum＝Complete sprint；CMP Kanban＝Release 或 Hide completed；TMP Kanban＝14 天自動清或手動 Clear Done。
  6. Parallel sprints你常錯Jira admin 在 Jira configuration 開；一次只能完成一個 sprint；Velocity 不分團隊。
  7. 一個 board 最多 5,000 張（考試版）超過的不會顯示，要縮小 filter。現行新版 board view 已取消這個上限。
本節所有「本段必考」（13 條）
  • Scrum 看 sprint；Kanban 看 flow。
  • Kanban with backlog＝Kanban＋開 backlog，不是新類型。
  • Board 類型不能互轉。
  • 開法：Board settings → Columns，把 status 拖進 Kanban backlog 面板。
  • 誰能開：官方寫 Jira administrator 或 board administrator。
  • Scrum：Complete sprint。
  • CMP Kanban：Release 或 Hide completed（1／2／4 週）。
  • TMP：14 天自動清；開了 Sprints 就不能手動清。
  • 開關：Jira admin，Jira configuration。
  • 一次完成一個 sprint。你常錯
  • Velocity 每個 sprint 一組長條，但不分團隊。你常錯
  • TMP 要第二個 board → 用 saved filter 建。
  • 建 board 需要 Browse Projects。

620.2.2 跨 project board

Board 看 filter，不看 projectfilter 決定內容；location 只決定放哪。
Copy board 不 copy filter要脫鉤就 Save as。
兩道門filter 分享＋Browse Projects。
  1. 跨 project board＝一份跨 project 的 saved filterproject in (A, B, C) ORDER BY Rank ASC，再用它建 board。
  2. 誰看得到 board＝誰看得到 filterboard 沒有自己的分享設定；卡片再依各自的 Browse Projects 顯示。
  3. Copy board 沿用同一份 filter你常錯改副本的 filter 查詢，原 board 也會變；要脫鉤就 Save as 另存新 filter。
  4. Location 只決定 board 掛在哪哪個 project 的側欄、哪個 project admin 能管；不影響顯示哪些 issue。
  5. 跨 project 會打架的Version 不能跨 project；sprint 跨 project 要每個 project 的 Manage Sprints；估算方式整個 board 一種。
  6. Simplified workflow 只給單一 project board跨 project board 不能在 board 上直接加 status。
本節所有「本段必考」（8 條）
  • 看得到 board＝filter 有分享。
  • 看得到卡片＝有該 project 的 Browse Projects。
  • Copy board ≠ Copy filter。你常錯
  • 要獨立範圍：Save as 新 filter 再指定給副本。
  • Location＝放哪、誰管；filter＝顯示什麼。
  • Version 不能跨 project。
  • 跨 project sprint：每個 project 都要 Manage Sprints。
  • Simplified workflow 只支援單一 project board。

620.2.3 Columns 與 status

沒對欄就隱形Unmapped status 的 issue 不在 board。
Scrum 看最右、Kanban 看類別完成判定兩套標準。
WIP：C 上下、T 只上CMP 上下限、TMP 只有上限。
  1. 一欄可以放多個 status一個 status 在同一個 board 只能對到一欄。
  2. 沒對到欄的 status＝隱形官方：Unmapped statuses will hide work items both in your board view and backlog view；只有搜尋找得到。
  3. Scrum 以最右欄判定完成Done、Cancelled、Won't Do 都要放最右欄，否則完成 sprint 時會被帶到下一個 sprint。
  4. Kanban 的 Hide completed 看 status category進到 Done 類別就算完成，跟放在哪一欄無關；任何編輯都會重設計時。
  5. WIP limit（column constraint）只提醒不阻擋超過上限欄頭變紅、低於下限變黃；卡片照樣拖得進去；算整欄總數，不管 quick filter。
  6. CMP 可設上下限，TMP 只能設上限你常錯CMP 的 Scrum、Kanban 都能設；題目問「最適合設 WIP limit 的 project」選 CMP Kanban。
本節所有「本段必考」（9 條）
  • 未對應＝隱形。
  • 最右欄＝完成（Scrum）。
  • 刪欄不刪 issue。
  • CMP：上下限、Scrum／Kanban 都有。你常錯
  • TMP：只有上限。你常錯
  • 只提醒不阻擋；算整欄總數。
  • Scrum：最右欄；Kanban 隱藏：status category Done。
  • Hide completed 只有 1／2／4 週；編輯會重設。
  • 單一 project＋共用一個 workflow＋只用內建元件。

620.2.4 Filter、sub-filter、quick filter

三層漏斗只減不加board filter → sub-filter → quick filter。
報表只認 board filtersub、hide、quick 都只動 board；自訂條件選 sub，1／2／4 週選 hide。
Quick 疊加是 ANDOR 寫在同一條。
  1. 每一層只能縮小quick filter 不能讓 board filter 排除的 issue 出現。
  2. Sub-filter 只有 CMP Kanban 有你常錯預設 fixVersion in unreleasedVersions() OR fixVersion is EMPTY；它只改 board 顯示，報表不會跟著縮小。
  3. 報表只看 board filter你常錯sub-filter、Hide completed、quick filter 都只改 board 顯示；要改報表範圍就改 board filter。
  4. Quick filter 多選＝AND勾越多越少；要 OR 就寫在同一個 quick filter。
  5. 改 board filter 立即生效board、backlog、報表全部用新範圍；同一份 filter 的所有 board 一起變。
  6. Sub-filter 還是 Hide completed？看條件你常錯自訂條件（48 小時、只藏 Won't Fix）→ sub-filter；完成超過 1／2／4 週 → Hide completed。
  7. 沒有 ORDER BY Rank 就拖不動Board settings → General → Add Rank。
  8. 只看自己團隊的 issue你常錯改 board filter（一勞永逸）或建 quick filter；不是 issue security。
本節所有「本段必考」（11 條）
  • 每層只能縮小。
  • Quick filter 多選是 AND。

620.5.1 JQL

  • ORDER BY 永遠在最後。
  • 同時有 AND 和 OR 就加括號。
  • !=、NOT IN 漏掉空值 → 補 OR IS EMPTY。你常錯

容器歸容器、資料歸資料分享 dashboard 不等於分享 filter。
一維 Pie、二維 Two D兩個欄位交叉只有 Two Dimensional。
Sprint 接 board、個人免設定Sprint Health／Burndown／Days Remaining 接 board；Assigned to Me 不用設定。
救 dashboard 找 Jira admintrash 60 天，只有 Jira admin 能還原。
  1. 每個 gadget 都要接資料來源大多接 filter 或 project；Sprint 三個接 board；Assigned to Me 這類個人 gadget 不用設定。
  2. 任何人都能建 dashboard要分享出去才需要 global permission「Share dashboards and filters」。
  3. 分享 dashboard ≠ 分享資料同事打開一片空白 → 底層 filter 沒分享給他，或他沒有 Browse Projects。
  4. 一維 vs 二維Pie Chart、Issue Statistics 一次只能一個欄位；「每個人各狀態幾張」要用 Two Dimensional Filter Statistics。
  5. Sprint 三兄弟接 boardSprint Health（進度條＋數字）、Sprint Burndown（曲線）、Days Remaining（一個數字）。
  6. 刪掉的 dashboard 只有 Jira admin 救得回丟進 trash 60 天後永久刪除；System dashboard 也只有 Jira admin 能改。
  7. 吃 working days 的 gadget 只有兩個你常錯Sprint Health 和 Burndown gadget。
  8. Road Map gadget你常錯列出未來 N 天要 release 的版本和各版本進度；單一版本的預測日要看 Version report。
本節所有「本段必考」（16 條）
  • 分佈類：Pie、Issue Statistics 一維；Two Dimensional 二維。
  • Sprint 類接 board；個人類不用設定來源。
  • 分享 dashboard ≠ 分享 filter。
  • Sprint Health、Sprint Burndown、Days Remaining 接 board。
  • Assigned to Me 這類個人 gadget 不用設定來源。
  • 建立：任何人；分享：要 Share dashboards and filters。
  • 還原：只有 Jira admin，60 天內。
  • System dashboard：只有 Jira admin 能改。
  • 兩個欄位交叉 → Two Dimensional。
  • backlog 趨勢 → Created vs Resolved。
  • 未來 N 天的版本 → Road Map。
  • Sprint Health：進度條＋5 個數字（含 scope change）。
  • Assigned to Me＝指派給我且未完成；Issues in Progress＝進行中的。
  • Average Age 看未解決；Resolution Time 看已解決。
  • 一維 vs 二維 vs 清單。
  • 跟著觀看者變的：Assigned to Me、Issues in Progress、Watched、Voted。

620.5.3 Agile reports

多久 Control、幾張 CFD問時間長短看 Control chart，問數量、瓶頸看 CFD。
Kanban 只有兩張Control chart＋CFD；其他都要 sprint。
吃工作日：燒 Sprint Epic 版控Burndown、Sprint、Epic report、Version、Control（＋Sprint Health、Burndown gadget）。
帳本一定記，圖上不一定畫Sprint 中途加 sub-task：一定是 scope change；burndown 只有時間追蹤模式才畫。
  1. 「多久」用 Control chart，「幾張」用 CFD你常錯問 cycle time、lead time、在某狀態待多久 → Control chart；問各狀態的數量、瓶頸 → CFD。
  2. Kanban 只有 2 張報表Control chart 和 CFD。其他 8 張（burndown、burnup、sprint report、velocity、epic 與 version 系列）都要有 sprint，只有 Scrum 有。
  3. Burnup 紅線＝總量紅線往上跳＝sprint 中途被加工作（scope creep）；綠線才是完成量。
  4. Sprint report 的 * 和 3 → 5* ＝ sprint 開始後才加入；3 → 5 ＝ 中途改估點。Velocity 的 Commitment 不含這些。
  5. 吃 working days 的只有 5 張報表＋2 個 gadget你常錯Burndown、Sprint、Epic、Version report、Control chart；gadget 是 Sprint Health、Burndown。Burnup、Velocity、CFD 不吃。
  6. Epic／Release burndown 用最近 3 個 sprint 預測未估點超過 30% 會警告；status 沒對應 column 的 issue 完全不算。
  7. Version report 有樂觀／悲觀藍線＝預測日，左右灰帶是 ±10% 速度；要先完成 10% 才有預測。
  8. Sub-task 的估點不進 sprint 報表你常錯但 sprint 中途加 sub-task 一律算 scope change；只有用 Remaining estimate and time spent 時，burndown 才畫得出來。

  • Sprint 類與 Epic／Version 類只有 Scrum 有。
  • 流動類（Control chart、CFD）Scrum 和 Kanban 都有。
  • Issue analysis 不綁 board，從 Reports → More reports 進去。

  • 「還要幾個 sprint」→ Epic／Release burndown；「哪一天」→ Version report。
  • Kanban 只有 Control chart 和 CFD。
  • TMP 只有 Burnup、Sprint burndown、Velocity、CFD 四張；沒有 Control chart。
  • 報表範圍＝目前的 board，不是整個 project。
  • 吃 working days：Burndown、Sprint、Epic report、Version、Control（＋Sprint Health、Burndown gadget）。你常錯
  • Burnup、Velocity、CFD、Epic／Release burndown 不吃。
  • Version report 直接排除 sub-task 類型。
  • Burnup：紅線＝總量、綠線＝完成；紅線往上跳＝scope creep。
  • Sprint report：* 中途加入、3 → 5 中途改估點。
  • Velocity：Commitment 不含開始後加入的；Completed 含。
  • 加 sub-task 一律算 scope change；只有時間追蹤模式 burndown 才畫得出來。你常錯
  • Epic／Release burndown：最近 3 個 sprint、30% 未估點警告、unmapped status 不計。
  • Version report：預測日＋樂觀／悲觀 ±10%；要先完成 10%。

  • Single Level Group By 是表格、只能用 filter。
  • TMP 只有 Burnup、Sprint burndown、Velocity、CFD。
  • TMP 沒有 Control chart、Sprint report、Epic／Version 系列。
  • Space insights 看整個 project；傳統報表看目前 board。
