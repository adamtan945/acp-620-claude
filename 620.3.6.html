620.3.6 · Configure issue field layout

設定 issue field layout：欄位放哪、誰能改、改了不等於能編輯

Issue layout 是 project admin 少數能直接動手的 CMP 設定，但有兩個前提常被忽略：哪些欄位「可用」由 Jira admin 的 screen 決定，以及欄位出現在畫面上不代表使用者有權限改它。這一節把區域、權責、權限三件事拆開講。

術語：考試用 project／issue／screen；現行產品為 space／work item／screen。本教材沿用考試用語。
這一節考什麼

兩條 bullet，翻成考題語言

官方 bullet考題會怎麼問
Understand configuration options for the issue view「description fields 與 context fields 差在哪？」「Hide when empty 分隔線的效果？」「project admin 想加一個新欄位，為什麼加不了？」「layout 能不能複製到別的 project？」
Understand the relationship between fields and project permissions「使用者看得到 Assignee 欄位卻改不了，缺什麼權限？」「Due date 改不了是 layout 問題還是權限問題？」
核心模型

Layout 的四個區域

打開任一 issue → 右上 ••• → Configure（或 Project settings → Issues → Layout）。畫面分成三個可見區域加一個「不顯示」區域，欄位在四者之間拖曳。

圖 1　拖曳規則：Description ↔ Context 可互拖；分隔線以下的欄位空值時收進「Show more fields」，一有值就自動跳到 Details。
區域放什麼行為
Description fields多行 rich text：Description、Environment、自訂 Paragraph最顯眼；可放文字、程式碼、圖片、表格
Context fields · DetailsAssignee、Reporter、Priority、Labels、自訂 select／user picker永遠顯示，即使空值
Context fields · More fields偶爾才填的欄位空值時收在「Show x more fields」；填了值自動升到 Details
Pinned fields使用者自己釘的 context 欄位個人設定，不是 layout；每個人不同
Hidden fields不想在這個 project 顯示的欄位畫面不顯示；欄位仍存在 screen，資料保留，JQL 仍搜得到
權責

誰能改什麼：project admin 排位置，Jira admin 決定有哪些欄位

圖 2　「加不了欄位」的答案幾乎都在左邊：要 Jira admin 把欄位放上 screen（或建新欄位），project admin 才排得到。
動作Project adminJira admin備註
拖曳欄位到 Description／Context／Hidden、移動分隔線✓✓需要 Administer Projects；且 screen 未被其他 project 共用
把既有欄位加進 layout（欄位已在 screen 上）✓✓從「Edit fields」找 screen 上但尚未顯示的欄位
建立新的自訂欄位、把欄位加到 screen—✓「Create fields」入口最終仍走全域 screen 設定
建立／編輯 field tabs—✓tabs 顯示在 Description 區；project admin 也不能在 tab 內重排欄位（官方明列）
複製 layout 到其他 project✓✓只能複製到使用相同 screen 的 project
被授予 Manage work item layouts 細分權限的人✓✓只能使用既有欄位排版，且受「screen 未被其他 project 共用」等限制；不等於全站 custom field 管理權
釘選欄位（Pinned fields）任何使用者個人設定，不影響他人
改 Task 卻連 Sub-task 一起變
如果 Task 與 Sub-task 共用同一個 View screen，layout 設定可能以同一組 issue types 一起生效。改之前先看清楚正在調整的是哪個 screen、涵蓋哪些 types；改完用另一個共用同 screen 的 type 開一張 issue 驗證。
Screen 共用時 project admin 改不了
如果這個 project 的 screen 也被別的 project 使用，layout 設定會鎖住（避免一個 project 改動影響另一個）。解法：請 Jira admin 複製一份 screen／screen scheme 給這個 project 專用。

TMP 對照

TMP 的欄位長在 project 裡：Project settings → Issue types → 選 type → 直接拖曳欄位、建新欄位，不需要 Jira admin，也沒有全站共用的 screen／screen scheme 物件（考試作答用這版）。考題問「哪種 project 的 admin 能自己新增欄位」→ TMP。

TMP：必填、預設內容、排序是三件不同的事
  • Required：在 Project settings → Issue types（或 Work types）為該類型的欄位勾選；Summary 本來就必填。
  • 預設內容／預設值：建立時帶入的起始資料（例如 Bug 的「重現步驟」範本、Story point estimate 的 Default number），使用者仍可改，不是強制保留。
  • 排序：只是呈現位置，調整順序不會讓任何欄位變成必填。
系統欄位「不能改名稱」不代表「不能設 default value」；官方也未逐一承諾每個預設欄位都提供相同控制，實際選項以站台為準。來源：Customize work item fields in team-managed spaces（2026-09-08 核對）
現行差異（2026-09-08 查核）
官方「Map a screen to a workflow transition」現已列出 TMP 入口：Project settings → Work types → Edit workflow → 選 transition → Rules → Add → Request input → Show a screen，可在轉換時要求填欄位。所以「TMP 完全沒有 screen」已不準確：TMP 沒有 screen scheme，但 transition 可掛輸入畫面。實際選項以站台為準（實機驗證）。
欄位 vs 權限

看得到 ≠ 改得了

Layout 決定欄位顯不顯示；permission scheme 決定使用者能不能改。三個欄位有專屬權限，Edit Issues 管不到它們：

欄位需要的權限沒權限時的表現
AssigneeAssign Issues欄位顯示但無法點選編輯；自己也不能把 issue 改給別人
ReporterModify Reporter欄位顯示為唯讀
Due date（以及 board／backlog 的 rank）Schedule Issues不能改 due date、不能拖曳排序
其他一般欄位（Summary、Description、Priority、Labels、自訂欄位…）Edit Issues整張 issue 唯讀
Time tracking（Original estimate、Log work）Work On Issues（＋ Edit Issues 改估算）沒有 Log work 選項
Security LevelSet Issue Security欄位不出現在可編輯項目
考題長相
「使用者回報 Due date 欄位是灰的改不了，但 Description 可以改」→ 不是 layout，是缺 Schedule Issues。「Assignee 欄位整個不見」→ 才是 layout（被拖到 Hidden）或 screen 上沒有。

情境練習

先自己判斷，再點開解答

TMP 的 admin 想讓 Bug 的「重現步驟」一定要填，於是把它拖到最上面。使用者仍可以留空送出。為什麼？
解答
排序只是呈現。要強制填寫得在 Project settings → Issue types（Work types）為該欄位勾 Required；若只是想給範本，那是「預設內容」，使用者仍可改。三件事互相獨立。
Project admin 改了 Task 的 layout，結果 Sub-task 的畫面也跟著變。哪裡出問題？
解答
沒出問題。兩個 issue type 共用同一個 View screen 時，layout 會以同一組 types 一起生效。要分開就請 Jira admin 給其中一種專用 screen。
Project admin 想在 issue 上加一個新的「Customer」下拉欄位，Configure 畫面找不到。原因？
解答
欄位不存在或不在 screen 上；建欄位、加進 screen 是 Jira admin 的事。Layout 只能排 screen 上已有的欄位。
Project admin 打開 Configure，所有欄位都拖不動。最可能原因？
解答
該 project 的 screen 被其他 project 共用。請 Jira admin 複製 screen／screen scheme 專用。
Fix versions 放在分隔線下方，某張 issue 卻顯示在 Details。為什麼？
解答
Hide when empty：一旦有值就自動升到 Details；空值時才收進 More fields。
使用者能改 Summary、Description，但 Assignee 灰掉。缺什麼？
解答
Assign Issues 權限。Edit Issues 不涵蓋 Assignee。
使用者說「Due date 欄位完全不見了」，另一位說「看得到但改不了」。分別是什麼問題？
解答
前者是 layout（拖到 Hidden）或 screen 沒有此欄位；後者是缺 Schedule Issues 權限。
兩個 project 用同一份 screen，PM 想讓 B project 的 layout 跟 A 一樣。最快做法？
解答
在 A 的 layout 用「複製到其他 project」，前提就是相同 screen。
PM 想讓自己的 issue 畫面把「Sprint」放最上面，但不想影響同事。
解答
用 Pinned fields（個人設定），不要改 layout。
把「Story points」拖到 Hidden 後，JQL 還搜得到嗎？舊資料還在嗎？
解答
都在。Hidden 只影響 issue 畫面顯示，欄位仍在 screen、資料保留。
TMP 的 project admin 想新增欄位，需要找 Jira admin 嗎？
解答
不需要。TMP 在 Project settings → Issue types 直接建欄位、拖曳，沒有 screen scheme（現行 transition 的 Request input 規則可掛畫面，但那不是欄位管理）。
常見陷阱

考題喜歡設的誤解

誤解事實
「Project admin 可以在 layout 建新欄位」只能排 screen 上已有的；建欄位、加進 screen 是 Jira admin
「Layout 可以跨 project 共用」per-project；只能複製到相同 screen 的 project
「Hidden 會刪掉欄位資料」只是不顯示，資料與 JQL 都還在
「Edit Issues 就能改所有欄位」Assignee、Reporter、Due date／rank 各有專屬權限
「Pinned fields 是 layout 的一部分」是個人設定，每個人不同
「TMP 把欄位往上排就會變成必填」Required、預設內容、排序是三件事；排序只是呈現
「有 Manage work item layouts 就能建欄位」只能排既有欄位，且受 screen 未共用等限制；不是全站欄位管理權
「改 Task 的 layout 不會影響 Sub-task」共用同一個 View screen 時可能一起生效
「分隔線下方的欄位永遠不顯示」空值才收起，填值就升到 Details
實作（20 分鐘）

把 layout 與權限拆開看

  1. CMP 任一 issue → ••• → Configure：把 Due date 拖到分隔線下、Labels 拖到 Hidden，存檔後開 issue 看差異；填一個 Due date 觀察它跳到 Details。
  2. 用第二個帳號（只有 Browse＋Edit Issues 的 role）開同一張 issue：Assignee、Reporter 顯示但唯讀；再給它 Assign Issues，重新整理。
  3. 把 project 的 screen scheme 指給另一個 project 共用，回到 Configure 觀察被鎖住的提示；改回專用後再試。
  4. 在 layout 頁用「Copy to other projects」複製到相同 screen 的 project。
  5. 對照 TMP：Project settings → Issue types → Story，直接建一個新欄位並拖曳；再對同一欄位勾一次 Required、設一次預設內容、換一次排序，各建一張 issue 觀察三者互不影響。
  6. 找兩個共用同一 View screen 的 issue type（例如 Task 與 Sub-task），改其中一個的 layout 後開另一個驗證是否一起變動。
