3 分鐘速覽

Layout 管「顯示在哪」，權限管「改不改得了」

  1. Layout 三個區Description fields、Context fields（Details 與分隔線下的 More fields）、Hidden。
  2. Screen 決定有沒有、layout 決定擺哪、權限決定能不能改你常錯Screen 上沒有的欄位，所有人都看不到（Jira admin 也一樣）；要 Jira admin 把它加上 screen。
  3. Project admin 排位置，Jira admin 決定有哪些欄位新欄位要 Jira admin 建並放上 screen；screen 被共用時 project admin 改不了 layout。官方 layout 頁的「Add fields and create field tabs」一節則寫「只有 site admin」能把欄位加進來、建 tab，和同頁「只有 Jira admin 能設定 tab」的寫法並存；作答時 project admin 一律做不到。
  4. 看得到 ≠ 改得了Assignee 要 Assign Issues、Reporter 要 Modify Reporter、Due date 要 Schedule Issues。
  5. TMP 的 admin 可以自己加欄位考試版：TMP 沒有 screen scheme；現行 transition 可用 Request input 顯示畫面。

你問過的：screen 和 issue layout 差在哪？

Screen 決定「有沒有」，layout 決定「擺哪裡」，權限決定「能不能改」。

  • Screen 上沒有 Due date → 所有人都看不到（不是只有 project admin），layout 的欄位清單也找不到 → 找 Jira admin 加上 screen。
  • Screen 上有 → project admin 在 layout 決定放哪一區、Hidden、Hide when empty。
  • 看得到但是灰色 → 缺權限（Due date 要 Schedule Issues）。

例：「所有 screen 都要顯示 Due date」→ Jira admin；「欄位空的時候隱藏」→ project admin 在 layout 設 Hide when empty。

誰能把欄位加進 layout：官方說法不一。Configure field layout 頁的「Add fields and create field tabs」一節寫：這一節的操作只有 site admin 能做（要到全站的 screen 設定加欄位、管 tab）；同一頁前面又寫只有 Jira admin 能設定 tab，Add a custom field to a screen 頁也是從 Jira admin 設定進去。教材沿用考試版的「Jira admin」；兩種說法都同意 project admin 做不到，只能排 screen 上已有的欄位。

動手做

實作 Lab：排 issue layout，分清「不見」與「灰色」

約 25 分鐘WEB 的 space admin（layout）；Jira admin（screen、scheme）

第一次做 Lab？先看 Lab 環境準備：用測試站台、準備測試帳號。畫面名稱可能隨 Atlassian 更新而不同，以下以現行畫面為準。

目標：在 WEB 的 Bug layout 搬動欄位、設 Hide when empty 與 Hidden；再從 screen 加一個欄位進來，最後用 Leo 看「欄位看得到但改不了」是權限問題。

這個 Lab 對應的考點

Screen 決定有沒有、layout 決定擺哪、權限決定改不改得了；layout 只能排 screen 上已有的欄位；Hidden 只是不顯示；Assignee、Reporter、Due date 各有專屬權限。

準備

  • 620.3.4 Lab 建的 Lab Product 欄位還在（沒有的話，任選一個不在 Bug 畫面上的欄位）。

步驟

  1. 你應該看到：Layout 頁分成 Description fields、Context fields（中間有 Hide when empty 分隔線）、Hidden fields 三區。
  2. 你應該看到：儲存成功；這些只影響 WEB 的 Bug 怎麼顯示。
  3. 你應該看到：Priority 有值時出現在 Details；空白時收進 More fields。Environment 完全不出現。
  4. 你應該看到：找不到：layout 只能排 screen 上已有的欄位。
  5. 你應該看到：Lab Product 出現在可排的欄位裡了：新欄位要 admin 放上 screen，project admin 才排得到。官方 layout 頁這一節寫「只有 site admin」能做，同頁另一處與 Add a custom field to a screen 頁則寫 Jira admin；若你是 Jira admin 卻進不去，以站台畫面為準。
  6. 你應該看到：如果 Developers 沒有 Modify Reporter，Leo 看得到 Reporter 但改不了；Summary 照樣能改（Edit Issues）。欄位灰色是權限，不是 layout。
  7. 你應該看到：TMP 的 space admin 自己就能加欄位、設必填，不需要 Jira admin 改 screen。

試試看：改一個設定，觀察差異

T1用 JQL project = WEB AND environment is not EMPTY 搜尋。看結果
通常仍查得到有填 Environment 的 Bug：Hidden 只是不顯示在 issue 上，資料沒被刪。
T2（想像，不實際做）WEB 的 Bug screen 也被 OPS 共用時，用沒有 Jira admin 的 space admin 改 WEB 的 layout。看結果
改不了：screen 被多個 space 共用時，要 Administer Jira 才能更新 layout。
T3打開 TEAM 的 workflow，點一個 transition → Rules → Request input（只看不存）。看結果
現行 TMP 可以在 transition 用 Request input 顯示畫面；考試版的說法是 TMP 沒有 transition screen。
心像錨點：閉上眼睛想一次這個畫面

Layout 頁中間那條 Hide when empty 虛線：線上面永遠看得到，線下面空的就收起來，最右邊 Hidden 區完全不顯示。口訣：不見看 layout、灰色看權限。

收尾

  • 把 Priority、Environment 拖回原位，Save changes。
  • 把 Lab Product 從 Bug screen 移除（Remove）。
  • TEAM 的 Bug 取消 Required，移除剛加的欄位。
