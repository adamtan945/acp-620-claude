620.3.7 · Evaluate ways to enrich issues (attachments, links, time tracking, developer information)

讓 issue 更豐富：附件、連結、時間追蹤、開發資訊

六個功能看起來各自獨立，考法其實只有一種：「使用者做不了 X」是全域開關、project 權限，還是欄位沒放上畫面？把每個功能拆成這三道關卡，排查與考題都能一次對上。

術語：考試用 project／issue／sub-task；現行產品為 space／work item／subtask。本教材沿用考試用語。

核心模型

每個功能都是「全域開關 × Project 權限 × 畫面欄位」三道關卡的 AND

選一個功能，再把三道關卡逐一關掉，看結果怎麼變。這也是排查順序：先問 Jira admin 開了沒，再看 permission scheme，最後看 screen／layout。

功能
關卡

考題長相
「有 Link Issues 權限卻沒有 Link 按鈕」→ 關卡①：全域 Issue linking 被停用。「Log work 出現在 ••• 但填了沒存」→ 關卡②：Work On Issues。「Original estimate 填不到」→ 關卡③：Time tracking 欄位不在 screen 上。
Time tracking

時間追蹤：全站設定 ＋ Work On Issues ＋ 欄位放上 screen

關卡內容
① 全域⚙ → Issues → Time tracking。現行官方文件：Jira Cloud 的 time tracking 永遠啟用，沒有 Activate／Deactivate 按鈕；要「關掉」是用 field configuration 隱藏 Time tracking 欄位（CMP）或從 issue type 移除該欄位（TMP）。可安裝 Marketplace 的第三方 time tracking provider 取代內建（資料存在 app 廠商）。
考綱是 2023 版，舊版 UI 有 Activate／Deactivate；考題若出現「啟用 time tracking」，理解為「讓欄位出現在畫面上」即可。
① 全域設定值每日工時（預設 8，可小數）、每週工作天（預設 5）、時間格式（Pretty／Days／Hours）、預設單位（minute／hour／day／week）、「Copy comment to work description」（勾了以後 transition 畫面的留言會複製進 work log，且只對選定 role／group 可見）
② 權限Work On Issues（記工時）；Edit Own／All Worklogs、Delete Own／All Worklogs 各自獨立。在 permission scheme 的 Time tracking 群組
③ 欄位CMP：Jira admin 把 Time Tracking 欄位放到 create／edit screen，使用者才能在建立時填 Original estimate；project admin 再在 layout 排位置。TMP：在 issue type 的欄位設定加 Time tracking
有 Work On Issues 卻還是不能記工時：第四個原因
檢查目前 status 的 workflow property。官方列出 jira.permission.work.denied（值留空）可停用該狀態的 work log，常加在 Epic 的狀態上。這是 permission scheme 以外的限制，只有 Jira admin 能在 workflow 的 status 上設定。
同系列還有 jira.permission.edit.denied、jira.permission.comment.denied、jira.permission.attach.denied，都是「值留空 ＝ 全面禁止該動作」。來源：Use workflow properties（2026-09-08 核對）
Edit／Delete All Worklogs 不是「新增工時」的替代
Add：Work On Issues；改別人的既有紀錄：Edit All Worklogs；刪別人的：Delete All Worklogs。有「All」不代表同時具備新增或刪除；排錯時先問「是誰的紀錄、要新增／改／刪哪一種」，再去對權限。也不要把 Edit Issues 當成一切操作的總開關。

記錄工時的入口：issue 的 ••• → Log work，或 Time tracking 欄位。Sub-task 的工時可以彙總到 parent（parent 的 time tracking 面板勾 include sub-tasks）；Scrum board 的 estimation 若選「Remaining estimate and time spent」，burndown 用的就是這組欄位。

Issue links

Issue link：全域開關、link type 的兩個方向、跨 project 兩邊都要權限

圖 2　Link type 由 Jira admin 定義：Name ＋ Outward description ＋ Inward description。
關卡內容
① 全域⚙ → Issues → Issue linking → Activate／Deactivate。停用後所有 project 的 Link 入口都消失（權限給了也沒用）
① Link types管理頁列的四個核心內建 type：Blocks（blocks／is blocked by）、Cloners（clones／is cloned by，不建議改）、Duplicate（duplicates／is duplicated by）、Relates（relates to）。現行新站台另預設 is implemented by／implements、merged into／merged from、is reviewed by／reviews、is caused by／causes、added to idea／is idea for（Link work items 頁列出 14 種）。自訂：Name ＋ outward ＋ inward，例如 Problem/Incident：causes／is caused by。刪除 link type 時可把既有連結改到另一個 type 或一併移除
② 權限Link Issues。跨 project 連結：兩邊 project 都要有才看得到完整連結
③ 入口issue 的 Add → Linked work item；board 卡片右鍵 → Link；⌘K 命令列。已關閉的 issue 不會出現在搜尋下拉，要輸入完整 key
JQL 小陷阱（官方特別提醒）
issueLinkType（現行 workitemLinkType）會同時比對 name、outward、inward 三個字串。內建「Blocks」的 name 與 outward 都叫 blocks，查詢時分不出方向；官方建議把 type 改名（例如 Blocking）以區分。

Board 卡片可在 View settings 打開「Linked work items」顯示連結（每位使用者各自的設定）。Sub-task 與 linked issue 完成後是否顯示刪除線，由 board 設定決定。

Web／Confluence links

連到 issue 以外的東西：web link、Confluence page、smart link

連結種類怎麼加特性
Web linkAdd → Web link，貼 URL 並給標題純外部連結；也算在 issue link 權限（Link Issues）之下
Confluence pageAdd → Page → Link page（parent 層 issue 如 epic 才有「Related work」入口；一般 issue 直接貼 Confluence 網址）前提：Jira 站台已與 Confluence 連結（同一站台或 application link）。CMP 才有 epic 的 Link page；一張 issue 最多 2,000 個連結（web、Confluence、外部 issue 合計）
Smart link在 Description／留言貼上 Google Drive、Dropbox、Figma、Confluence 等網址自動展開成卡片並永遠指向最新版；也可貼在 Attachments 區當「連結的檔案」
Issue link（對照）Add → Linked work item有方向（outward／inward）、可用 JQL 查、進 Related work 統計
考題型態
「PM 要把設計規格文件掛到 epic 上，讓 Release page 也看得到」→ Confluence page link（Related work）。「要表達『A 做完 B 才能開始』」→ issue link 的 Blocks，不是 web link。
@mention 與 watch

誰會被通知：@提及、watch、留言

@mention
  • 留言或 Description 輸入 @ ＋ 名字 → 被提及者收到通知，並直接連到那則留言。
  • 看得到誰：有 Browse users and groups（全域）→ 全站使用者；沒有 → 只看得到同 project 有 Browse Projects 的人。
  • 留言本身需要 Add Comments。快捷鍵 M 跳到留言框。
Watch
  • Watch 圖示或快捷鍵 W；watcher 在留言、編輯、轉換狀態時收通知。
  • 幫別人加／移除 watcher：Manage Watchers；看 watcher 清單：View Voters and Watchers。
  • 「我留言／編輯後自動 watch」在 Personal settings，是個人偏好不是 project 設定。
  • Vote 圖示：表達重要性，watcher 看得到票數。
通知不是權限，寄件者與收件者分開設定
被 @提及的人若打不開 issue，先查 Browse Projects、issue security 與帳號的產品存取——把他設成 assignee 不是解法（除非該 scheme 明確用 Current assignee 授權）。
TMP 也能設通知：Project settings → Notifications 可設定事件（建立、指派、更新、留言、移動、記工時…）與收件角色（watchers、current assignee、current user、reporter、space lead、space role），並可設定通知的寄件地址；不是只有 CMP 才調得動通知。設定通知不會替收件人增加任何存取權。來源：Customize notifications in team-managed spaces（2026-09-08 核對）

留言的限制可見範圍（鎖頭 → role／group）與編輯／刪除他人留言的權限，在 620.1.1 的權限深入段落已講；分享 issue 最常用的方式是複製 issue key 旁的連結。

Attachments

附件：四種加法、兩層限制、三個權限

關卡內容
① 全域⚙ → System → Attachments：啟用／停用、單檔大小上限、ZIP 支援（預覽壓縮檔內容、一鍵下載全部附件）。只有 Administer Jira 能改。
單檔上限：預設 1 GB、最大 2 GB（管理頁 Configure file attachments 為權威來源）。使用者頁仍寫「預設 10 MB」，是舊敘述；考試若問數字以管理頁為準，問「誰能改」答 Jira admin。
① 方案容量Free 每個 app 2 GB、Standard 250 GB、Premium 無上限
② 權限Create Attachments（上傳）、Delete Own Attachments、Delete All Attachments。Default Permission Scheme 已含前兩者；自訂 scheme 要自己加
③ 入口拖曳、Add → Attachment、留言區貼上、貼雲端網址成 smart link。（實務經驗，官方未明列：Attachment 欄位若在 field configuration 被隱藏，建立畫面會沒有附檔入口。）
上傳得了 ≠ 刪得掉
Create Attachments（上傳）、Delete Own Attachments（刪自己的）、Delete All Attachments（刪任何人的）是三個獨立權限。上傳失敗時先查 Create Attachments、檔名、單檔大小與方案總容量，不能因為 Edit Issues 正常就認定附件權限正常。

四種加法與檔名限制

  • 拖曳到 issue 上；Add → Attachment；在留言或長文字欄位貼上／拖入；貼雲端檔案網址變成 smart link（永遠指向最新版）。
  • 檔名不能含 \ / " % : $ ? *。
  • Attachments 區把檔案、Confluence 頁、Loom 影片放在一起，可依 All／Images／Videos／Documents 篩選、切換清單或格狀。
Bitbucket 開發資訊

Issue key 是唯一的膠水

圖 3　三個放 key 的位置匯流到同一個面板；面板另一端由連線與權限把關。

Smart commits：在 commit 訊息裡操作 issue

指令語法範例
留言<KEY> #comment <文字>MOB-10 #comment 修好轉址
記工時<KEY> #time 1w 2d 4h 30m <文字>MOB-10 #time 2h 重構登入
轉換狀態<KEY> #<transition 名稱>MOB-10 #resolve #comment done
多指令／多 issue同一行可串多個指令；多個 key 共用一組指令MOB-10 MOB-11 #resolve
Smart commit 不生效的三個原因（官方列的）
① commit 的 email 沒有對應到剛好一個 Jira 使用者；② 該使用者沒有 project 權限（Add Comments、Work On Issues、Transition Issues）；③ transition 有必填欄位沒填。另外：key 要兩個以上大寫字母＋連字號＋數字（MOB-10）；指令不能跨行；transition 名稱有空白時用連字號（#start-review）。
情境練習

先自己判斷，再點開解答

使用者有 Work On Issues，在 Story 上記得了工時，但同一個人在 Epic 上找不到 Log work。權限沒問題，還可能是什麼？
解答
該 Epic 目前 status 上設了 workflow property jira.permission.work.denied（值留空），停用該狀態的 work log——官方文件明說常加在 Epic 的狀態上。這在 permission scheme 之外，只有 Jira admin 改得動。
PM 有 Edit All Worklogs，卻按不到 Log work。缺什麼？
解答
缺 Work On Issues。Edit All Worklogs 只讓他修改別人已存在的工時紀錄，不是新增工時的替代權限。
TMP 團隊想讓「有人留言」時通知 reporter，並把通知信的寄件地址換成團隊信箱。做得到嗎？
解答
做得到。Project settings → Notifications 可設定事件與收件角色（含 reporter），並可設定通知的寄件地址。注意設定通知不會讓收件人取得該 issue 的存取權。
工程師有 Link Issues 權限，但所有 issue 的 Add 選單裡都沒有「Linked work item」。
解答
全域 Issue linking 被停用（關卡①）。請 Jira admin 到 ⚙ → Issues → Issue linking → Activate。
MOB-10 顯示「blocks MOB-22」，MOB-22 上會顯示什麼？
解答
「is blocked by MOB-10」——同一條連結的 inward 描述。
使用者在 A project 連結了 B project 的 issue，但同事只在 A 看到一半的資訊。
解答
同事在 B project 沒有 Link Issues（或 Browse）權限；跨 project 連結兩邊都要有權限。
建立 issue 時填不到 Original estimate，但既有 issue 可以 Log work。
解答
關卡③：Time Tracking 欄位沒放在 create screen。Log work 能用代表全域與 Work On Issues 都沒問題。
PM 想把 Confluence 的規格頁掛到 epic，讓 Release page 的 Related work 看得到。
解答
Epic → Add → Page → Link page（需 Jira 已連接 Confluence；CMP）。
@ 某位同事時找不到他，但他確實有 Jira 帳號。
解答
自己沒有 Browse users and groups 全域權限，只看得到同 project 有 Browse 的人；或該同事沒有這個 project 的 Browse Projects。
Scrum master 想把整個團隊加為某張 issue 的 watcher。需要什麼？
解答
Manage Watchers 權限；看清單需 View Voters and Watchers。
附件上傳被拒，訊息說檔案太大。誰能改？
解答
Jira admin（Administer Jira）在 ⚙ → System → Attachments 調整單檔上限；方案容量（Free 2 GB／Standard 250 GB／Premium 無限）是另一層限制。
設計師想刪掉工程師誤傳的附件。
解答
需要 Delete All Attachments；Delete Own 只能刪自己的。
commit 訊息寫了「mob-10 fix」，issue 上卻沒有開發資訊。
解答
Key 必須大寫 MOB-10。其他可能：站台未連接 Bitbucket、使用者沒有 View Development Tools（面板整個不顯示）。
Smart commit 寫了 MOB-10 #time 2h 但沒記到工時。
解答
依序查：commit email 沒對到剛好一個 Jira 帳號；該帳號沒有 Work On Issues；Time tracking 欄位被 field configuration 隱藏；key 不是大寫或指令跨行。
「web link」和「issue link」該怎麼選？
解答
要表達 issue 間的關係（阻擋、重複、因果）用 issue link，有方向且可 JQL；指向外部文件或網頁用 web link／smart link。
常見陷阱

考題喜歡設的誤解

誤解事實
「Link Issues 權限給了就能連結」全域 Issue linking 要先啟用；跨 project 兩邊都要權限
「Log work 是 Edit Issues 的一部分」是獨立的 Work On Issues，在 Time tracking 群組
「Original estimate 填不到是權限問題」多半是 Time Tracking 欄位沒放在 screen（關卡③）
「Project admin 可以改附件大小上限」只有 Jira admin（⚙ → System → Attachments）
「@ 提及看不到人是 project 權限」是全域 Browse users and groups；沒有它只看得到同 project 的人
「commit 訊息寫小寫 key 也能連」只認大寫 key
「開發面板看不到＝沒連 Bitbucket」也可能是缺 View Development Tools
「有 Work On Issues 就一定能記工時」該 status 若有 jira.permission.work.denied property（值留空）就記不了
「Edit All Worklogs 也能新增工時」新增是 Work On Issues；All 只管維護他人既有紀錄
「只有 CMP 能設通知」TMP 在 Project settings → Notifications 可設事件、收件角色與寄件地址
「能上傳附件就能刪別人的附件」Delete Own／Delete All Attachments 是分開的權限
「Web link 也能用 JQL 查關係」只有 issue link 有方向與 link type 可查
實作（40 分鐘）

把每個功能的三道關卡各關一次

  1. Time tracking：⚙ → Issues → Time tracking 看設定值；把 Time Tracking 欄位從 create screen 拿掉，建 issue 觀察 Original estimate 消失；拿掉第二帳號的 Work On Issues，Log work 消失。
  2. Issue linking：新增 link type「Causes」（causes／is caused by），在兩張 issue 間建立，兩端各看一次方向；Deactivate 全域後看 Add 選單；JQL 試 issueLinkType = "is caused by"。
  3. Confluence／web link：在 epic 上 Link page 一個 Confluence 頁，到 Release page 看 Related work；在一般 issue 貼一個 Google Drive 網址看 smart link。
  4. @mention／watch：拿掉第二帳號的 Browse users and groups，@ 時觀察清單縮小；給它 Manage Watchers 幫別人加 watcher。
  5. Attachments：⚙ → System → Attachments 看上限；拿掉 Create Attachments 試上傳。
  6. Workflow property（需 Jira admin）：在測試 workflow 的某個 status 加 jira.permission.work.denied（值留空），把 issue 轉到該狀態，用有 Work On Issues 的帳號確認 Log work 消失；移除 property 後恢復。
  7. Worklog 三種權限：用第二帳號記一筆工時 → 拿掉它的 Work On Issues（仍保留 Edit Own Worklogs），確認「改得了舊紀錄、加不了新紀錄」。
  8. TMP 通知：在一個 TMP 的 Project settings → Notifications 加一條「有人留言 → 通知 reporter」，並看寄件地址設定的位置。
  9. 完整交接演練：建 A「付款失敗」與 B「完成驗收」，A 的 Description 寫現象／重現步驟／預期結果；附一張不含敏感資訊的截圖；貼一個 Confluence 或文件網址；建立 A blocks B 後從 B 確認反向描述；為 A 填 Original estimate=2h 並 Log work 30m，觀察 Time spent 與 Remaining。最後用一般帳號逐項確認「誰看得到、哪一項需要哪個權限」。
  10. Bitbucket（有連接時）：建 branch MOB-10-test、commit 訊息 MOB-10 #comment hello，回 issue 看 development panel 與留言；拿掉 View Development Tools 看面板消失。
