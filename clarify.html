觀念釐清：練習題最常錯的地方

從練習測驗的錯題歸納出來、最容易混淆的觀念，依錯誤率由高到低排列：Reporting 最多，其次是 Board configuration。每一條都說明正確的判斷方式，並連到對應的教材小節。

怎麼用
先讀每區塊開頭那句「錯在哪裡」，再看表格；覺得不熟的觀念點教材連結回去補。練習題的解答跟這裡不同時，以最下方「題庫答錯的」與官方出處為準。
心智圖：練習題常錯的觀念分成六類，每個小膠囊是一條觀念，點下去跳到下方對應的區塊。
ReportingBoard configurationManaging projectsProject creationAutomation 與 workflowJQL題庫答錯的

Reporting：報表與 gadget

最常錯的區塊。多數題目是「看題幹關鍵字挑報表」，關鍵在分清楚每張報表的 X／Y 軸在量什麼。

觀念釐清
「幾張」vs「多久」各狀態有幾張、一段時間內的變化 → CFD（也用來看 WIP、throughput 與平均 cycle time 的趨勢）。某張或某群 issue 在某狀態待多久、cycle／lead time、可預測性 → Control chart。
教材：620.5.3
CFD 是累積圖卡片往前走，前面的狀態數字不會變少；往回拖時（Done → To Do），Done 和 In Progress 各扣 1，To Do 維持不變，因為沒有新卡進來（官方例子）。
教材：620.5.3
Control chart 怎麼看變快rolling average 往下、點大多落在平均線下方＝處理時間變短。往上、落在上方＝變慢。
教材：620.5.3
Sprint 層級 vs 版本層級這個 sprint 還剩多少、做不做得完 → Burndown。某個版本還要幾個 sprint → Release burndown；哪天能 release → Version report。
教材：620.5.3
Issue analysis 四組圖＋表、未解決、平均年齡 → Average Age。filter 依欄位分組＋每組進度條 → Single Level Group By。每期新建立的裡面還有多少沒解決 → Recently Created。建立 vs 解決兩條線 → Created vs Resolved。
教材：620.5.3
看自己的 gadget不用設定來源、依觀看者本人：Assigned to Me（未完成）、Issues in Progress（進行中）。要自選欄位的清單 → Filter Results。每人幾張＋百分比 → Issue Statistics；要圖 → 再加 Pie Chart。新人導覽 → Introduction、Projects、Activity Stream。
教材：620.5.2
Sprint Health 有哪些數字Time elapsed、Work complete、Scope change %、Blockers、Flagged。題目要「剩幾天＋scope 變化＋flag 數」就是它。
教材：620.5.2
吃 working days 的報表：Burndown、Sprint report、Epic report、Version report、Control chart；gadget：Sprint Health、Burndown。Velocity、CFD、Pie chart 都不吃。
教材：620.5.3
Advanced Roadmaps（Plans）能做什麼跨多個 project 的 plan、多個 scenario 比較時程、自訂 view 給不同對象、epic 以上的階層。不能直接等於 Jira Align，也不是用來合併多個 Jira 站台。
教材：620.5.3

Board configuration：board 設定

第二弱。錯的多半是「哪一層在管什麼」：filter、sub-filter、quick filter、swimlane、card color 各自的範圍。

觀念釐清
issue 不在 board 上：三層排查① board filter 有沒有撈到 ② 看的人有沒有 Browse、issue 有沒有 security level ③ 撈到也看得到卻不在 board 上 → status 沒對應欄位、quick filter 開著、Kanban sub-filter、Kanban 的 Hide completed。題幹說「search 看得到」就排除第 ②；說「已確認都有對應」就排除 status mapping。
教材：620.2.7
同一個 filter，不同人看到的數量不同因為結果受每個人的權限影響：application access、project permissions、project role、group membership（還有 issue security）。filter subscription 跟這無關。
教材：620.2.7
backlog 拖不動兩個原因：filter 沒有 ORDER BY Rank，或缺 Schedule Issues（官方：它管 due date 和排序）。題目若說她「設得了 due date」，就代表有 Schedule Issues，答案只剩 filter。
教材：620.2.7
把 issue 加進 sprint要 Browse＋Edit Issues＋Schedule Issues。缺 Schedule 時，畫面上拖得動，但不會真的排進 sprint。
教材：620.2.4
sub-filter vs quick filtersub-filter 只有 CMP Kanban 有，對所有人生效；官方原文：The sub-filter also allows you to show different data in Reports（會影響報表）。quick filter 是看的人自己點、臨時的。
教材：620.2.4
一個 board 就能做各隊 CFDCFD 和 Control chart 都有 Refine report，可以套 quick filter。六個團隊各建一個 component 的 quick filter，用一個 board 就能各看各的 CFD。
教材：620.5.3
清掉完成的卡CMP Kanban 的 Hide completed 只有 1／2／4 週；要「本週」選 1 週。要「48 小時」這種自訂時間 → 改 sub-filter（例如 resolved >= -2d OR resolution is EMPTY）。Scrum board 沒有 Hide completed，看不到舊 issue 要查 saved filter。
教材：620.2.4
Swimlane 與 card color 的選項Swimlane：Queries、Stories（讓 sub-task 排在 parent 底下）、Assignees、Epics、Projects、None。沒有 components、versions。Card color：Issue type、Priority、Assignee、Queries、None。沒有 Status、Epic、Component、saved filter。
教材：620.2.6
Estimationestimation statistic 只能用數字欄位（select list 不行）；可以隨時改；sprint 可以帶著未估點的 issue 開始。Time tracking 選 Remaining estimate and time spent 時，進度＝Original estimate 減 Time spent。
教材：620.2.5
Simplified workflow 加欄同名 status 已經對應到別的欄 → 新欄沒有 status。同名 status 存在但沒被這個 project 用 → 自動對應到新欄。
教材：620.2.3
跨 project board各 project 的 workflow 不同時，要把缺的 status 對應到欄位，或乾脆統一 workflow。可以把 issue 拖進別 project 的 epic，但不能用別 project 的 version（version 是 project 自己的）。
教材：620.2.2
誰能管 boardboard admin、location project 的 project admin、Jira admin；建立者自動成為 board admin。copy 別人的 board，你是新 board 的 admin（filter 仍是原本的）。同一個 CMP project 可以同時有 Scrum 和 Kanban board。
教材：620.2.2

Managing projects：權限、版本、設定

錯在「這個動作到底要哪個權限」與「project admin 的權限邊界」。

觀念釐清
排序、sprint、due dateSchedule Issues 管 due date 和排序（沒有叫 Rank issues 的權限）。再加上 Browse、Edit。
教材：620.3.1
全域權限Make bulk changes、Manage group filter subscriptions、Browse users and groups、Create shared objects（分享 filter／dashboard）都是全域；Work on issues、Administer projects 是 project 權限。
教材：620.3.1
做不到的常見原因有 Work on issues 還記不了工時 → status property jira.issue.editable=false。bulk 改 component → Edit Issues＋全域 Make bulk changes。bulk 不能一次替跨 project 的 issue 設 Fix versions（version 是各 project 的）。
教材：620.3.1
Issue security 與 roleissue security 管「誰能看／改某些 issue」，例如只有 team lead、只有報案的外部客戶。project role 可以用在 Browse Projects、dashboard 分享、issue security level。
教材：620.3.1
Project admin 的邊界能改：name、description、lead、avatar、URL、default assignee、components、versions、issue layout（screen 沒被共用時）。不能：改 CMP 的 key（要 Jira admin，你 9/9 實測過）、改 screen、改 permission scheme。
教材：620.1.4
版本操作建立：Releases 頁、Fix／Affects versions 欄位、Kanban board 的 Release 按鈕都可以；要 Administer Projects。刪掉 2.0 並把 issue 移到 2.1 → Merge，或 Delete 時選移到 2.1。archive 後 issue 仍在 board、JQL 搜得到，但不能再指派給它。
教材：620.3.3
自動指派優先序 Component lead ＞ Project lead ＞ Unassigned ＞ Project default，同級依 component 名稱字母序。
教材：620.3.5
sub-task不繼承 Fix versions（project、sprint、security level 會跟 parent 一樣）。排序跟著 parent 走，只能在兄弟之間調整。
教材：620.1.3
永久刪除 project先 Move to trash，再從 trash 刪除；只丟 trash 會保留 60 天。
教材：620.1.4

Project creation：CMP 與 TMP

錯在 TMP 的預設值和兩種 project 的功能差異。

觀念釐清
TMP 的內建 role只有 Administrator、Member、Viewer。沒有 Project lead、Jira administrators、Developer 這些 role。
教材：620.1.2
TMP 的 accessOpen：全站使用者自動是 Member（能建、編、排序），不必另外加 role。Limited：Viewer（看、留言）。Private：只有被加進去的人。預設設定下，有產品存取的人都能建 TMP。
教材：620.1.2
只有 CMP 才有issue security、Kanban sub-filter、components、shared configuration、多個 board。
教材：620.1.1
用範本建 CMP新 project 會拿到自己的 workflow scheme、issue type scheme、screen scheme；permission、notification、field configuration 等用預設（共用）。用 shared configuration 建的話，要手動補 version、components、avatar。
教材：620.1.1
Parallel sprints由 Jira admin 在全域開啟；同一個 board 用同一種估點單位；不能一次完成全部 active sprint，Velocity 仍按 sprint 分開顯示。考試版只有 CMP 支援，現行 TMP 也可以。
教材：620.2.1

Automation 與 workflow

錯在分不清 workflow 各元件的用途。

觀念釐清
workflow 五個元件送 email、設定 resolution → post function；限制誰能加附件 → status property；按鈕只給某群組看 → condition；必填欄位不能空 → validator。
教材：620.4.1
什麼時候用 automationclone 並複製附件、清空 resolution（post function 也行）、每週提醒（Scheduled trigger）。project rule 也能把 issue clone 到另一個 project。
教材：620.4.2
scope 與限制scope：Single project、Multiple projects、Project type、Global。一條 rule 的元件總數有上限，if／else 本身沒有另外限制數量。
教材：620.4.2

JQL

錯在版本函數與歷史運算子。

觀念釐清
沒有 labellabels is EMPTY、labels = EMPTY、labels = null、labels in (null) 都可以；labels = '' 不行。
教材：620.5.1
版本函數最近一個已 release 的版本 → latestReleasedVersion()；下一個要 release 的 → earliestUnreleasedVersion()；releasedVersions()／unreleasedVersions() 是「全部」。只要某一個版本時別用複數函數。
教材：620.5.1
歷史運算子曾在 Done、現在不是：status was Done AND status != Done。從 Done 退回 To Do：status changed from Done to "To Do"。resolution changed from "Canceled" to "Fixed" 也可以（resolution 支援 CHANGED）。Jira 的 audit log 記的是設定變更，不記錄 issue 欄位的變更。
教材：620.5.1
組合條件project in (A, B) AND priority >= High AND assignee in membersOf("team") AND due < now() AND statusCategory != Done：多個值用 in，群組成員用 in membersOf()，過期用 due < now()。
教材：620.5.1

練習題庫答錯的（查證後）

下面這幾個觀念，練習題庫給的答案跟官方文件不一致，作答時以官方為準。

題庫的說法正確說法
✗ sub-filter 只影響 board，不影響報表✓ 官方：The sub-filter also allows you to show different data in Reports.
出處：官方文件
✗ 每個團隊要看自己的 CFD，就得一隊建一個 board✓ CFD 有 Refine report 可以套 quick filter，一個 board 就夠。
出處：官方文件
✗ 卡片從 Done 拖回 To Do，To Do 會加 1✓ 官方例子：Done 和 In Progress 各扣 1，To Do 不變（累積圖）。
出處：官方文件
✗ 用 Jira audit log 找出被改掉 resolution 的 issue✓ audit log 記的是設定與管理操作，issue 欄位變更要看 issue history 或用 resolution changed。
✗ 她設得了 due date，卻因為缺 Schedule Issues 不能排序✓ Schedule Issues 同時管 due date 和排序，能設 due date 就代表有這個權限。
出處：官方文件
✗ 「只要 1.2 版」用 fixVersion in releasedVersions()✓ 那會把所有已 release 的版本都抓進來；只要最近一個用 latestReleasedVersion()。
