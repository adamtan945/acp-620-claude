620.1.2 · Create and configure team-managed projects

建立與設定 team-managed project

三條 bullet：怎麼建、存取與權限怎麼運作、怎麼加人。官方四個有效連結加上 hub 子頁「Create and edit team-managed projects」全部讀完，建立流程的細節都在那頁。

術語：考試用 project／issue；現行產品為 space／work item。本教材沿用考試用語。

Work types：TMP 自己管，但有兩個硬限制

TMP：column ＝ status
  • 建 column「Review」→ 同時生成 status「Review」
  • 改 column 名稱 → status 跟著改名

必記規則

規則內容
位置決定類別最左欄 ＝ To do 類別；最右欄 ＝ Done 類別；中間全是 In progress
最右欄 ＝ resolved進最右欄的 issue 打勾、視為完成
永遠要有 Done不能刪掉最後一個 Done column；刪含 issue 的 Done 欄，接收的欄會繼承 Done 狀態
Sprints 開著時board 在 sprint 開始前是空的；不能在 board 上直接建 issue，只能在 backlog 建再拉進 sprint；sprint 結束時 Done 的 issue 清掉、不回 backlog
Sprints 關著（Kanban 式）Done 的 issue 14 天後自動清掉；可手動清（僅 project admin／Jira admin）；清 parent 時 sub-task 一起清，不管 sub-task 狀態
Column limitKanban 式可設每欄上限（••• → Set column limit）
Status categoriesTo do／In progress／Done 三類，多個 status 可歸同一類（例：Backlog、Waiting for approval 都是 To do）
考題
「TMP 開了 Sprints，成員說 board 上看不到任何 issue」→ 還沒開始 sprint。「TMP Kanban 的 Done issue 兩週後不見了」→ 正常，14 天自動清除，可用 See all Done issues 找回。
Bullet 2

存取與權限：兩個變數決定一個人能做什麼

圖 2　互動版加總計算器在 620.1.1 的存取等級段落。

被加入 project 時自動獲得的三項

不管給什麼 role，一被加入就有：Browse project View project View issues。所以 TMP 沒有「加了人但他看不到 project」這種狀況（CMP 有，因為 Browse Projects 可能沒給那個 role）。

三個反例（考題最愛）
  • Open ＋ 指派 Viewer ≠ 唯讀：Open 已經給全站 Member，Viewer 只是疊上去，他照樣能編輯。要唯讀得先把 project 改成 Limited。
  • 從 Open 改成 Limited，原本的人不會自動保有 Member：只有被明確加入的人保住原 role，其餘（包含正被指派 issue 的人）掉成 Viewer。想保住核心成員，先把他們明確加為 Member 再改 access level。
  • Viewer 不是純唯讀：Viewer 能留言與加附件。「Limited 之下沒被加入的人能不能留言？」答案是能。

來源：Manage how people access your team-managed space、Team-managed space permissions

高頻考點
「Assignable User」在 TMP 被簡化掉了，不能單獨控制「誰可以被指派」。

需要 app access 的權限

Viewer 可以給任何站台註冊使用者，不需要 Jira 授權席次。但 Member／Administrator 的多數權限需要 Jira app access——沒有席次的人即使給了 Member，功能也用不全。席次只有 site admin 能給。

考題
「加了一個人為 Member，他能看但不能編輯」→ 他沒有 Jira app access（授權席次），找 site admin。

Bullet 3

怎麼加人

圖 3　兩個入口匯合到同一個「加人」對話框，之後流程相同。
規則內容
能加誰只能加已加入 Atlassian 站台的人；搜不到 → 請 Jira admin 先邀請進站台
外部協作者請 admin 邀請為 guest（限單一 project、不佔正式席次）
可加群組可以，整個 group 拿同一個 role
多重 role一個人或 group 可同時有多個 role
疊加原則Access 頁指派的 role 不覆蓋 access level 給的 role，是加上去
Role 的兩種用途（官方）① 給 access level 沒給的權限 ② 讓核心成員即使 access level 之後改變也保有穩定權限

第二個用途值得記：把核心團隊明確加為 Member，之後就算 project 從 Open 改成 Limited，他們仍是 Member；沒被明確加的人則降成 Viewer。

移除人的兩個陷阱

  1. 如果你曾把全站 group 加進某個 role，被移除的人可能仍透過 group 有權限——要跟 Jira admin 確認 group 成員。
  2. 從 project 移除 ≠ 從 Jira 移除；後者只有 Jira admin／site admin 在 user management 做。
把三個 bullet 串起來

Acme 新成立「Data Platform」團隊，工程師小林要自己開 project

  1. 小林點 Projects → 看得到 Create project → 有權限（Create TMP 全域權限）
  2. Scrum template → Select a team-managed project → Name「Data Platform」，key 自動「DP」→ Next
  3. Details：category 選 Jira admin 建好的「Engineering」；default assignee 設自己
  4. Access：改成 Limited（全公司可看可留言，不能亂改）
  5. Add people：三個工程師 → Member（明確加，之後 level 變動也不掉權限）；資料分析師阿芳 → 複製 Member 改成「Analyst」，拿掉 Manage sprints；外包 Kevin → 請 admin 邀成 guest，加為自訂 role「Contractor」，只勾 Collaborate 包 ＋ Create issues
  6. Sprints 開著 → 提醒團隊：board 在第一個 sprint 開始前是空的，issue 要在 backlog 建
阿芳說她看得到 issue 但拖不動、改不了
檢查 site admin 有沒有給她 Jira app access。
Kevin 可以被指派 issue，但小林沒給他 Work on 的權限
檢查是否勾了 Work on 群組裡任一項（例如 Log work）；TMP 只要有其中一項就可被指派。
自測

13 題

使用者說「我沒有 Create project 按鈕」，TMP 的情況下該查什麼？
解答
全域權限 Create team-managed projects 是否被 Jira admin 從其群組移除。
TMP 的 key 規則有哪三條？改 key 後多久生效？
解答
≥2 字元、大寫字母開頭、只含大寫字母與數字；最多 10 分鐘。
Private project 的名稱，Jira admin 看得到嗎？官方建議？
解答
看得到（Jira admin 永遠看得到所有 project 名稱）；敏感專案用代號。
Sprints 開著時，能在 board 上直接建 issue 嗎？
解答
不能，只能在 backlog 建再拉進 sprint。
Kanban 式 TMP 的 Done issue 多久清一次？誰能手動清？
解答
14 天自動；project admin 與 Jira admin 可手動（Sprints 開著時不能手動清）。
被加入 TMP 時自動獲得哪三項權限？
解答
Browse project、View project、View issues。
Member 有沒有 Manage sprints？有沒有 Edit reporters？
解答
有 Manage sprints；沒有 Edit reporters（那是 Admin）。
TMP 的 Transition any issue 對應 CMP 哪三個權限？
解答
Transition Issues、Resolve Issues、Close Issues。
TMP 怎麼決定誰可以被指派？
解答
任何 role 只要有「Work on issues」群組中任一權限，其成員即可被指派；沒有獨立的 Assignable User。
內建的 Viewer／Member／Administrator 能編輯嗎？能刪嗎？
解答
不能編輯、不能刪除；要客製就 Duplicate。
刪除自訂 role 會影響哪兩件事？會把人移出 project 嗎？
解答
Notifications、issue type restrictions；不會移出人。
加人時找不到某位同事，原因？外部人員怎麼辦？
解答
他還沒被邀請進 Atlassian 站台，請 Jira admin 邀請；外部人員請 admin 邀為 guest。
Open project 裡明確把某人加為 Viewer，他能編輯 issue 嗎？
解答
能——Open 給全站 Member，指派的 Viewer 只是疊加，不會降權。要限制先改成 Limited。
常見陷阱

考題喜歡設的誤解

誤解事實
「把人指派成 Viewer 就變唯讀」Open 之下他仍是 Member；role 是疊加，不會降權
「Private project 連 Jira admin 都看不到」Jira admin 永遠看得到 project 名稱，也進得了 project settings；敏感專案要用代號命名
「加成 Member 就一定能編輯」還要有 Jira app access（授權席次），否則只能看
「刪掉自訂 role，那些人就離開 project 了」不會；人還在，只是少了該 role 的權限，另會影響 notifications 與 issue type restrictions
「TMP 可以指定誰能被指派」沒有獨立的 Assignable User；有 Work on issues 群組任一項權限就可被指派
「TMP 的自訂欄位別的 project 也能用」只屬於這個 project；同名欄位是兩個物件
「TMP 想加幾種 work type 都可以」上限 30 個，而且只能自訂 standard 層
「把人從 project 移除＝他在 Jira 沒帳號了」兩回事；他可能還透過 group 有權限，移除站台帳號是 Jira／site admin 的事
實作（25 分鐘）

用第二個帳號，把六種組合各看一次

建一個測試 TMP，準備第二個帳號（測試帳號或請同事幫忙）。每一步都用第二個帳號實際開 project，確認「看得到什麼、能做什麼」。

#設定第二個帳號應該看到的結果
AAccess ＝ Open，不加任何人找得到 project、能編輯 issue（全站預設 Member）
BOpen ＋ 明確指派 Viewer仍然能編輯——role 疊加，不會降權
C改成 Limited，不加人看得到、能留言與加附件，但不能編輯
DLimited ＋ 明確加為 Member能編輯；之後 access level 再變也保得住
E改成 Private（保留 D 的指派）D 的人仍進得去；沒被加的人搜不到也進不去
FManage roles → Duplicate Member → 自訂 role（只留 View、Comment）→ 指派驗證自訂 role 生效；同時確認內建三個 role 不能編輯也不能刪

「他為什麼不能做 X」的排查順序

  1. 他在站台上有帳號嗎？（Add people 搜不到人＝還沒被邀請進站台）
  2. 他是不是 Jira admin？（是的話權限來自全域，不受 access level 影響）
  3. project 的 access level 是什麼？（決定他的預設 role）
  4. 他有沒有被明確指派 role？（記得是疊加，不是覆蓋）
  5. 他是不是透過 group 拿到 role？（移除個人不會拿掉 group 給的）
  6. 他有 Jira app access（授權席次）嗎？（看得到但不能編輯，多半是這一項）
  7. 站台方案限制？（Free 不能編輯 permissions／roles）
  8. 該 issue 有沒有 issue type restriction 或留言可見度限制？
