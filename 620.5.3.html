3 分鐘速覽

這一節只考兩件事：選對報表、讀懂圖

  1. 「多久」用 Control chart，「幾張」用 CFD你常錯問 cycle time、lead time、在某狀態待多久 → Control chart；問各狀態的數量、瓶頸 → CFD。
  2. Kanban 只有 2 張報表Control chart 和 CFD。其他 8 張（burndown、burnup、sprint report、velocity、epic 與 version 系列）都要有 sprint，只有 Scrum 有。
  3. Burnup 紅線＝總量紅線往上跳＝sprint 中途被加工作（scope creep）；綠線才是完成量。
  4. Sprint report 的 * 和 3 → 5* ＝ sprint 開始後才加入；3 → 5 ＝ 中途改估點。Velocity 的 Commitment 不含這些。
  5. 吃 working days 的只有 5 張報表＋2 個 gadget你常錯Burndown、Sprint、Epic、Version report、Control chart；gadget 是 Sprint Health、Burndown。Burnup、Velocity、CFD 不吃。
  6. Epic／Release burndown 用最近 3 個 sprint 預測未估點超過 30% 會警告；status 沒對應 column 的 issue 完全不算。
  7. Version report 有樂觀／悲觀藍線＝預測日，左右灰帶是 ±10% 速度；要先完成 10% 才有預測。
  8. Sub-task 的估點不進 sprint 報表你常錯但 sprint 中途加 sub-task 一律算 scope change；只有用 Remaining estimate and time spent 時，burndown 才畫得出來。

Cumulative Flow Diagram

ScrumKanbanTMP 也有
回答
各狀態的數量怎麼變？瓶頸在哪一欄？
X 軸
日期
Y 軸
issue 數（累積堆疊）
  • 每一色帶＝一個狀態（對應 board column）；由下往上是 workflow 倒過來，Done 在最底、To Do 在最上。
  • 哪條帶一直變厚，哪裡就是瓶頸。
  • 色帶厚度＝該狀態的件數；線的高度是累積上界。

題目關鍵字：bottleneck、work in progress、flow、statuses over time
官方說明

CFD 讀值：卡片往回拖時

讀什麼意思
某一條線的高度累積上界（它和底下所有狀態的總和）
兩條線之間的厚度該狀態目前的件數
某一色帶一直變厚那個狀態是瓶頸：流進來的比流出去的多

Control chart 的三個細節

  • Rolling average 是依 issue 數算的：每點取自己加前後各幾張平均，張數＝顯示總數的 20%、至少 5、一定是奇數。不是「過去 7 天平均」。
  • Columns 勾哪些狀態就算在那些狀態待多久：勾 In Progress 到 Done 之前＝cycle time；從建立算起＝lead time。
  • Y 軸：最長經過時間少於 30 天用線性刻度，30 天以上改用立方根刻度。
你練習時錯過

「看某狀態待了多久」要用 Control chart（Columns 只勾那個狀態），不是 CFD。CFD 只看數量，看不到單張卡。

  • CFD：色帶變厚＝瓶頸；厚度＝件數，線高＝累積上界。
  • 卡片往回拖：離開的狀態各扣 1，To Do 線不變。你常錯
Issue analysis

不綁 board 的 11 張報表

從 Reports → More reports 進去，資料來源選 project 或 filter。考題常描述「畫面上有什麼」，所以每張都要認得長相。標「要開 time tracking」的 4 張看的是工時，不是 story points。

四組最容易搞混的

這一組差在哪一點
Average Age vs Resolution TimeAverage Age 看還沒解決的放了多久；Resolution Time 看已經解決的花了多久
Created vs Resolved vs Recently Created前者兩條線比較同期的建立與解決（backlog 淨變化）；後者一期一根長條，追蹤那期建立的卡解決了幾張

Time Tracking Report

不綁 board
回答
這個版本的估時準不準？超前還是落後？
形式
上方兩條橫條；下方表格：Original、Remaining、Spent、Accuracy
  • Progress：綠＝已花、橙＝剩餘。Accuracy：藍＝原估。

考題愛用的錯誤說法

5 個團隊在同一個 CMP project、用 component 分、每隊要看只有自己 issue 的 CFD → 最少建 5 個 board。
1 個。建一個 board，替每個團隊建一個 quick filter（例如 component = Payments），CFD 的 Refine report 可以勾 quick filter（也能選 swimlane、欄位），每隊各自勾自己的就好。Control chart 也有同樣的 Refine report。
問「最少幾個 board」＋「每隊看自己的 CFD／Control chart」→ 1 個 board＋quick filter。
你練習時錯過官方來源
Epic report 適合 sprint planning。
Epic report 是看一個 epic 跨好幾個 sprint 的進度（官方：useful in planning work for an epic that may extend over multiple sprints）。規劃下個 sprint 放多少工作，看的是 Velocity chart。另外 Epic report 只有 Scrum board，Kanban 沒有。讀圖：最右邊藍色（完成）約 56 點、灰色（總量）約 62 點 → 已完成 > 剩餘，但還沒做完。
Epic 跨 sprint 看 epic，下個 sprint 放多少看 velocity；Epic 類報表只有 Scrum。
你練習時錯過官方來源
要看「每月建立幾張、其中幾張還沒解決」用 Resolution Time。
用 Recently Created：每期一根長條＝那期建立的 issue，依現在解了沒分兩色。Resolution Time＝已解決的平均花多久；Average Age＝未解決的平均放多久；Created vs Resolved＝建立與解決兩條線比。
看那期建的現在解了沒 → Recently Created。
你練習時錯過官方來源
題目同時提到「每個狀態的工作量＋throughput＋平均 cycle time」，選 Control chart。
選 CFD：帶子厚度＝各狀態件數（只有 CFD 看得到）、Done 線斜率＝throughput、兩線水平距離＝平均 cycle time。Control chart 看的是每張 issue 花多久，看不到各狀態件數。
只問「多久／穩不穩」才選 Control chart。
你練習時錯過官方來源
Version report 的預測線在 Today 彎折，跟非工作日無關；報表中的版本可能是 Archived。
兩句都錯。Version report 吃 working days：預測用每個工作天的平均速度，Today 之後的非工作日比之前多，線就會往下彎。它不顯示 Archived 版本（官方：shows Released but not Archived）。讀圖：灰總量、藍完成（Today 前）、藍線預測（Today 後）、紅未估（看右軸 PERCENT）。
你練習時錯過官方來源
Control chart 的淺藍帶子在尾端變寬，就代表未來無法預測。
看帶子整體寬窄：大部分很窄、點貼著深藍線 → 未來 cycle time 會接近移動平均（官方原句）。尾端變寬多半是離群點或資料變少，不代表趨勢改變。
趨勢看深藍線：往下＝變快（生產力提升），往上＝變慢。
你練習時錯過官方來源
Epic／Release burndown 的每根 bar 都從 0 開始。
中途加的 scope（深藍）畫在 0 線下方，所以有 scope change 的 bar 會往下凸出。官方：淺綠＋淺藍＝sprint 開始時的原估，淺藍＋深藍＝結束時的剩餘。
