620.3.2 · Assign team members to project roles

把團隊成員指派到 project role

上一節講「需要哪把鑰匙」，這一節講「鑰匙怎麼發」。Project role 是 Jira admin 寫在 scheme 裡的佔位符，由 project admin 在各自的 project 填上真人。理解這個分工，你就知道為什麼同一份 scheme 掛給 20 個 project，每個 project 能管 sprint 的人都不一樣。

術語：考試用 project／issue；現行官方文件為 space／work item。本教材沿用考試用語。
這一節考什麼

三條 bullet

官方 bullet考題會怎麼問
Know how to add users to a project role「在哪裡、需要什麼身分、能加 group 嗎、外部人員怎麼辦」——操作題
Understand the relationship between project permissions and project roles「scheme 寫 role，人是誰填？」「role 還能用在哪？」「role vs group vs Reporter 何時選哪個？」
Understand the use of the Administer Projects permission「project admin 能不能建新 role？能不能把自己加進 Administrators？」
核心模型

Role 是佔位符：Jira admin 寫名字，project admin 填人

Instead of explicitly-defining users, Jira admins can assign qualities in a scheme to roles within a space. These roles can later be defined by the Space admin at their discretion, allowing Jira admins to use the same scheme for multiple spaces without sacrificing granularity or constantly updating schemes.— Atlassian, How to use space roles

圖 1　官方例子：不用 role 的話，要嘛所有共用 scheme 的 project 都給同一個人，要嘛每個 project 各用一份 scheme——兩種都得 Jira admin 出手。
兩種「不用 role」的代價（官方原文整理）
  • 在 scheme 直接指定某個人 → 這個人在所有用該 scheme 的 project 都能管 sprint。
  • 想限制範圍 → 每個 project 用不同 scheme。
  • 兩種情況下，換人都要 Jira admin。Role 讓 project admin 自己換人，只影響自己的 project。

規則內容
需要的身分Project admin（有 Administer Projects）；Jira admin 也可以
能加誰已在 Atlassian 站台的 user 或 group；搜不到 → 請 admin 先邀請進站台
外部協作者請 admin 邀請為 guest，再放進 role
加進 Administrators同一個流程；project admin 可以把別人加成 admin（官方原句：same process for the Administrators role）
想給「只能看自己被指派的 issue」這種限縮權限官方明講：請 Jira admin 建一個新的 role——project admin 建不了 role
Free 方案沒有 permission scheme、project role、issue security；這一節整個不適用
背景知識

內建 role、預設成員、與 app 用的 role

CMP 內建 role
  • Administrators：預設拿到 Administer Projects；建 project 的人自動進去
  • atlassian-addons-project-access：給 Marketplace app 與整合（例如 Slack）用；官方：要讓 app 能在 Jira 動作，把這個 role 加進 permission scheme。不要刪、不要拿掉它的權限
  • 其他常見自建：Developers、Members、Viewers、Lead Developer（官方範例）
Jira admin 才能做的 role 管理
  • 建 role：⚙ → System → Security → Project roles → Add
  • Manage Default Members：設定「之後新建的 project」自動把某 user／group 放進該 role；不影響既有 project
  • View project role usage：看某個 role 被哪些 project 用
  • Role 是全站物件：名稱在所有 project 共用，成員各 project 獨立
考題長相
「Jira admin 把 group dev-leads 設成 Lead Developer 的 default member，為什麼舊 project 沒有變化？」→ default members 只套用到之後新建的 project。
兩種管理邊界，別當成故障

A 的 project admin 可以把阿宏加進既有的 Developers，卻不能修改全站 Developers 的 default members——這不是權限壞了，是「本地 membership」與「全站初始設定」的分工。

如果把某個 group 設成 default member，還要再分清兩件事：新 project 會取得該 group；而該 group 之後換人，仍可能透過既有的群組授權影響舊 project。離職或轉組時，把「全站帳號狀態」「群組成員」「各 project 的直接角色成員」分開盤點。

Bullet 2

Role 不只用在 permission scheme：五個用途

圖 2　官方列出的五個用途。把人放進 role 的那一刻，這五處全部同時生效——這是 role 比 group 更「project 本位」的原因。
刪 role 前先查 usage（官方功能）

因為同一個 role 可能被上面五種設定引用，官方提供了查詢入口：⚙ Settings → System →（Security）Project roles → View Usage，會列出使用這個 role 的 permission schemes、email notification schemes、work item security levels 與 workflow conditions。

所以「把某人從 role 移除」的影響可能是收不到通知、過不了 transition condition、或看不到受限的 issue，不只是編輯按鈕消失。刪除整個 role 之前務必先 View Usage，別刪掉其他 project 還在用的角色。

來源：View space role usage（2026-09-08 查核）

判斷

Role、group、還是欄位對象？

需求選理由
各 project 的人不同，PM 要能自己換人Project role下放給 project admin；不必改 scheme
全站同一批人（所有 project 的 QA 都是同一組）Group由 org／site admin 集中維護；可放進 role 兼得兩者
每張 issue 各自的人Reporter／Current assignee／User picker 欄位官方：Assignee、Reporter、任何 User select 或 Group 欄位裡的人都可直接授權
只有一個人、永遠不變Single user（不建議）scheme 共用時會在所有 project 生效，換人要 Jira admin
整合工具要能建 issueatlassian-addons-project-access官方指定的 app 用 role
Role 與 access level 的差別（TMP）
這一節是 CMP 的 role。TMP 的 role 是 project admin 自己建、自己勾權限，且加人時還會疊加 access level 給的 Member／Viewer；見 620.1.2。考題若混著問，先看題目是哪種 project。
情境練習

先自己判斷，再點開解答

新來的 Scrum master 要能開始 sprint。Scheme 把 Manage Sprints 給了 role「Lead Developer」。誰、在哪裡處理？
解答
Project admin 在 Project settings → People 把他加進 Lead Developer；不需要 Jira admin。
PM 想讓實習生「只能看自己被指派的 issue」，現有 role 都太寬。PM 能自己建一個新 role 嗎？
解答
不能。官方明說要請 Jira admin 建新 role（並在 scheme 用 Current assignee 或新 role 授權）。
Jira admin 在 scheme 直接把 Manage Sprints 給了「小美」這個人。三個月後小美離職，後果？
解答
所有共用該 scheme 的 project 同時失去能管 sprint 的人，而且換人要 Jira admin 改 scheme。應改成給 role，各 project 自己填。
Jira admin 把 group「qa-team」設為 role「QA」的 default member，舊的 10 個 project 卻沒有變化。
解答
Default members 只套用到之後新建的 project；舊的要各 project admin 手動加。
Slack 整合建不了 issue，權限錯誤。Project admin 該查什麼？
解答
scheme 的 Create Issues 是否包含 atlassian-addons-project-access；若被拿掉要請 Jira admin 補回。
外包 Kevin 沒有 Atlassian 帳號，PM 在 People 頁搜不到他。
解答
先請 admin 邀請 Kevin（建議為 guest），再放進 role。
把小傑加進 role「Developers」後，他同時收到了這個 project 的通知，也能在 issue security level「內部」看到 issue。為什麼一次生效？
解答
Role 同時被 permission scheme、notification scheme、issue security level 引用；加人時五種用途一起生效。
Project admin 想把自己加進 Administrators 以外的 role「Release Manager」，可以嗎？
解答
可以；People 頁對任何 role 都是同一流程，一個人可以有多個 role。
公司要求「所有 project 的 Browse Projects 都給同一個群組 all-staff」，用 role 還是 group？
解答
Group（全站一致）；也可以把 group 放進一個 role 以便日後例外處理。
Free 方案的 project admin 想調整 role 成員，找不到 People 頁的 role 選項。
解答
Free 沒有 permission scheme 與 project role，這一節的功能在 Free 不存在。
常見陷阱

考題喜歡設的誤解

誤解事實
「Project admin 可以建 role」只能填成員；建 role 是 Jira admin（⚙ → System → Security 區的 Project roles，現行稱 Space roles）
「Role 的成員全站一致」role 名稱全站共用，成員各 project 獨立
「Default members 會套到既有 project」只套到之後新建的
「atlassian-addons-project-access 沒用可以刪」app 與整合靠它動作
「Role 只用在權限」還有 notification、issue security、workflow condition、filter／dashboard 分享
「加人要 Jira admin」Administer Projects 就夠
「role 沒人用了就可以直接刪」先 View Usage：permission scheme、notification scheme、issue security level、workflow condition 都可能引用它
實作（30 分鐘）

把佔位符填上真人

  1. Jira admin：⚙ → System → Security → Project roles（Space roles），建「Lead Developer」；在 scheme 把 Manage Sprints 改成只給它。
  2. Project admin：People → Add people，把測試帳號加進 Lead Developer → 該帳號能開始 sprint。
  3. 再建一個 project 用同一份 scheme，People 頁不填人 → 沒有人能管 sprint；填另一個帳號 → 只在該 project 生效。
  4. Jira admin：對 Lead Developer 設 Manage Default Members = group dev-leads；建第三個 project 確認自動帶入，舊 project 不變。
  5. 把 role「Lead Developer」加進 notification scheme 的某事件與一個 issue security level；觀察加人時通知與可見性同步改變。
  6. 在 scheme 把 Create Issues 從 atlassian-addons-project-access 拿掉，觸發一次 Slack／automation 建 issue → 失敗；補回。
  7. 在 A 把 Lab Leads 的成員從小美換成阿宏、scheme 完全不動 → 預期只有 A 的結果改變，B 不受這個 membership 操作影響。
  8. 收尾前先到 ⚙ → System →（Security）Project roles → View Usage 查這個測試 role 被哪些 scheme／notification／security level／workflow condition 使用，確認沒有正式 project 在用，再刪除。
