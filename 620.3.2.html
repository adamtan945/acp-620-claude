Project roles

3 分鐘速覽

Role 是佔位符：Jira admin 寫名字、project admin 填人

  1. 同一份 scheme，各 project 的人不同Scheme 寫「Developers 有 X 權限」，每個 project 的 admin 自己決定誰是 Developers。
  2. Project admin 能加人進 role，不能建 role建 role、設 default members 是 Jira admin（⚙ → System → Project roles）。
  3. Role 能用在哪你常錯Permission scheme、notification scheme、issue security level、workflow condition、分享 filter／dashboard。
  4. Role 不能用在哪你常錯全域權限、產品存取（只能 group）；filter subscription（只能自己或 group）。
  5. Default members 只套用到新 project既有 project 不會變。

Role 的用途

能用在哪、不能用在哪

可以指定 project role

  • Permission scheme（例：Browse Projects）
  • Notification scheme 的收件人
  • Issue security level 的成員
  • Workflow condition
  • 分享 filter／dashboard 給某 project 的某 role

不能用 project role

  • 全域權限（只能 group）
  • 產品存取（只能 group）
  • Filter subscription（只能自己或 group）
你練習時錯過

「哪些可以關聯 project role」選：Dashboard sharing、Browse Projects（permission scheme）、Issue security levels。不選 filter subscription 與 global permissions。

動手做

實作 Lab：建一個 role，讓它只在 WEB 有效

約 25 分鐘Jira admin（建 role、改 scheme）；WEB 的 space admin（加人進 role）

第一次做 Lab？先看 Lab 環境準備：用測試站台、準備測試帳號。畫面名稱可能隨 Atlassian 更新而不同，以下以現行畫面為準。

目標：以 Jira admin 建一個新的 space role、在 scheme 授權給它，再以 WEB 的 space admin 把 Leo 放進去，看「Jira admin 寫名字、project admin 填人」。

這個 Lab 對應的考點

Role 是佔位符：Jira admin 建 role 並寫進 scheme，各 project 的 admin 自己填人；default members 只套用到新 project；全域權限、filter subscription 不能指定 role。

準備

  • WEB 目前有一個 future sprint（沒有的話先在 Backlog 建一個 Lab Sprint，不要開始）。

步驟

  1. 你應該看到：列表多了 Lab Lead Developer；這一步只有 Jira admin 做得到。
  2. 你應該看到：Manage Sprints 只剩原本的 Administrators（若有）與 Lab Lead Developer。
  3. 你應該看到：Leo 通常無法開始 sprint：他現在只有 Developers，沒有 Manage Sprints。
  4. 你應該看到：People 清單裡 Leo 同時有 Developers 與 Lab Lead Developer 兩個 role（一個人可以有多個 role）。
  5. 你應該看到：Leo 可以 Start sprint 了；權限只在 WEB 生效。先不要真的開始，或開始後立刻完成。
  6. 你應該看到：也看得到 Lab Lead Developer，但 OPS 這裡沒有人在這個 role：role 是全站共用的名字，每個 space 各自填人。
  7. 你應該看到：只能選自己或你所屬的 group；沒有 project role 可選。
  8. 你應該看到：收件人選項裡有 Space role：notification scheme 可以用 role。

試試看：改一個設定，觀察差異

T1⚙ Settings›System›Space roles → Lab Lead Developer 的 Manage Default Members → 加入 Kim。再看 WEB 的 People。看結果
Kim 不會出現在 WEB 的 Lab Lead Developer：default members 只套用到之後新建的 space，既有的 space 不變。
T2⚙ Settings›System›Global permissions → 頁面下方 Grant Permission，看授權對象的下拉。看結果
只有 group（現行另有 user、Anyone），沒有 project role：全域權限不能給 role。
T3打開 TEAM（TMP）的 Space settings → Access，找建立自訂 role 的地方（只看）。看結果
TMP 的 space admin 可以自己建 role（Free 方案不行）；CMP 的 role 只能由 Jira admin 在 Space roles 頁建立。
心像錨點：閉上眼睛想一次這個畫面

WEB 的 People 頁：Leo 那一列有兩個 role 標籤，Developers 與 Lab Lead Developer。OPS 的 People 頁同一個 role 名字底下是空的。口訣：Admin 寫名、PM 填人。

收尾

  • 把 Leo 從 Lab Lead Developer 移除；Manage Sprints 改回原樣（加回 Developers，若原本有）。
  • 移除 Lab Lead Developer 的 default members（Kim），再刪除 Lab Lead Developer 這個 role。
  • 如果 Lab Sprint 被開始了，把它完成或刪除。
