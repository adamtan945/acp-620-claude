練習題庫與官方文件不一致的地方

這些是你做過的練習題中，答案鍵跟官方文件不一致的觀念。作答一律以官方為準。

題庫的說法正確說法小節
✗ 「Priority 曾經是 High」答 priority changed to High before now() 與 priority was High✓ 官方：WAS＝currently have or previously had（含建立時的值）；CHANGED 只找有改過的，建立時就是 High 的會漏。最準是 WAS；WAS AND (=High OR !=High) 括號恆真，結果相同。620.5.1
✗ 「不用手動指派的四種方式」答 bulk、project permissions、component lead、automation✓ 題庫答案欄（A,C,D,F）和它自己的解析（bulk、project default、component、automation）矛盾。Project permissions 不會指派任何人，一定錯；project default、component lead、automation 一定對；第四個在 workflow post function（完全自動）與 bulk（仍要人操作）之間，依題意選 workflow。620.3.5
✗ Automation 改 Fix versions 失敗是缺 Schedule Issues✓ Fix version 歸 Resolve Issues（官方：update the Resolution field and view the Fix version field）；Schedule Issues 只管 Due date 與 rank。Trigger 是 due date 變更不代表要 Schedule。620.3.1
✗ 依 Due Date 建 saved filter 只要 Viewers（Create Issues）✓ 要 Browse Projects（Users）：搜尋只回傳能 Browse 的 issue；Create Issues 不含 Browse；Schedule Issues 是改 due date 用的。620.3.1
✗ 多個 component 預設指派衝突時一律 Unassigned✓ 官方 KB：只要有一個 component 的預設是 Component lead，就指派給那位 lead；衝突不會自動變 Unassigned。620.3.5
✗ Sprint 中途在 story 加 sub-task，不算 scope change（story points 的 board）✓ 一律算 scope change；只是沒開時間追蹤時 burndown 看不到。620.5.3
✗ 卡片從 Done 拖回 To Do，CFD 的 To Do 加 1✓ Done 與 In Progress 的累積線各扣 1，To Do 不變。620.5.3
✗ 每個團隊要看自己的 CFD 就得各建一個 board✓ CFD 的 Refine report 可以套 quick filter，一個 board 就夠。620.5.3
✗ 用 audit log 找被改掉 resolution 的 issue✓ Audit log 記設定與管理操作；issue 欄位變更看 issue history 或 JQL resolution CHANGED。620.5.1
✗ 能設 due date 卻因為缺 Schedule Issues 不能排序✓ Schedule Issues 同時管 due date 與排序，能設 due date 就有這個權限。620.3.1
✗ 「只要 1.2 版」用 fixVersion in releasedVersions()✓ 那會抓全部已發布版本；最近一版用 latestReleasedVersion()。620.5.1
✗ Team-managed Kanban 不能設 WIP limit、Scrum board 不能設 column constraint✓ TMP 可設上限；CMP 的 Scrum、Kanban 都能設上下限（單選「最適合」仍選 CMP Kanban）。620.2.3
✗ 缺 Create shared objects 就不能 Copy board✓ 可以複製：副本沿用原 board 的 filter 與分享對象；只有「從 Boards 頁新建 board 再分享」才需要 Create Shared Objects。620.2.2
