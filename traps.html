易錯觀念：第三方題庫常見的錯誤答案

市面上的 ACP-620 練習題庫，答案鍵不一定正確。下面整理的是查證過程中發現、題庫最常答錯的觀念，每一條都對照官方文件或在測試站台實測過。依考綱章節排列，點章節標籤可以回到該節教材。

怎麼用這一頁
練習題的答案跟這裡衝突時，以這裡附的官方出處為準；看完再回該節教材，把前後文補起來。查證日期 2026-09-24。

620.1.1

選擇實作方式

常見的錯誤說法正確說法
✗ Shared configuration 的來源 project 改設定後，新 project 可以選擇要不要接受。✓ 共用的是同一份 scheme，來源改了會自動套用到所有共用的 project。官方：If you change the configuration in one space, it affects all other spaces sharing that setup.
出處：Create a new space
✗ 用 shared configuration 建新 project 後，status 和 priority 還要手動設定。✓ status 包含在 workflow scheme 裡、priority 也是 scheme，都會共用。要手動補的是 project 自己的資料：version、component、avatar。
出處：Create a new space
✗ 「每兩週分批交付」的團隊適合 Bug tracking 或 Kanban 範本。✓ 固定週期交付＝sprint 節奏＝Scrum；持續交付、沒有固定週期才是 Kanban。
出處：620.1.1 教材
620.2.1

選 board 類型

常見的錯誤說法正確說法
✗ 完成 sprint 時，沒做完的 issue 會被刪除或封存。✓ 未完成的 issue 由你選擇移到下一個（或新建的）sprint，或移回 backlog，不會被刪除也不會被封存。
出處：Complete a sprint
✗ Jira admin 一定要有 Manage Sprints 權限才能完成 sprint。✓ 官方：you must be a Jira Administrator or a user with the Manage Sprints permission。Jira admin 不需要 Manage Sprints，但要看得到 project（Browse）；若還要搬未完成的 issue，另外需要 Schedule 與 Edit Issues。
出處：Complete a sprint
620.2.3

Columns 與 status

常見的錯誤說法正確說法
✗ workflow 移除 Resolved status 後，Created vs Resolved 報表要跟著改。✓ 那張報表看的是 Resolution 欄位與 resolution date，跟 status 名稱無關。要改的是寫了 status = Resolved 的 saved filter，以及 board 的欄位對應。
出處：Generate a report
620.2.4

Filter／sub-filter／quick filter

常見的錯誤說法正確說法
✗ Kanban 的 sub-filter 不會影響報表。✓ 官方 sub-filter 頁寫的是：The sub-filter also allows you to show different data in Reports. 第三方題庫常把它當成「只影響畫面、不影響報表」，碰到這類題目請留意題目想要的是哪一種說法。
出處：Add a sub-filter
620.3.1

專案權限

常見的錯誤說法正確說法
✗ 看得到 due date 需要 Schedule Issues。✓ Schedule work items 是「修改 due date 和排序」用的：change a work item's Due date and change work item ranking。只要看、要依 due date 建 filter，Browse Projects 就夠了。
出處：Work item permissions
✗ 改 Fix versions 需要 Schedule Issues 或 Edit Issues 就夠。✓ Fix version 由 Resolve work items 管：update the Resolution field and view the Fix version field。automation 的執行者要改 fix versions，缺的通常是它。
出處：Work item permissions
620.3.2

Project roles

常見的錯誤說法正確說法
✗ 「由 project admin 管理成員」是適合用 group 的情境。✓ 那是 project role 的特徵。group 由 site／org admin 管理，適合全站層級的權限、跨多個 project 的同一批人。
出處：620.3.2 教材
620.3.3

Versions 與 roadmap

常見的錯誤說法正確說法
✗ archive 一個 version 之後，它的 issue 會從 board 和 JQL 搜尋裡消失。✓ 2026-09-24 實測：archive 後 issue 還在 board 上、JQL 也搜得到。真正的改變是不能再把 issue 指派給它（Jira 回「Cannot assign issue to versions … as they have been archived」），以及從下拉選單和 Version report 中隱藏。
出處：Manage versions
✗ version 只能在 Releases 頁建立。✓ 有權限的人也能在 Fix versions、Affects versions 欄位直接建立新 version。
出處：Manage versions
620.3.4

Components／labels／fields

常見的錯誤說法正確說法
✗ Checkboxes 可以當「只能選一個值」的欄位。✓ Checkboxes 可以複選。只能選一個又要有預設值、不同 project 選項不同，用 Radio Buttons 或 Select List (single choice) 加 context。
出處：620.3.4 教材
✗ 報表不能用 labels。✓ Pie Chart 報表可以用 Labels 分組，dashboard 也有 Labels gadget。labels 真正的缺點是值容易不一致（任何人隨手打，會長出拼字變體）。
出處：620.3.4 教材
620.3.5

自動指派

常見的錯誤說法正確說法
✗ 多個 component 都是 Component lead 時，看哪個先建立（或隨機）。✓ 先比類型優先序：Component lead ＞ Project lead ＞ Unassigned ＞ Project default；同一級再依 component 名稱字母序取第一個。例如 Database、Java、Server 都是 Component lead，會指派給 Database 的 lead。
出處：Manage component's default assignee（KB）
✗ Unassigned 會壓過 Component lead。✓ Unassigned 的優先級低於 Component lead 和 Project lead，只比 Project default 高。
出處：Manage component's default assignee（KB）
✗ bulk operation、project permissions 也算「自動指派」。✓ bulk operation 是人工操作；permission 本身不會指派人。會自動指派的是：project default assignee、component default assignee、workflow post function、automation rule。
出處：620.3.5 教材
✗ 依 Radio Buttons 的值指派，可以用 component 的 default assignee。✓ component default assignee 只對 Components 欄位生效（而且可複選）。依自訂欄位的值指派要用 automation rule。
出處：620.3.5 教材
620.4.2

Automation rule

常見的錯誤說法正確說法
✗ automation 的 scope 可以設成 issue type。✓ scope 只有 Single／Multiple projects、Project type、Global（All projects）；現行文件另有 team 兩種。要限定 issue type，請在規則裡加 condition。
出處：What are flow details and settings?
620.5.1

JQL

常見的錯誤說法正確說法
✗ priority changed to High 等於 priority was High。✓ changed to 只抓得到「有變更成 High」的紀錄，建立時就是 High、從沒改過的 issue 會漏掉；was High 連初始值一起算。
出處：JQL operators
