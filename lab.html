動手做 Lab

Lab 環境準備

每一節最後都有一個「動手做 Lab」：照步驟在測試站台實際點一次，看到真的 board、報表與設定畫面，親手改一次設定，考題情境出現時腦中就有畫面。這一頁準備所有 Lab 共用的環境，只要做一次。

約 40 分鐘只在測試站台做

為什麼要動手

看過、點過、弄壞過，才記得住

  1. 看到畫面Board 設定、報表、automation 在哪一頁、按鈕叫什麼。考題問「在哪裡設定」時，腦中直接浮現那一頁。
  2. 親手改一次改完回 board 或報表看結果，記住「因 → 果」。
  3. 故意弄壞每個 Lab 都有「試試看」：把 status 拿出 column、改 filter、拿掉權限，看會發生什麼。考題的錯誤選項通常就是這些情境。
  4. 留下心像錨點每個 Lab 最後有一句「閉上眼睛想一次這個畫面」，考前複習只要想這些畫面。
站台

用哪一種站台

  • 用個人 email 開一個 Jira 試用站台（Standard 或 Premium 試用皆可；Plans 等進階功能要 Premium）。自己建站的人會是 org admin 與 Jira admin，可以做全部 Lab。
  • Free 方案沒有 permission scheme 與 project role 的自訂，620.3.1、620.3.2 的 Lab 做不了（見 ACP-120 的官方說明）。
  • 現行畫面把 project 叫做 space、issue 叫做 work item；考試仍用 project／issue。
不要在公司正式站台做

Lab 會改 board filter、column、permission scheme、automation rule，還會建立與刪除 issue。請用個人試用站台或公司專用的 sandbox。

測試帳號

三個人，用來切換視角

名字角色用途
你Org admin＋Jira admin＋project admin設定
LeoWEB 的 Developers開發者視角：拖卡、記工時
KimWEB 的 Users（或 Viewers）只看、不改；測試看不到或不能做的情境
AnaOPS 的成員另一個團隊；跨 project board 的範例
  1. 準備三個 email用 email 別名（例如 Gmail 的 你的帳號+leo@gmail.com）或其他信箱。
  2. 邀請Atlassian Administration›Directory›Users›Invite users：輸入 email，Jira 的角色選 User。
  3. 切換視角每個測試帳號用一個瀏覽器設定檔（Chrome profile）登入；無痕視窗當「未登入的路人」。
測試 project

三個 project

Key類型用途
WEBCompany-managed Scrum多數 board、權限、version、報表的 Lab
OPSCompany-managed KanbanKanban、cumulative flow、跨 project board
TEAMTeam-managed Scrum和 CMP 對照：access、role、功能開關
  • 每個 project 建 15～20 張 issue：Story、Bug、Task 都要有，部分加 sub-task、story points、original estimate、fix version、component；WEB 再建 1～2 個 epic。
  • WEB 跑過至少一個 sprint（可以把 sprint 日期設短、完成後再開下一個），報表才有資料。
  • WEB 的 permission scheme 先複製一份（⚙ Settings → Work items → Permission schemes → Copy，改名 WEB Permission Scheme），再到 WEB 的 Space settings → Permissions 換成它；之後的 Lab 都改這份。
  • WEB 的 People：Leo 加進 Developers，Kim 加進 Users；OPS 的 People：Ana 加進 Developers。
準備好了

之後每個 Lab 的「準備」只會寫這一頁以外需要的東西。Lab 做完都有「收尾」，把設定改回來，下一個 Lab 才不會被影響。

小技巧

做 Lab 時

  • 先讀完該節教材再做 Lab；步驟前的方框可以打勾，進度只存在這台裝置。
  • 報表需要時間累積資料；沒有資料的報表，先看設定畫面與座標軸。
  • 畫面和文字對不上時，用 ⚙ Settings 或 board 設定的搜尋找名稱；Atlassian 常改選單位置，但設定名稱大多不變。
