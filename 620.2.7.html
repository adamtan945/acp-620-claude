Issue 不在 board 上：照順序查

  1. 排查順序issue 存在？→ board filter 撈得到？→ 看的人有權限？→ status 對到欄？→ sub-filter／quick filter？→ Scrum 是否在 active sprint？
  2. 先用題幹排除你常錯題目說「搜尋得到」→ 排除 filter 與權限；說「status 都有對應」→ 排除 column mapping。
  3. Board 沒有自己的分享設定看不到 board＝filter 沒分享；少了某 project 的卡＝缺 Browse Projects。
  4. RANK 是拖曳的開關沒有 ORDER BY Rank：拖不動、Scrum 建不了 sprint。
  5. 排序需要 Schedule Issues＋Edit Issues你常錯不是 Manage Sprints。
  6. Stacked quick filters＝AND只能縮小。

RANK

ORDER BY Rank 管四件事

有 ORDER BY Rank沒有
board 與 backlog 可拖曳排序拖不動
Scrum 可建 sprint、把 issue 拉進去建不了 sprint
Sub-task 排在 parent 底下散落各處
Kanban 可從 backlog 拉進 board拉不進去
  • 修法：Board settings → General → Add Rank（會改 saved filter 本身）。
  • 能排序還需要對該 issue 有 Schedule Issues＋Edit Issues。
  • Sub-task 跟著 parent 排；只能在自己的兄弟 sub-task 之間排先後。
你練習時錯過

「在 backlog 排序」要 Schedule Issues＋Edit Issues。Manage Sprints 管的是 sprint 本身（建立、開始、完成）。

自我檢查：先在心裡回答，再點開對答案
Q1成員看得到 backlog 但拖不動排序，缺哪兩個權限？看答案
Schedule Issues 與 Edit Issues（前提是 filter 有 ORDER BY Rank）。
本段必考
  • Rank＝拖曳、建 sprint、sub-task 排序的開關。
  • 排序權限：Schedule＋Edit Issues。你常錯

實作 Lab：讓一張 issue 從 board 消失，再找回來

約 30 分鐘WEB+OPS filter 的 owner（你）；WEB 的 project admin；Leo、Kim 的瀏覽器

第一次做 Lab？先看 Lab 環境準備：用測試站台、準備測試帳號。畫面名稱可能隨 Atlassian 更新而不同，以下以現行畫面為準。

目標：用 WEB+OPS board 依序製造「filter 沒撈到」「status 沒對欄」「quick filter 擋住」「沒有 Rank」四種狀況，練習照順序排查。

這個 Lab 對應的考點

排查順序：存在 → filter → 權限 → status 對欄 → sub-filter／quick filter → Scrum 是否在 active sprint；沒有 ORDER BY Rank 拖不動；排序需要 Schedule Issues＋Edit Issues。

準備

  • 620.2.2 的 WEB+OPS board 與 filter（已分享給 WEB）。
  • 在 WEB 建一張 Bug LAB-missing，指派給 Leo。

步驟

  1. 你應該看到：它在某一欄裡。
  2. 你應該看到：Board 上不見了，搜尋還找得到：第一關 board filter 沒撈到。改回原本的查詢。
  3. 你應該看到：Board 上又不見了，filter 和搜尋都沒問題：status 沒對到欄。拖回原欄。
  4. 你應該看到：LAB-missing（指派給 Leo）不見了；取消勾選就回來。
  5. 你應該看到：卡片無法上下拖曳排序。
  6. 你應該看到：Filter 結尾變回 ORDER BY Rank ASC，又能拖曳；官方提醒這會影響所有用這份 filter 的 board。
  7. 你應該看到：Leo 還能改 Summary（有 Edit），但通常無法調整排序：排序要 Schedule work items＋Edit work items。
