3 分鐘速覽

JQL 考兩件事：看懂零件、避開陷阱

  1. 一句 JQL＝欄位＋運算子＋值多個條件用 AND／OR 接起來，最後才能放 ORDER BY。
  2. != 和 NOT IN 會漏掉空欄位你常錯要連「沒填」的一起找，自己補 OR field IS EMPTY。
  3. IS／IS NOT 只能配 EMPTY 或 NULL你常錯labels is CERT-330 會報錯；labels = EMPTY、!= EMPTY 都合法。
  4. 文字欄位只能用 ~ 和 !~summary = crash 會錯；要寫 summary ~ crash。
  5. WAS／CHANGED 只支援 6 個欄位Assignee、Fix Version、Priority、Reporter、Resolution、Status。WAS＝現在是或曾經是。
  6. Sprint 函數只有三個你常錯openSprints()、futureSprints()、closedSprints()；沒有 currentSprint、nextSprint。
  7. 未解決用 resolution你常錯resolution = Unresolved（或 IS EMPTY）；standardIssueTypes() 排除 sub-task。
  8. ORDER BY 一定在最後後面不能再接任何條件。
核心模型

一句 JQL 只有五種零件

projectin(MOB, WEB)ANDsprintinopenSprints()ANDresolution=UnresolvedORDER BYpriorityDESC
欄位 field運算子 operator值 value函數 function關鍵字 keyword
關鍵字作用例子
AND縮小結果project = MOB AND status = Done
OR擴大結果；多個值時 IN 更好寫duedate < now() OR duedate IS EMPTY
NOT否定一個條件或一整組括號NOT (reporter = jsmith OR reporter = jbrown)
EMPTY／NULL欄位沒有值（兩者相同）labels IS EMPTY
ORDER BY排序；必須在整句最後… ORDER BY priority DESC, created ASC

沒有括號時由左到右評估。只要同時用了 AND 和 OR，就加括號，意思才不會被誤讀。

自我檢查：先在心裡回答，再點開對答案
Q1project = MOB AND status = Done ORDER BY created DESC AND priority = High 錯在哪？看答案
ORDER BY 必須放在最後，後面不能再接 AND priority = High。
本段必考
  • 欄位 → 運算子 → 值（或函數）；用 AND／OR／NOT 接。
  • ORDER BY 永遠在最後。
  • 同時有 AND 和 OR 就加括號。
運算子

每種運算子「不能用在哪」

運算子規則與陷阱
= 、!= 、IN、NOT IN= 不能用在文字欄位。IN (a,b)＝多個 = 用 OR 接。!= 與 NOT IN 不會匹配空值。
> >= < <=只能用在可排序的欄位：日期、版本、數字、priority。不能用在文字欄位。
~ 、!~只用在文字欄位：Summary、Description、Environment、Comment、文字型 custom field。支援萬用字元 login*。
IS、IS NOT只能配 EMPTY 或 NULL：fixVersion IS EMPTY、votes IS NOT EMPTY。
WAS、WAS IN、WAS NOT、CHANGED只支援 6 個欄位：Assignee、Fix Version、Priority、Reporter、Resolution、Status。可加 BY、DURING、BEFORE、AFTER、ON；CHANGED 另有 FROM、TO。

空值陷阱：!= 會漏掉沒填的

= EMPTY 合法嗎？

寫法合法嗎意思
assignee = EMPTY✓等於 assignee IS EMPTY（沒指派）
assignee != EMPTY✓等於 assignee IS NOT EMPTY（有指派）
labels = CERT-330✓有這個 label
labels IS CERT-330✗ 報錯IS 只能接 EMPTY 或 NULL
你問過的

labels != CERT-330 會找到「有其他 label」的 issue、排除有 CERT-330 的，但不會找到完全沒有 label 的。labels NOT IN (CERT-330) 結果一樣。

自我檢查：先在心裡回答，再點開對答案
Q1component != Backend 會找到沒有 component 的 issue 嗎？看答案
不會。要寫 component != Backend OR component IS EMPTY。
Q2assignee = EMPTY 和 assignee IS EMPTY 一樣嗎？看答案
一樣，官方明寫 field = EMPTY 等同 field IS EMPTY。
Q3可以用 WAS 查 component 的歷史嗎？看答案
不行。WAS／CHANGED 只支援 Assignee、Fix Version、Priority、Reporter、Resolution、Status。
本段必考
  • !=、NOT IN 漏掉空值 → 補 OR IS EMPTY。你常錯
  • IS／IS NOT 只配 EMPTY、NULL；= EMPTY、!= EMPTY 也合法。你常錯
  • 文字欄位用 ~；比較運算子只給可排序的欄位。
  • 歷史運算子只有 6 個欄位。
歷史運算子

WAS 和 CHANGED：用一張 issue 的歷史來看

  1. 9/1　To Doissue 建立
  2. 9/3　In Progress
  3. 9/5　In Review
  4. 9/6　In Progressreview 被退回
  5. 9/8　Done現在的狀態
查詢找得到這張嗎為什麼
status WAS "In Review"✓曾經是
status WAS "Done"✓WAS＝現在是或曾經是
status WAS NOT "Blocked"✓WAS NOT＝從來沒有過
status CHANGED FROM "In Review" TO "In Progress"✓9/6 發生過這個變更
status = "In Progress"✗現在是 Done
自我檢查：先在心裡回答，再點開對答案
Q1status WAS "In Progress" 會不會找到現在就是 In Progress 的 issue？看答案
會。WAS 是「現在是或曾經是」。要排除現在的，再加 AND status != "In Progress"。
本段必考
  • WAS＝現在是或曾經是；WAS NOT＝從來沒有過。
  • CHANGED 看「有沒有發生過這個變更」，可加 FROM／TO／BY／DURING。
函數

會考的函數（依用途）

用途函數要記的點
SprintopenSprints()、futureSprints()、closedSprints()只有這三個；寫法是 sprint IN openSprints()，要用 IN 不能用 =
類型standardIssueTypes()、subtaskIssueTypes()issuetype IN standardIssueTypes()＝排除 sub-task
人currentUser()、membersOf("group")currentUser() 只對登入者有效，不要放在給匿名者用的 filter
日期now()、startOfDay／Week／Month()、endOfDay…startOfWeek(-1)＝上週一開始；-7d 是「往前 7 天」不是「上週」
版本releasedVersions()、unreleasedVersions()、latestReleasedVersion()、earliestUnreleasedVersion()「只要最近發布的那一版」用 latestReleasedVersion()
連結linkedIssues("KEY")可指定 link type
個人紀錄watchedIssues()、votedIssues()、issueHistory()只對登入者有效
你問過的

「目前 active sprint 裡、標準類型、還沒解決」的正解：
issuetype in standardIssueTypes() AND sprint in openSprints() AND project = "ORBIT" AND resolution = Unresolvedsprint = currentSprint()status != "Done"（會漏掉 Won't Do 等其他已解決）

自我檢查：先在心裡回答，再點開對答案
Q1哪兩個不是 JQL 內建函數：openSprints()、futureSprints()、currentSprints()、nextSprints()、closedSprints()？看答案
currentSprints() 和 nextSprints()。
Q2「還沒解決」為什麼用 resolution 而不是 status != Done？看答案
只要被設了任何 resolution（Done、Won't Do、Duplicate…）就算已解決；status 名稱各 workflow 不同，會漏或誤判。
本段必考
  • Sprint 函數：open／future／closed，用 IN。你常錯
  • standardIssueTypes() 排除 sub-task。
  • 未解決：resolution = Unresolved 或 IS EMPTY。你常錯
  • -7d ≠ 上週；上週用 startOfWeek(-1)。
欄位

常考欄位的限制

欄位要記的點
statusCategory只有 To Do／In Progress／Done 三個值，跨 workflow 通用：statusCategory != Done
resolutionIS EMPTY 或 = Unresolved＝未解決
text一次搜 summary、description、comment 與文字 custom field
parent找某 parent 的所有 child（取代舊的 Epic Link）
category找屬於某個 project category 的所有 project
workRatiotimeSpent ÷ originalEstimate × 100；workRatio > 100＝超過原估
cf[10003]自訂欄位同名或含空白時用 ID 指定

JQL 不能比較兩個欄位（寫不出 assignee = reporter）。

本段必考
  • 跨 workflow 找未完成：statusCategory != Done。
  • workRatio > 100＝超過原估工時。
Basic vs JQL

Basic search 做不到的

  • 條件之間只能 AND：沒有 OR、NOT、括號
  • 沒有 !=、>、~、EMPTY 這類運算子
  • 沒有 ORDER BY 與 WAS／CHANGED
  • 用了這些的 JQL 切不回 Basic
本段必考
  • 要 OR、NOT、!=、EMPTY、排序、歷史查詢 → 一定要切 JQL。
常考寫法

需求 → JQL

需求JQL
指派給我、還沒完成assignee = currentUser() AND resolution IS EMPTY
未指派或不是我的assignee != currentUser() OR assignee IS EMPTY
上週建立created >= startOfWeek(-1) AND created < startOfWeek()
逾期未解決duedate < now() AND resolution IS EMPTY
目前 sprint 的 bugsprint IN openSprints() AND issuetype = Bug
曾經進行中、現在不是status WAS "In Progress" AND status != "In Progress"
上個月被 jsmith 改成 Donestatus CHANGED TO Done BY jsmith DURING (startOfMonth(-1), endOfMonth(-1))
沒貼任何 labellabels IS EMPTY
三個 project、依優先再依建立時間排序project IN (A,B,C) ORDER BY priority DESC, created ASC
本段必考
  • 「不是 X」幾乎都要想「空值要不要算」。
  • 歷史條件用 WAS／CHANGED，只限 6 個欄位。
