620.5.1 · Translate business requirements into appropriate JQL queries

把業務需求翻成 JQL

Reporting 這個 domain 的三節裡，JQL 是地基：filter 餵 board、餵 dashboard gadget、餵報表。考題給你一段「老闆想看…」的需求，要你挑出正確的 JQL，或指出哪一句寫錯在哪。官方三份 reference（fields、functions、keywords、operators）這一頁全部讀完，並整理成可以查表的形式。

術語：考試用 project／issue；現行 JQL 文件已改稱 space／work item（例如 space = X、standardWorkTypes()），但舊字仍可用且考試用舊字。本教材沿用 project、issuetype、standardIssueTypes()。

核心模型

一句 JQL 只有四種零件

官方定義：一個最簡單的查詢（clause）＝ field → operator → value 或 function；多個 clause 用 keyword 接起來；最後可加 ORDER BY。看懂零件，就能拆任何一句。

圖 1　四種零件的顏色沿用整份教材：brand＝欄位、amber＝運算子、green＝值、teal＝函數、violet＝關鍵字。
官方對四種零件的定義
  • Field：代表一個 Jira 欄位（含 custom field）的字。
  • Operator：比較左邊欄位與右邊值的符號或字，只留下為真的結果；有些會搭配 NOT。
  • Keyword：把 clause 接起來、改變邏輯、或有特殊定義的字（AND、OR、NOT、EMPTY、NULL、ORDER BY）。
  • Function：字加括號，對 Jira 資料做計算後回傳值，例如 currentUser()、startOfWeek(-1)。
優先序與括號

沒有括號時由左到右依序評估。官方例子：

(status=resolved AND project=SysAdmin) OR assignee=bobsmith

括號也可以把一組 clause 包起來給 NOT：NOT (reporter = jsmith OR reporter = jbrown)。考題常拿「少了括號意思就變了」出題。

Keywords

六個關鍵字（官方 reference 全表）

Keyword作用官方例子
AND合併多個 clause，縮小結果project in (JRA,CONF) and fixVersion = "3.14"
OR合併多個 clause，擴大結果；多值時 IN 更方便duedate < now() or duedate is empty（逾期或沒設到期日）
NOT否定單一 clause 或括號內整組not (reporter = jsmith or reporter = jbrown)
EMPTY欄位沒有值；只能配支援 IS／IS NOT 的欄位duedate is empty（duedate = empty 也接受）
NULL與 EMPTY 完全相同duedate is null
ORDER BY指定排序欄位；必須放在整句最後，否則無效；可多欄、asc／descduedate = empty order by created, priority desc
官方註記
用 Components 或 Versions 排序時，會先依 project 排、再依欄位自然順序（JRA-31113）。
Operators

運算子分四群，各有「不能用在哪」

群運算子規則與陷阱（官方原文整理）
相等= != IN NOT IN= 不能用在文字欄位（要用 ~）。IN (a,b,c) ＝ 多個 = 用 OR 接。!= 與 NOT IN 不會匹配空值：component != fred 只找「有 component 且不是 fred」；要含沒有 component 的，寫 component != fred OR component IS EMPTY。field != EMPTY 等於 field IS NOT EMPTY。
比較> >= < <=只能用在可排序的欄位：日期、版本、數字、priority（priority > normal）。不能用在文字欄位。日期可用相對值：created >= "-5d"、updated <= "-4w 2d"。逾期：duedate < now() AND resolution IS EMPTY。
文字~ !~用在 Summary、Description、Environment、Comments、Free Text Searcher 的 custom field，以及 issue key。支援模糊／詞幹（summary ~ win 也找到 wins）、萬用字元（"win*"）、精確片語（"\"full screen\""）。text ~ "x" 一次搜所有文字欄位，欄位多時較慢。!~ 對多則留言的 issue 會失效。
空值IS IS NOT只能配 EMPTY／NULL：fixVersion is empty、votes is not empty。
歷史WAS WAS IN WAS NOT WAS NOT IN CHANGED只能用在 6 個欄位：Assignee、Fix Version、Priority、Reporter、Resolution、Status。述詞：AFTER、BEFORE、BY（可多人 BY (a,b)）、DURING ("d1","d2")、ON；CHANGED 另有 FROM、TO。WAS ＝ 現在是或曾經是；WAS NOT ＝ 從來沒有過。超過 10,000 筆變更只搜最近的。

WAS 與 CHANGED 的差別，用一張 issue 的歷史看

圖 2　WAS 看「有沒有出現過這個值」；CHANGED 看「有沒有發生過這個變更」。兩者都只支援六個欄位。

兩個容易漏掉的欄位技巧
  • workRatio：官方定義 workRatio = (timeSpent / originalEstimate) × 100。想找「已超過原估工時」寫 workRatio > 100；官方範例 workRatio > 75 是「已用掉超過 75% 原估」。需要全域 time tracking 已啟用且兩個欄位都有值。
  • cf[欄位ID]：自訂欄位名稱重複（不同 context 同名）或含空白時，改用 ID 精確指定，例如 cf[10003] = "New York"、cf[10003] in ("London","Milan")。ID 在不同站台不同，不要照抄別站的 ID。
  • JQL 不能逐筆比較兩個欄位：寫不出 assignee = reporter 或 timeSpent > originalEstimate。先找有沒有現成的衍生欄位（workRatio 就是這種），真的需要才評估匯出或 app。

Basic vs JQL

Basic search 做不到、非切 JQL 不可的

Basic search 的天花板
  • clause 之間只能 AND；沒有 OR、NOT
  • 沒有 EMPTY、!=、>、~ 這類運算子（只有「等於」與文字關鍵字）
  • 沒有 ORDER BY（只能點欄頭排序）
  • 沒有 WAS／CHANGED 歷史查詢
  • 沒選 project 時，project 專屬欄位（component、version）不會出現
  • 複雜 JQL 切回 Basic 時會被拒絕，例如用了 OR、NOT、括號、EMPTY、比較運算子
官方提醒的兩種查詢

Bounded：至少有一個「欄位 運算子 值」的限制，例如 project = TEST order by key。

Unbounded：沒有任何限制，只有排序或空白，例如 order by createdDate。

保留字（a、an、and、or、by、on、after…約 200 個）與特殊字元要用引號包起來：summary ~ "\"full screen\""、field ~ "email@atlassian.com"。

情境練習

先自己判斷，再點開解答

PM 要「所有沒有 component 的 issue，加上 component 不是 Backend 的」。component != Backend 夠嗎？
解答
不夠。!= 不匹配空值，要寫 component != Backend OR component IS EMPTY。
project = MOB AND status = Done ORDER BY created DESC AND priority = High 哪裡錯？
解答
ORDER BY 必須在整句最後；排序後面不能再接 clause。
「找 summary 含有 crash 這個字的 issue」該用哪個運算子？
解答
summary ~ crash。文字欄位不能用 =。
status WAS "In Progress" 會不會找到現在正在 In Progress 的 issue？
解答
會。WAS 是「現在是或曾經是」。要排除現在的，加 AND status != "In Progress"。
想用 WAS 查 component 的歷史，可以嗎？
解答
不行。WAS／CHANGED 只支援 Assignee、Fix Version、Priority、Reporter、Resolution、Status 六個欄位。
Filter 要分享給匿名的公開 dashboard 用，裡面寫 assignee = currentUser()，會怎樣？
解答
匿名使用者沒有 currentUser，查詢不會如預期。官方明講：預期給匿名用的 saved filter 不要用 currentUser()。
「resolved 的 SysAdmin issue，加上所有指派給 bobsmith 的 issue」，寫成 status=resolved AND project=SysAdmin OR assignee=bobsmith 對嗎？
解答
沒括號時由左到右評估，這句剛好等於 (status=resolved AND project=SysAdmin) OR assignee=bobsmith，結果正確；但為了可讀與避免誤判，官方建議加括號。若需求改成「resolved 且（SysAdmin 或 bobsmith）」就必須寫 status=resolved AND (project=SysAdmin OR assignee=bobsmith)。
「上週建立的 issue」寫成 created >= -7d 有什麼問題？
解答
-7d 是「最近 7 天」，不是「上一個日曆週」。要用 created >= startOfWeek(-1) AND created < startOfWeek()。
Basic search 可以做「status 是 Done 或 Closed，且不是 jsmith 建立的」嗎？
解答
「Done 或 Closed」可以（同一欄位多選＝IN）；「不是 jsmith」不行——Basic 沒有 NOT／!=，要切 JQL：status IN (Done, Closed) AND reporter != jsmith。
想找 label 完全沒貼的 issue。
解答
labels IS EMPTY。EMPTY 只能配 IS／IS NOT。
跨三個 project 找「未完成」，各 project 的 Done 狀態名不同。
解答
用 statusCategory != Done（或 resolution IS EMPTY），不要逐一列狀態名。
reporter in (Jack,Jill,John) 等於哪一種寫法？
解答
reporter = Jack OR reporter = Jill OR reporter = John。NOT IN 則等於多個 != 用 AND 接，且同樣不含空值。
常見陷阱

考題喜歡設的誤解

誤解事實
「!= 會把沒有值的也找出來」不會；要另加 OR field IS EMPTY。NOT IN 同理。
「ORDER BY 可以放在任何位置」只能放最後，否則整句無效。
「文字欄位可以用 = 精確比對」不能；用 ~，精確片語用跳脫引號。
「WAS 可以查任何欄位的歷史」只有六個欄位。
「-7d 等於上週」是「往前 7 天」；日曆週用 startOfWeek(-1)。
「JQL 是 SQL」官方明講不是資料庫查詢語言，只是語法相似；沒有 JOIN、沒有子查詢。
「currentUser() 在公開 filter 也能用」只有登入者能用。
「保留字可以直接寫」約 200 個保留字（a、an、and、or、by、on…）當值用時要加引號。
「Basic 與 JQL 可以無損互切」用了 OR、NOT、括號、EMPTY、比較運算子等就切不回 Basic。
實作（30 分鐘）

把 12 個模板各跑一次

  1. 開 Filters → View all issues，切到 JQL。把「常考寫法」12 句逐一貼上，觀察 autocomplete 與結果數。
  2. 拿掉 OR assignee IS EMPTY 再跑一次，比較結果數——親眼看 != 不含空值。
  3. 把 ORDER BY 移到中間，看錯誤訊息。
  4. 對某張 issue 改幾次狀態，分別跑 status WAS、status CHANGED FROM … TO …、status WAS NOT，對照圖 2。
  5. 存成 filter，分享給 project role，再到 620.5.2 用它建 dashboard。
  6. 試著把含 OR 的 JQL 切回 Basic，看它拒絕。
  7. 用四張卡證明邊界（另一套教材的 lab）：在隔離 project 建 A（Task／指派自己／labels acp620-jql-lab, urgent）、B（Task／未指派／acp620-jql-lab）、C（Bug／指派自己／acp620-jql-lab）、D（Task／labels 留白）。 先跑 labels = acp620-jql-lab → 預期 A、B、C；加 AND assignee != currentUser() → B 不會被選中；改成 AND (assignee != currentUser() OR assignee IS EMPTY) → B 回來。 再用 key IN (…四張…) 限定範圍測 labels NOT IN (urgent) OR labels IS EMPTY → 預期 B、C、D。
  8. 用一般測試帳號開同一個 filter，確認查不到時可能是 filter 沒分享或缺 Browse Projects／issue security，不一定是語法錯。
