3 分鐘速覽

JQL 考兩件事：看懂零件、避開陷阱

  1. 一句 JQL＝欄位＋運算子＋值多個條件用 AND／OR 接起來，最後才能放 ORDER BY。
  2. != 和 NOT IN 會漏掉空欄位你常錯要連「沒填」的一起找，自己補 OR field IS EMPTY。
  3. IS／IS NOT 只能配 EMPTY 或 NULL你常錯labels is CERT-330 會報錯；labels = EMPTY、!= EMPTY 都合法。
  4. 文字欄位只能用 ~ 和 !~summary = crash 會錯；要寫 summary ~ crash。
  5. WAS／CHANGED 只支援 6 個欄位Assignee、Fix Version、Priority、Reporter、Resolution、Status。WAS＝現在是或曾經是。
  6. Sprint 函數只有三個你常錯openSprints()、futureSprints()、closedSprints()；沒有 currentSprint、nextSprint。
  7. 未解決用 resolution你常錯resolution = Unresolved（或 IS EMPTY）；standardIssueTypes() 排除 sub-task。
  8. ORDER BY 一定在最後後面不能再接任何條件。

核心模型

一句 JQL 只有五種零件

projectin(MOB, WEB)ANDsprintinopenSprints()ANDresolution=UnresolvedORDER BYpriorityDESC
欄位 field運算子 operator值 value函數 function關鍵字 keyword
關鍵字作用例子
AND縮小結果project = MOB AND status = Done
OR擴大結果；多個值時 IN 更好寫duedate < now() OR duedate IS EMPTY
NOT否定一個條件或一整組括號NOT (reporter = jsmith OR reporter = jbrown)
EMPTY／NULL欄位沒有值（兩者相同）labels IS EMPTY
ORDER BY排序；必須在整句最後… ORDER BY priority DESC, created ASC

沒有括號時由左到右評估。只要同時用了 AND 和 OR，就加括號，意思才不會被誤讀。

自我檢查：先在心裡回答，再點開對答案
Q1project = MOB AND status = Done ORDER BY created DESC AND priority = High 錯在哪？看答案
ORDER BY 必須放在最後，後面不能再接 AND priority = High。
本段必考
  • 欄位 → 運算子 → 值（或函數）；用 AND／OR／NOT 接。
  • ORDER BY 永遠在最後。
  • 同時有 AND 和 OR 就加括號。

運算子

每種運算子「不能用在哪」

運算子規則與陷阱
= 、!= 、IN、NOT IN= 不能用在文字欄位。IN (a,b)＝多個 = 用 OR 接。!= 與 NOT IN 不會匹配空值。
> >= < <=只能用在可排序的欄位：日期、版本、數字、priority。不能用在文字欄位。
~ 、!~只用在文字欄位：Summary、Description、Environment、Comment、文字型 custom field。支援萬用字元 login*。
IS、IS NOT只能配 EMPTY 或 NULL：fixVersion IS EMPTY、votes IS NOT EMPTY。
WAS、WAS IN、WAS NOT、CHANGED只支援 6 個欄位：Assignee、Fix Version、Priority、Reporter、Resolution、Status。可加 BY、DURING、BEFORE、AFTER、ON；CHANGED 另有 FROM、TO。

空值陷阱：!= 會漏掉沒填的

= EMPTY 合法嗎？

寫法合法嗎意思
assignee = EMPTY✓等於 assignee IS EMPTY（沒指派）
assignee != EMPTY✓等於 assignee IS NOT EMPTY（有指派）
labels = CERT-330✓有這個 label
labels IS CERT-330✗ 報錯IS 只能接 EMPTY 或 NULL
你問過的

labels != CERT-330 會找到「有其他 label」的 issue、排除有 CERT-330 的，但不會找到完全沒有 label 的。labels NOT IN (CERT-330) 結果一樣。

自我檢查：先在心裡回答，再點開對答案
Q1component != Backend 會找到沒有 component 的 issue 嗎？看答案
不會。要寫 component != Backend OR component IS EMPTY。
Q2assignee = EMPTY 和 assignee IS EMPTY 一樣嗎？看答案
結果一樣。官方 keywords 頁的 EMPTY 範例，把 duedate = empty 和 duedate is empty 並列為「找沒有 Due date 的 issue」的兩種寫法。注意 operators 頁明寫的是另一半：field != EMPTY 等同 field IS NOT EMPTY。
Q3可以用 WAS 查 component 的歷史嗎？看答案
不行。WAS／CHANGED 只支援 Assignee、Fix Version、Priority、Reporter、Resolution、Status。
本段必考
  • !=、NOT IN 漏掉空值 → 補 OR IS EMPTY。你常錯
  • IS／IS NOT 只配 EMPTY、NULL；= EMPTY、!= EMPTY 也合法。你常錯
  • 文字欄位用 ~；比較運算子只給可排序的欄位。
  • 歷史運算子只有 6 個欄位。

Basic vs JQL

Basic search 做不到的

  • 條件之間只能 AND：沒有 OR、NOT、括號
  • 沒有 !=、>、~、EMPTY 這類運算子
  • 沒有 ORDER BY 與 WAS／CHANGED
  • 用了這些的 JQL 切不回 Basic
本段必考
  • 要 OR、NOT、!=、EMPTY、排序、歷史查詢 → 一定要切 JQL。

  • What is advanced search in Jira Cloud?the query contains an OR operator. Instead, you can use an IN operator and it will be translated.

易錯觀念

考題愛用的錯誤說法

「Priority 曾經是 High、現在不一定還是」用 priority changed to High before now() 最完整。
官方：WAS 找 currently have or previously had 這個值的 issue，含現在；CHANGED 只找「有改過」的 issue——建立時就是 High、從沒改過的會漏掉。所以最準的是 priority was High。priority was High AND (priority = High OR priority != High) 括號裡恆真（priority 一定有值），結果和 WAS 一樣。（有題庫答案給 CHANGED＋WAS，依官方定義 CHANGED 會漏掉建立時就是 High 的 issue。）
WAS 含現在也含建立時；CHANGED 要真的改過。
你練習時錯過官方來源
「MARS 最近發布版本、非 Done」寫 status != "Done" and affectedVersion IN releasedVersion(MARS) and project = "MARS"。
三個錯：releasedVersion() 不存在（是 releasedVersions()，複數）；releasedVersions 撈全部已發布版本，「最近一版」要 latestReleasedVersion(MARS)；版本本來就屬於 MARS，不必再加 project = MARS。正解：status != "Done" and affectedVersion = latestReleasedVersion(MARS)。另外 status is not "Done"、is not in 都不合法：IS／IS NOT 只配 EMPTY。latestReleasedVersion() 括號不能空：官方語法只有 latestReleasedVersion(space)，一定要指定 project（只能用 = 或 !=）；releasedVersions() 才可以省略 project（＝全部 project），而且只能用 IN／NOT IN。
最近一版＝latest；函數名要寫全（…Versions、…Version）；IS 只配 EMPTY。
你練習時錯過官方來源
due < "0" 是錯的，因為加了引號的 0 是文字；兩個 project 用 project = A AND project = B。
引號不代表文字型別：日期欄位會把 "0" 讀成相對時間 0＝現在，等同 due < now()（還有 "-1d"、"2w"）。一張 issue 不可能同屬兩個 project，要寫 project in (A, B)；至少 High 用 >=；經辦人屬於 group 用 assignee in membersOf()；overdue()、current() 不存在。
你練習時錯過官方來源
fixVersion = latestReleased() 或 fixVersion in 1.0 是合法的 JQL。
都錯：版本函數要寫完整 latestReleasedVersion()（尾巴有 Version）；in 後面要括號 in (1.0)。只發布過一版時，releasedVersions() 與 latestReleasedVersion() 結果相同。
先檢查語法（函數名、括號），再看範圍。
你練習時錯過官方來源
statusCategory != Closed 可以撈出未完成的 issue。
Status category 只有 To Do、In Progress、Done 三個；Closed 是 status 名稱不是 category。要寫 statusCategory != Done 或 resolution = Unresolved。
Automation 題：Lookup issues 的 JQL 寫 statusCategory != Closed → 這個元件設定錯。

「即將發布（upcoming）的版本」用 releasedVersions() 或 nextUnreleasedVersion()。
Upcoming＝下一個還沒發布的＝earliestUnreleasedVersion()；releasedVersions() 是所有已發布的，nextUnreleasedVersion() 不存在。
「與該版本相關的所有 issue」要查兩個欄位並用 OR：fixVersion = earliestUnreleasedVersion("P") OR affectedVersion = earliestUnreleasedVersion("P")。

動手做

實作 Lab：把需求翻成 JQL，再故意寫錯

約 25 分鐘一般 Jira 使用者（能 Browse WEB）

第一次做 Lab？先看 Lab 環境準備：用測試站台、準備測試帳號。畫面名稱可能隨 Atlassian 更新而不同，以下以現行畫面為準。

目標：在 WEB 親手跑一次空值陷阱、sprint 函數、WAS 歷史查詢，再看幾個常考的錯誤寫法會出什麼錯，最後存成 filter 給下一個 Lab 用。

這個 Lab 對應的考點

!= 與 NOT IN 漏掉空值、要補 OR … IS EMPTY；IS 只接 EMPTY／NULL；sprint 函數只有 open／future／closed；WAS／CHANGED 只支援 6 個欄位；ORDER BY 在最後；用了 OR、!=、EMPTY 的 JQL 切不回 basic。

準備

  • WEB 至少有 5 張 issue：2 張 component 是 Backend、1～2 張是其他 component、2 張沒有 component。
  • WEB 有一個進行中的 sprint，裡面有幾張還沒完成的 Story、Bug，其中一張有 sub-task。
  • 挑一張 WEB 的 issue 拖到 In Progress，再拖回 To Do（給步驟 6 的 WAS 用）。

步驟

  1. 你應該看到：出現 JQL 編輯框；打字時有自動完成建議。
  2. 你應該看到：只列出「有 component、而且不是 Backend」的 issue；沒有 component 的那 2 張不在結果裡。
  3. 你應該看到：筆數多了 2：沒有 component 的 issue 出現了。這就是 != 不匹配空值。
  4. 你應該看到：JQL 編輯框下方出現錯誤說明：IS 只能接 EMPTY 或 NULL。改成 labels IS EMPTY 就能執行。
  5. 你應該看到：只列出目前 sprint 裡、還沒解決的 Story、Bug，sub-task 不在結果裡。
  6. 你應該看到：準備時拖回 To Do 的那張出現了：WAS＝現在是或曾經是，再用 != 排除現在還在 In Progress 的。
  7. 你應該看到：通常會提示無法切換（或切不回原本的條件）：含 OR、!=、EMPTY 的 JQL 無法轉成 basic search。
  8. 你應該看到：側欄 Filters 裡出現 WEB open sprint，Owner 是你。620.5.2 的 Lab 會用它。

試試看：改一個設定，觀察差異

T1輸入 project = WEB ORDER BY priority DESC AND status = Done。看結果
報錯。ORDER BY 必須在整句最後，後面不能再接條件。
T2輸入 project = WEB AND summary = login，再改成 summary ~ login。看結果
= 報錯（文字欄位不能用 =）；~ 可以執行。
T3輸入 project = WEB AND component WAS Backend，再試 sprint = currentSprint()。看結果
都報錯：WAS 只支援 Assignee、Fix Version、Priority、Reporter、Resolution、Status；currentSprint() 不是內建函數。

收尾

  • 保留 filter WEB open sprint（620.5.2 會用）。
  • 其他測試用的搜尋不用存。

一分鐘腦內整理

讀完了？用這張收攏整節

不等於要補空!=、NOT IN 漏掉空值 → OR IS EMPTY。
IS 只認空IS／IS NOT 只接 EMPTY、NULL。
Sprint 三兄弟：開、未來、關openSprints、futureSprints、closedSprints。
歷史六欄：指修優報解狀Assignee、Fix Version、Priority、Reporter、Resolution、Status。
一句 JQL 只有五種零件
  • 欄位 → 運算子 → 值（或函數）；用 AND／OR／NOT 接。
  • ORDER BY 永遠在最後。
  • 同時有 AND 和 OR 就加括號。
每種運算子「不能用在哪」
  • !=、NOT IN 漏掉空值 → 補 OR IS EMPTY。你常錯
  • IS／IS NOT 只配 EMPTY、NULL；= EMPTY、!= EMPTY 也合法。你常錯
  • 文字欄位用 ~；比較運算子只給可排序的欄位。
  • 歷史運算子只有 6 個欄位。
WAS 和 CHANGED：用一張 issue 的歷史來看
  • WAS＝現在是或曾經是；WAS NOT＝從來沒有過。
  • CHANGED 看「有沒有發生過這個變更」，可加 FROM／TO／BY／DURING。
會考的函數（依用途）
  • Sprint 函數：open／future／closed，用 IN。你常錯
  • standardIssueTypes() 排除 sub-task。
  • 未解決：resolution = Unresolved 或 IS EMPTY。你常錯
  • -7d ≠ 上週；上週用 startOfWeek(-1)。
常考欄位的限制
  • 跨 workflow 找未完成：statusCategory != Done。
  • workRatio > 100＝超過原估工時。
Basic search 做不到的
  • 要 OR、NOT、!=、EMPTY、排序、歷史查詢 → 一定要切 JQL。
需求 → JQL
  • 「不是 X」幾乎都要想「空值要不要算」。
  • 歷史條件用 WAS／CHANGED，只限 6 個欄位。
